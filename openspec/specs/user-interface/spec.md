# User Interface Capability

## Purpose
提供基于Web的管理界面，覆盖数据导入、智能填充、基础数据维护、RBAC权限管理、配置管理与审计日志等核心操作流程。
## Requirements
### Requirement: Web管理界面
系统 SHALL 提供可在浏览器访问的Web管理界面。

#### Scenario: 浏览器访问
- **WHEN** 用户通过浏览器访问系统URL
- **THEN** 系统显示登录页面或主界面

---

### Requirement: 客户与制程独立选择
系统 SHALL 允许用户分别选择客户与制程作为数据范围条件。

#### Scenario: 独立选择器
- **WHEN** 用户在导入/验收规格/智能填充页面选择范围
- **THEN** 页面提供独立的客户选择器与制程选择器

#### Scenario: 组合筛选
- **WHEN** 用户选择客户与制程后
- **THEN** 系统按(CustomerId, ProcessId)组合筛选数据

---

### Requirement: 数据导入界面
系统 SHALL 提供文档上传与导入的Web界面，并在仅规格导入时明确提示项目值将由规格值补齐。

#### Scenario: 导入文件上传
- **WHEN** 用户在导入界面上传Word或Excel文件
- **THEN** 系统解析文件并展示可导入内容

#### Scenario: 仅规格导入提示
- **GIVEN** 当前表被识别或用户确认为仅规格导入
- **AND** 项目列为空
- **WHEN** 用户进入导入确认步骤
- **THEN** 页面提示项目将使用规格内容自动补齐
- **AND** 页面提示仅规格导入可能增加跨项目匹配风险

#### Scenario: 疑似项目列需要人工处理
- **GIVEN** 当前表未识别出项目列
- **AND** 系统判断存在疑似项目列
- **WHEN** 用户进入导入确认步骤
- **THEN** 页面不得默认按仅规格导入提交
- **AND** 页面要求用户选择项目列或显式确认仅规格

#### Scenario: 导入前剔除数据
- **WHEN** 用户进入确认导入步骤
- **THEN** 系统显示本次待导入数据，并允许用户单个删除或批量删除不需要导入的行

#### Scenario: 导入冲突模态框确认
- **WHEN** 导入数据命中数据库已有差异记录
- **THEN** 系统弹出模态框，并按左右两侧分别展示数据库已有数据与本次待导入数据供用户逐条确认是否覆盖

#### Scenario: 导入确认
- **WHEN** 用户完成冲突确认并点击导入按钮
- **THEN** 系统仅导入用户保留且确认覆盖的行，并提示结果

#### Scenario: Word 列映射规则自动预填
- **WHEN** 用户上传 Word 文件并选择一个或多个表格进入配置映射步骤
- **THEN** 系统基于列映射规则自动预填项目、规格、验收和备注列
- **AND** 用户仍可逐表手动调整

#### Scenario: Excel 不使用列映射规则
- **WHEN** 用户上传 Excel 文件进入配置映射步骤
- **THEN** 系统不套用 Word 列映射规则
- **AND** 用户按工作表手动配置列序号

### Requirement: 智能填充界面
The system SHALL provide a smart-fill interface that supports match parameter configuration, preview, manual review, optional AI review, execution, and result download.

#### Scenario: 匹配参数配置
- **WHEN** the user configures smart-fill matching
- **THEN** the interface SHALL allow selecting matching scope, Embedding service, LLM service, thresholds, recall count, ambiguity margin, exact-match mode, empty-row filtering, and whether to enable synchronous AI equivalence adjudication

#### Scenario: 匹配预览
- **WHEN** the user starts preview
- **THEN** the interface SHALL show matched rows, confidence levels, no-match reasons, and decision details

#### Scenario: 详情弹窗
- **WHEN** the user opens a row detail
- **THEN** the interface SHALL show source text, selected candidate, top candidates, score details, evidence, conflicts, and AI equivalence result when present

#### Scenario: LLM复核
- **WHEN** the user triggers LLM review for rows requiring confirmation
- **THEN** the interface SHALL stream review progress and update row review state without blocking initial preview

#### Scenario: 执行填充
- **WHEN** the user confirms mappings and executes fill
- **THEN** the interface SHALL submit fill mappings and provide the generated result download

#### Scenario: Word 表格自动预填列索引
- **WHEN** 用户上传 Word 文件进入选择表格步骤
- **THEN** 系统基于列映射规则自动预填项目列、规格列、验收列和备注列
- **AND** 用户仍可逐表调整

#### Scenario: Excel 表格不自动套用规则
- **WHEN** 用户上传 Excel 文件进入选择表格步骤
- **THEN** 系统不套用 Word 列映射规则
- **AND** 用户继续按工作表手动配置列索引

### Requirement: 基础数据管理界面
系统 SHALL 提供客户、制程、验收规格的Web管理页面，并支持关键词检索与 AI 语义搜索两种查找方式。

#### Scenario: 客户管理
- **WHEN** 用户访问客户管理页面
- **THEN** 系统显示客户列表并支持新增、编辑、删除

#### Scenario: 制程管理
- **WHEN** 用户访问制程管理页面
- **THEN** 系统显示制程列表并支持新增、编辑、删除

#### Scenario: 验收规格浏览
- **WHEN** 用户访问验收规格页面
- **THEN** 系统显示规格列表并支持按客户、制程筛选

#### Scenario: 验收规格 AI 搜索
- **WHEN** 用户在验收规格页面需要查找语义相近的历史规格
- **THEN** 系统允许用户进入 AI 搜索流程而不影响现有关键词搜索

### Requirement: 配置管理界面
系统 SHALL 提供 AI 服务、Prompt 模板与列映射规则的 Web 配置页面。列映射规则页面 SHALL 能维护包括内置默认词在内的全部表头字段识别词，并提供"恢复默认词"操作。

#### Scenario: AI服务配置
- **WHEN** 用户访问AI配置页面
- **THEN** 系统显示AI服务列表并支持新增、编辑、删除

#### Scenario: 连接测试
- **WHEN** 用户点击测试连接按钮
- **THEN** 系统测试AI服务连接并显示结果

#### Scenario: Prompt 模板配置
- **WHEN** 用户访问 Prompt 模板页面
- **THEN** 系统显示系统模板场景列表并支持编辑、预览测试与恢复默认
- **AND** 页面不再以"设为默认模板"作为主操作

#### Scenario: 列映射规则配置
- **WHEN** 用户访问列映射规则页面
- **THEN** 系统显示列映射规则列表（含内置默认词）并支持新增、编辑、删除
- **AND** 用户对某表头词的新增/停用/删除会改变后续文档识别结果

#### Scenario: 恢复默认词
- **WHEN** 用户在列映射规则页面点击"恢复默认词"
- **THEN** 系统补齐缺失的内置默认词且不改动手动、学习与客户级规则
- **AND** 界面提示"删除单个内置词后可通过恢复默认词补齐；重启只在某字段内置词全空时兜底补齐"

#### Scenario: 旧 matching-knowledge 页面不可访问
- **WHEN** 用户尝试访问 matching-knowledge 配置页、分组作者视图或草稿生成入口
- **THEN** 系统不提供相关页面、导航、权限入口或旧提示文案

### Requirement: 权限与组织管理界面
系统 SHALL 提供角色、用户、权限与根组织的 Web 管理页面；其中系统用户仅允许配置一个角色和一个组织归属，组织管理界面只暴露根组织节点。

#### Scenario: 角色管理
- **WHEN** 用户访问角色管理页面
- **THEN** 系统显示角色列表，并支持维护页面级、按钮级和 API 级权限

#### Scenario: 用户管理
- **WHEN** 用户访问用户管理页面
- **THEN** 系统显示用户列表，并支持分配单个角色与单个组织归属

#### Scenario: 创建或编辑用户选择角色
- **WHEN** 管理员在新增或编辑用户弹窗中配置角色
- **THEN** 页面使用单选组件，且不允许提交空角色

#### Scenario: 组织管理
- **WHEN** 用户访问组织管理页面
- **THEN** 系统只显示当前公司的根组织节点
- **AND** 页面不提供新增子组织或删除组织节点操作

#### Scenario: 权限字典查看
- **WHEN** 用户访问权限字典页面
- **THEN** 系统显示当前页面、按钮与 API 权限编码清单

### Requirement: 审计日志界面
系统 SHALL 提供审计日志列表与详情查看的Web页面。

#### Scenario: 审计日志列表
- **WHEN** 用户访问审计日志页面
- **THEN** 系统显示控制器级别的新增、修改、删除与登录等审计记录

#### Scenario: 审计日志详情
- **WHEN** 用户点击某条审计日志
- **THEN** 系统显示该条日志的详情信息，而不在列表中直接展开全部内容

### Requirement: 智能填充界面支持实体判别配置
系统 SHALL 在智能填充匹配配置中提供 LLM 实体判别开关与阈值配置。

#### Scenario: 用户开启运行时实体判别
- **WHEN** 用户进入智能填充的匹配配置步骤
- **THEN** 页面提供 LLM 实体判别开关
- **AND** 页面允许配置候选数量或置信阈值等实体判别参数

### Requirement: 智能填充界面展示实体判别结果
系统 SHALL 在预览表和详情弹窗中展示实体判别带来的问题说明或同一实体提示。

#### Scenario: 预览表展示实体冲突
- **GIVEN** 某行最佳匹配存在实体冲突问题
- **WHEN** 系统展示匹配预览表
- **THEN** 用户无需打开详情即可看到实体冲突提示

#### Scenario: 详情弹窗展示实体未知
- **GIVEN** 某候选被判定为 `unknown`
- **WHEN** 用户打开详情弹窗
- **THEN** 页面展示该候选的实体未知问题说明
- **AND** 提示用户需要人工确认品牌或组织实体

### Requirement: 验收规格 AI 语义搜索界面
系统 SHALL 在验收规格页面提供 AI 语义搜索入口，用于搜索语义相近的历史验收规格。

#### Scenario: 打开 AI 搜索
- **WHEN** 用户在验收规格页面点击 `AI搜索`
- **THEN** 系统显示独立的 AI 搜索面板
- **AND** 保留当前分组上下文（客户、机型、制程）

#### Scenario: 批量输入语义搜索
- **WHEN** 用户在 AI 搜索面板输入多行文本并执行搜索
- **THEN** 系统将每一行文本视为一条独立查询
- **AND** 按查询文本分组展示搜索结果

#### Scenario: 分组展示搜索结果
- **WHEN** 语义搜索返回命中结果
- **THEN** 系统展示每条结果的相似度分数、项目、规格、验收标准、备注和所属分组信息
- **AND** 每组结果显示对应查询文本与命中数量

#### Scenario: 搜索结果逐条编辑
- **WHEN** 用户在 AI 搜索结果中点击某条规格的 `编辑`
- **THEN** 系统打开验收规格编辑界面
- **AND** 保存成功后刷新当前结果项与主规格列表

#### Scenario: 搜索无结果
- **WHEN** 某条输入文本没有命中任何规格
- **THEN** 系统在该输入分组下展示明确的空状态提示

### Requirement: 页面级权限过滤
前端 MUST 支持基于页面权限码过滤菜单与路由可见性，权限码采用 `page:module:page` 形式。

#### Scenario: 用户缺少页面权限
- **WHEN** 登录用户权限集中不包含目标页面权限码
- **THEN** 菜单中不展示该页面入口

### Requirement: 按钮级权限控制
前端 MUST 支持基于 `v-perms` 的按钮级权限控制，权限码采用 `btn:resource:action` 形式。

#### Scenario: 用户缺少按钮权限
- **WHEN** 登录用户不具备目标按钮权限码
- **THEN** 对应操作按钮不显示或不可操作

### Requirement: 决策透明展示
系统 SHALL 在预览与详情界面中展示匹配决策的关键证据与风险状态。

#### Scenario: 展示硬冲突与歧义原因
- **GIVEN** 某行匹配结果存在数值冲突、型号冲突或品牌实体冲突
- **WHEN** 系统展示预览或详情
- **THEN** 页面明确展示该行存在的关键冲突
- **AND** 告知该行不能自动采用

#### Scenario: 展示复核失败状态
- **GIVEN** 某行已进入 LLM 复核流程但复核超时或失败
- **WHEN** 系统展示预览或详情
- **THEN** 页面明确展示复核失败或超时状态
- **AND** 将该行标记为需要人工确认

### Requirement: 系统用户管理页面
系统 SHALL 提供系统用户管理页面，并支持管理员完成账号运维操作。

#### Scenario: 展示系统用户列表
- **WHEN** 管理员进入系统用户管理页面
- **THEN** 页面展示分页用户列表，包含用户名、昵称、角色、权限、启用状态和更新时间

#### Scenario: 新增系统用户
- **WHEN** 管理员在页面填写用户名、密码、角色等信息并提交
- **THEN** 页面调用创建接口并在成功后刷新用户列表

#### Scenario: 编辑系统用户
- **WHEN** 管理员在页面修改用户昵称、角色、权限或启用状态并保存
- **THEN** 页面调用更新接口并在成功后显示最新数据

#### Scenario: 重置用户密码
- **WHEN** 管理员在页面输入新密码并确认
- **THEN** 页面调用重置密码接口并提示操作结果

#### Scenario: 删除或禁用受限用户
- **WHEN** 管理员尝试删除当前登录账号或触发后端保护规则
- **THEN** 页面阻止或提示失败原因，不进行静默失败

### Requirement: Prompt 模板系统化管理界面
系统 SHALL 提供面向系统模板场景的 Prompt 模板管理界面，而不是以默认模板和任意命名为核心语义。

#### Scenario: 查看系统模板列表
- **WHEN** 用户访问 Prompt 模板页面
- **THEN** 页面显示系统模板的场景、系统键、显示名称、占位符说明和更新时间

#### Scenario: 编辑系统模板
- **WHEN** 用户编辑某个系统模板
- **THEN** 页面只允许编辑该场景对应的显示名称和模板内容
- **AND** 页面提示该模板被哪个业务场景使用

#### Scenario: 预览系统模板
- **WHEN** 用户在编辑页点击预览测试
- **THEN** 页面展示样例渲染结果和校验结果
- **AND** 在校验失败时阻止保存

#### Scenario: 恢复系统默认内容
- **WHEN** 用户点击恢复系统默认
- **THEN** 页面恢复该场景的默认模板内容
- **AND** 不影响其他场景模板

### Requirement: 页面与权限元数据单一来源
前端 MUST 使用一份共享导航元数据清单作为菜单、页面和页面权限码的单一来源，避免在多个路由模块中重复维护同一批元数据。

#### Scenario: 构建菜单与页面权限
- **WHEN** 前端装配静态路由和菜单
- **THEN** 系统从共享导航元数据清单读取页面标题、菜单层级与权限码
- **AND** 不在多个路由模块重复硬编码同一批页面权限信息

### Requirement: 前端启动不依赖运行时 async-routes
前端 MUST 通过静态路由注册完成启动，而不是依赖运行时请求后端 async-routes 接口。

#### Scenario: 页面初始化
- **WHEN** 用户刷新页面或首次进入系统
- **THEN** 前端通过静态路由注册完成页面初始化
- **AND** 不再以运行时 async-routes 请求作为启动前置条件

### Requirement: 批量回复页面
系统 SHALL 提供独立的“批量回复”页面，允许用户上传一份已回复来源文档，并将其验收与备注批量应用到其他同模板文件。

#### Scenario: 页面支持来源文档与目标文档上传
- **WHEN** 用户进入“批量回复”页面
- **THEN** 页面允许上传 1 份已回复来源文档和多份本地目标文档
- **AND** 页面明确提示来源文件与目标文件必须同格式

#### Scenario: 页面支持多表格配置
- **GIVEN** 用户已上传来源文档
- **WHEN** 用户配置批量回复参数
- **THEN** 页面允许按表格分别配置项目列、规格列、验收列、备注列、表头起始行、表头行数、数据起始行和空行过滤
- **AND** 页面支持一个来源文档配置多个表格

#### Scenario: 页面执行两段式流程
- **GIVEN** 用户已完成来源文档、表格配置和目标文档上传
- **WHEN** 用户点击预检
- **THEN** 页面逐文件展示可应用 / 不可应用状态与失败原因
- **AND** 只允许对通过预检的文件继续执行批量回复

#### Scenario: 页面明确不使用 AI
- **WHEN** 页面展示批量回复说明
- **THEN** 页面明确提示该流程不会重新匹配、不会调用 AI、不会做模糊判断
- **AND** 页面明确提示该流程只复制验收与备注

### Requirement: 批量回复采用独立菜单与权限
系统 SHALL 为“批量回复”提供独立菜单、页面和按钮权限，而不是复用“智能填充”的权限资源。

#### Scenario: 菜单与页面权限独立
- **WHEN** 系统下发导航与页面权限元数据
- **THEN** “批量回复”使用独立的菜单权限码和页面权限码
- **AND** 不复用 `smart-fill` 资源下的权限定义

#### Scenario: 按钮权限独立
- **WHEN** 登录用户缺少批量回复执行权限
- **THEN** 页面隐藏或禁用“预检批量回复”或“执行批量回复”按钮
- **AND** 不影响其已有的智能填充权限

### Requirement: 执行记录列表界面
系统 SHALL 提供智能填充与批量回复的执行记录列表界面，并按任务维度展示结果。

#### Scenario: 任务列表按一次执行一条展示
- **WHEN** 用户进入执行记录页面
- **THEN** 页面按一次任务一条记录展示列表
- **AND** 列表显示任务类型、源文件名、文件数、总行数、已采用数、未匹配数、跳过数、未采用数、人工选择数和执行时间

### Requirement: 执行记录详情界面
系统 SHALL 提供执行记录详情界面，并按文件和 Sheet 展示逐行结果。

#### Scenario: 先看文件再看 Sheet
- **WHEN** 用户打开某条执行记录
- **THEN** 页面先展示该任务下的文件列表

前端 MUST 统一上传区、决策标签、diff 视图、弹窗宽度和结果提示的视觉规则。

#### Scenario: 上传区统一
- **WHEN** 用户在导入、智能填充或批量回填流程上传文件
- **THEN** 上传区使用一致的图标尺寸、边框、主文案、副文案和状态样式

#### Scenario: 决策标签统一
- **WHEN** 页面展示自动采用、需人工确认、拒绝、失败或 AI 裁决参与状态
- **THEN** 页面使用统一业务决策色令牌
- **AND** 不通过局部 `!important` 硬编码覆盖全局主题

#### Scenario: 弹窗宽度规格化
- **WHEN** 页面打开业务弹窗
- **THEN** 弹窗宽度使用 S、M、L、XL 四档规格之一
- **AND** 小屏下宽度不得溢出视口

### Requirement: 核心流程表格可视行数
前端 MUST 保证数据导入和智能填充等核心流程的主预览表具备足够可视行数。

#### Scenario: 智能填充预览表可视行数
- **WHEN** 用户在 1080p 视口执行智能填充预览
- **THEN** 预览表可见数据行数不少于 15 行
- **AND** 页面不得通过固定 500px 高度限制主预览表

#### Scenario: 数据导入预览表使用剩余视口
- **WHEN** 用户在数据导入流程查看表格预览
- **THEN** 表格预览区域优先使用剩余视口高度展示数据
- **AND** 页面不得通过固定 400px 高度限制主预览表

### Requirement: 智能结构确认卡按推荐级别分组
系统 SHALL 在智能结构确认卡中按推荐导入、需要确认和建议跳过分组展示表格。

#### Scenario: 推荐表优先展示
- **GIVEN** 智能结构识别返回多张表
- **WHEN** 页面展示确认卡
- **THEN** 推荐导入的表优先展示
- **AND** 建议跳过的表默认折叠

#### Scenario: 用户可展开跳过表
- **GIVEN** 某张表被系统建议跳过
- **WHEN** 用户展开该表
- **THEN** 页面显示该表的表头、字段映射和跳过原因
- **AND** 用户可以手动改为参与导入或填充配置

### Requirement: 智能结构确认卡展示确认原因
系统 SHALL 在智能结构确认卡中展示 NeedConfirm 或 Skip 的具体原因。

#### Scenario: 显示缺列原因
- **GIVEN** 某张表因缺少规格列需要确认
- **WHEN** 页面展示该表
- **THEN** 页面显示缺少规格列的原因提示

#### Scenario: 显示路由规则原因
- **GIVEN** 某张表命中建议跳过的智能结构路由规则
- **WHEN** 页面展示该表
- **THEN** 页面显示命中的跳过原因

### Requirement: 智能结构识别保留手动兜底
系统 MUST 在新增推荐和跳过分组后继续保留手动配置兜底。

#### Scenario: 用户覆盖系统推荐
- **GIVEN** 系统将某张表建议跳过
- **WHEN** 用户认为该表应导入
- **THEN** 用户可以手动选择字段并继续现有导入或填充流程

### Requirement: 智能结构路由规则开放配置
系统 SHALL 提供智能结构路由规则配置入口，允许人员维护和审阅学习规则。

#### Scenario: 人员新增路由规则
- **GIVEN** 用户拥有智能结构路由规则维护权限
- **WHEN** 用户进入配置管理中的智能结构路由规则页面
- **THEN** 用户可以新增规则名称、表格类型、推荐结果、匹配范围、匹配方式、匹配词、权重、优先级、来源、客户域和启停状态

#### Scenario: 学习规则可审阅和调整
- **GIVEN** 用户确认智能结构后系统产生客户级学习规则
- **WHEN** 用户打开智能结构路由规则页面
- **THEN** 页面显示该学习规则的来源、客户域和匹配条件
- **AND** 用户可以禁用、编辑或删除该规则

### Requirement: 智能结构辅助规则页面降低表名误导
系统 SHALL 在智能结构路由规则配置页明确表达该页面用于辅助排除或覆盖推荐结果，而不是主结构识别配置入口。

#### Scenario: 页面展示辅助定位说明
- **WHEN** 用户进入智能结构路由规则配置页
- **THEN** 页面说明系统默认按表头结构和列映射识别
- **AND** 页面说明本页仅用于少数强制跳过、推荐覆盖或人工兜底场景

#### Scenario: 表名匹配标注 Excel 兜底
- **WHEN** 用户选择匹配范围
- **THEN** `TableName` 选项显示为“Sheet 名/表名（仅 Excel 兜底）”或等价中文说明

### Requirement: 智能结构辅助规则默认优先表头匹配
系统 SHALL 在新增智能结构辅助规则时默认使用表头匹配，避免引导用户按客户自定义 Sheet 名建立规则。

#### Scenario: 新增规则默认表头
- **WHEN** 用户点击新增智能结构辅助规则
- **THEN** 表单默认 `matchScope` 为 `Headers`
- **AND** 不默认使用 `TableName`

#### Scenario: 不暴露固定表格类型枚举
- **WHEN** 用户新增或编辑智能结构辅助规则
- **THEN** 页面不要求用户选择固定表格类型
- **AND** 页面不展示验收、安全、环保、SECS、Utility、报价、Layout 或备品等固定类型枚举
- **AND** 请求载荷使用内部中性类型值保持 API 兼容

#### Scenario: 不暴露历史学习路由规则
- **GIVEN** 数据库中残留来源为 `Learned` 的智能结构路由规则
- **WHEN** 用户打开智能结构辅助规则页面
- **THEN** 页面不展示这些历史学习规则
- **AND** 页面不提供“学习”作为可维护来源选项
