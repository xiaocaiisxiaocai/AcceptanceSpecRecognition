# User Interface Capability

## Purpose
提供基于Web的管理界面，覆盖数据导入、智能填充、基础数据维护、RBAC权限管理、配置管理与审计日志等核心操作流程。
## Requirements
### Requirement: Web管理界面
系统 SHALL 提供可在浏览器访问的Web管理界面。

#### Scenario: 浏览器访问
- **WHEN** 用户通过浏览器访问系统URL
- **THEN** 系统显示登录页面或主界面

---

### Requirement: 客户与制程独立选择
系统 SHALL 允许用户分别选择客户与制程作为数据范围条件。

#### Scenario: 独立选择器
- **WHEN** 用户在导入/验收规格/智能填充页面选择范围
- **THEN** 页面提供独立的客户选择器与制程选择器

#### Scenario: 组合筛选
- **WHEN** 用户选择客户与制程后
- **THEN** 系统按(CustomerId, ProcessId)组合筛选数据

---

### Requirement: 数据导入界面
系统 SHALL 提供文档上传与导入的Web界面。

#### Scenario: 文件上传
- **WHEN** 用户点击上传按钮并选择文档
- **THEN** 系统上传文件并显示文件信息

#### Scenario: 表格预览
- **WHEN** 文件上传成功
- **THEN** 系统显示文档中表格列表与预览内容

#### Scenario: 列映射配置
- **WHEN** 用户选择目标表格
- **THEN** 系统允许配置项目、规格、验收、备注列

#### Scenario: 客户制程选择
- **WHEN** 用户完成列映射配置
- **THEN** 系统提供客户与制程选择器

#### Scenario: 导入前剔除数据
- **WHEN** 用户进入确认导入步骤
- **THEN** 系统显示本次待导入数据，并允许用户单个删除或批量删除不需要导入的行

#### Scenario: 导入冲突模态框确认
- **WHEN** 系统检测到数据库已有相同项目与规格但内容不一致的数据
- **THEN** 系统弹出模态框，并按左右两侧分别展示数据库已有数据与本次待导入数据供用户逐条确认是否覆盖

#### Scenario: 导入确认
- **WHEN** 用户完成冲突确认并点击导入按钮
- **THEN** 系统仅导入用户保留且确认覆盖的行，并提示结果

### Requirement: 智能填充界面
系统 SHALL 提供基于统一多阶段匹配引擎的智能匹配与文档填充界面。

#### Scenario: 匹配参数配置
- **WHEN** 用户进入匹配配置步骤
- **THEN** 系统提供 Embedding 服务、LLM 服务、高置信阈值、候选过滤阈值、实体判别参数与复核并行参数
- **AND** AI 复核门禁固定开启，不再提供 `SingleStage / MultiStage` 或 `LLM 复核开关` 之类的策略切换
- **AND** 页面不再展示 `UseLlmReview`、`UseLlmSuggestion`、`SuggestNoMatchRows` 等旧兼容项

#### Scenario: 匹配预览
- **WHEN** 用户执行预览
- **THEN** 系统显示每行的匹配结果、最终决策状态、高置信状态与人工确认状态
- **AND** 对无法自动采用的样本给出明确提示
- **AND** 主表与详情以服务端返回的 `decision`、`confidenceLevel`、证据与 AI 裁决结果为准，不再由前端旧兼容字段自行推断

#### Scenario: 详情弹窗
- **WHEN** 用户查看匹配详情
- **THEN** 系统弹窗展示候选匹配列表、关键证据、冲突状态、歧义状态与复核结果

#### Scenario: LLM复核
- **WHEN** 系统处理高歧义样本
- **THEN** 系统流式返回复核进度
- **AND** 页面根据 `review.start`、`review.delta`、`review.done`、`review.error` 更新逐行状态
- **AND** 以 `stream.complete` 作为本次流式会话结束信号
- **AND** 仅对通过门禁的结果允许自动采用

#### Scenario: 执行填充
- **WHEN** 用户确认匹配结果并点击填充
- **THEN** 系统执行填充；Word 提供结果文件下载，Excel 写回源文件后提供下载入口
- **AND** 对需要人工确认但未确认的样本阻止直接自动采用
- **AND** 页面只提交当前文件中的 `SpecId` 与人工确认状态，不再透传旧 suggestion / compatibility 字段

### Requirement: 基础数据管理界面
系统 SHALL 提供客户、制程、验收规格的Web管理页面，并支持关键词检索与 AI 语义搜索两种查找方式。

#### Scenario: 客户管理
- **WHEN** 用户访问客户管理页面
- **THEN** 系统显示客户列表并支持新增、编辑、删除

#### Scenario: 制程管理
- **WHEN** 用户访问制程管理页面
- **THEN** 系统显示制程列表并支持新增、编辑、删除

#### Scenario: 验收规格浏览
- **WHEN** 用户访问验收规格页面
- **THEN** 系统显示规格列表并支持按客户、制程筛选

#### Scenario: 验收规格 AI 搜索
- **WHEN** 用户在验收规格页面需要查找语义相近的历史规格
- **THEN** 系统允许用户进入 AI 搜索流程而不影响现有关键词搜索

### Requirement: 配置管理界面
系统 SHALL 提供 AI 服务、Prompt 模板与列映射规则的 Web 配置页面。

#### Scenario: AI服务配置
- **WHEN** 用户访问AI配置页面
- **THEN** 系统显示AI服务列表并支持新增、编辑、删除

#### Scenario: 连接测试
- **WHEN** 用户点击测试连接按钮
- **THEN** 系统测试AI服务连接并显示结果

#### Scenario: Prompt 模板配置
- **WHEN** 用户访问 Prompt 模板页面
- **THEN** 系统显示系统模板场景列表并支持编辑、预览测试与恢复默认
- **AND** 页面不再以“设为默认模板”作为主操作

#### Scenario: 列映射规则配置
- **WHEN** 用户访问列映射规则页面
- **THEN** 系统显示列映射规则列表并支持新增、编辑、删除

### Requirement: 权限与组织管理界面
系统 SHALL 提供角色、用户、权限与根组织的 Web 管理页面；其中系统用户仅允许配置一个角色和一个组织归属，组织管理界面只暴露根组织节点。

#### Scenario: 角色管理
- **WHEN** 用户访问角色管理页面
- **THEN** 系统显示角色列表，并支持维护页面级、按钮级和 API 级权限

#### Scenario: 用户管理
- **WHEN** 用户访问用户管理页面
- **THEN** 系统显示用户列表，并支持分配单个角色与单个组织归属

#### Scenario: 创建或编辑用户选择角色
- **WHEN** 管理员在新增或编辑用户弹窗中配置角色
- **THEN** 页面使用单选组件，且不允许提交空角色

#### Scenario: 组织管理
- **WHEN** 用户访问组织管理页面
- **THEN** 系统只显示当前公司的根组织节点
- **AND** 页面不提供新增子组织或删除组织节点操作

#### Scenario: 权限字典查看
- **WHEN** 用户访问权限字典页面
- **THEN** 系统显示当前页面、按钮与 API 权限编码清单

### Requirement: 审计日志界面
系统 SHALL 提供审计日志列表与详情查看的Web页面。

#### Scenario: 审计日志列表
- **WHEN** 用户访问审计日志页面
- **THEN** 系统显示控制器级别的新增、修改、删除与登录等审计记录

#### Scenario: 审计日志详情
- **WHEN** 用户点击某条审计日志
- **THEN** 系统显示该条日志的详情信息，而不在列表中直接展开全部内容

### Requirement: 智能填充界面支持实体判别配置
系统 SHALL 在智能填充匹配配置中提供 LLM 实体判别开关与阈值配置。

#### Scenario: 用户开启运行时实体判别
- **WHEN** 用户进入智能填充的匹配配置步骤
- **THEN** 页面提供 LLM 实体判别开关
- **AND** 页面允许配置候选数量或置信阈值等实体判别参数

### Requirement: 智能填充界面展示实体判别结果
系统 SHALL 在预览表和详情弹窗中展示实体判别带来的问题说明或同一实体提示。

#### Scenario: 预览表展示实体冲突
- **GIVEN** 某行最佳匹配存在实体冲突问题
- **WHEN** 系统展示匹配预览表
- **THEN** 用户无需打开详情即可看到实体冲突提示

#### Scenario: 详情弹窗展示实体未知
- **GIVEN** 某候选被判定为 `unknown`
- **WHEN** 用户打开详情弹窗
- **THEN** 页面展示该候选的实体未知问题说明
- **AND** 提示用户需要人工确认品牌或组织实体

### Requirement: 验收规格 AI 语义搜索界面
系统 SHALL 在验收规格页面提供 AI 语义搜索入口，用于搜索语义相近的历史验收规格。

#### Scenario: 打开 AI 搜索
- **WHEN** 用户在验收规格页面点击 `AI搜索`
- **THEN** 系统显示独立的 AI 搜索面板
- **AND** 保留当前分组上下文（客户、机型、制程）

#### Scenario: 批量输入语义搜索
- **WHEN** 用户在 AI 搜索面板输入多行文本并执行搜索
- **THEN** 系统将每一行文本视为一条独立查询
- **AND** 按查询文本分组展示搜索结果

#### Scenario: 分组展示搜索结果
- **WHEN** 语义搜索返回命中结果
- **THEN** 系统展示每条结果的相似度分数、项目、规格、验收标准、备注和所属分组信息
- **AND** 每组结果显示对应查询文本与命中数量

#### Scenario: 搜索结果逐条编辑
- **WHEN** 用户在 AI 搜索结果中点击某条规格的 `编辑`
- **THEN** 系统打开验收规格编辑界面
- **AND** 保存成功后刷新当前结果项与主规格列表

#### Scenario: 搜索无结果
- **WHEN** 某条输入文本没有命中任何规格
- **THEN** 系统在该输入分组下展示明确的空状态提示

### Requirement: 页面级权限过滤
前端 MUST 支持基于页面权限码过滤菜单与路由可见性，权限码采用 `page:module:page` 形式。

#### Scenario: 用户缺少页面权限
- **WHEN** 登录用户权限集中不包含目标页面权限码
- **THEN** 菜单中不展示该页面入口

### Requirement: 按钮级权限控制
前端 MUST 支持基于 `v-perms` 的按钮级权限控制，权限码采用 `btn:resource:action` 形式。

#### Scenario: 用户缺少按钮权限
- **WHEN** 登录用户不具备目标按钮权限码
- **THEN** 对应操作按钮不显示或不可操作

### Requirement: 智能填充一次性严格复用界面
系统 SHALL 在智能填充完成后提供一次性严格复用界面，用于将当前已确认的填充结果应用到其他完全相同模板的文件。

#### Scenario: 填充完成后显示复用入口
- **GIVEN** 用户已经完成当前文件的智能填充
- **WHEN** 页面展示填充完成状态
- **THEN** 页面显示“应用到相同验规”入口
- **AND** 页面说明该能力基于当前填充结果执行严格复用

#### Scenario: 复用流程明确不使用 AI 且不保存模板
- **GIVEN** 用户进入严格复用流程
- **WHEN** 页面展示复用说明
- **THEN** 页面明确提示该流程不会重新匹配、不会调用 AI
- **AND** 页面明确提示本次复用不会保存为长期模板

#### Scenario: 展示逐文件预检结果
- **GIVEN** 用户上传多个目标文件
- **WHEN** 系统完成严格复用预检
- **THEN** 页面逐个展示文件是否可应用
- **AND** 对不可应用的文件显示失败原因
- **AND** 对可应用的文件允许继续批量执行

#### Scenario: 批量复用执行与下载
- **GIVEN** 存在一个或多个通过预检的目标文件
- **WHEN** 用户确认执行严格复用
- **THEN** 页面展示批量执行结果
- **AND** 单文件场景提供直接下载
- **AND** 多文件场景提供统一打包下载

### Requirement: 决策透明展示
系统 SHALL 在预览与详情界面中展示匹配决策的关键证据与风险状态。

#### Scenario: 展示硬冲突与歧义原因
- **GIVEN** 某行匹配结果存在数值冲突、型号冲突或品牌实体冲突
- **WHEN** 系统展示预览或详情
- **THEN** 页面明确展示该行存在的关键冲突
- **AND** 告知该行不能自动采用

#### Scenario: 展示复核失败状态
- **GIVEN** 某行已进入 LLM 复核流程但复核超时或失败
- **WHEN** 系统展示预览或详情
- **THEN** 页面明确展示复核失败或超时状态
- **AND** 将该行标记为需要人工确认

### Requirement: 系统用户管理页面
系统 SHALL 提供系统用户管理页面，并支持管理员完成账号运维操作。

#### Scenario: 展示系统用户列表
- **WHEN** 管理员进入系统用户管理页面
- **THEN** 页面展示分页用户列表，包含用户名、昵称、角色、权限、启用状态和更新时间

#### Scenario: 新增系统用户
- **WHEN** 管理员在页面填写用户名、密码、角色等信息并提交
- **THEN** 页面调用创建接口并在成功后刷新用户列表

#### Scenario: 编辑系统用户
- **WHEN** 管理员在页面修改用户昵称、角色、权限或启用状态并保存
- **THEN** 页面调用更新接口并在成功后显示最新数据

#### Scenario: 重置用户密码
- **WHEN** 管理员在页面输入新密码并确认
- **THEN** 页面调用重置密码接口并提示操作结果

#### Scenario: 删除或禁用受限用户
- **WHEN** 管理员尝试删除当前登录账号或触发后端保护规则
- **THEN** 页面阻止或提示失败原因，不进行静默失败

### Requirement: Prompt 模板系统化管理界面
系统 SHALL 提供面向系统模板场景的 Prompt 模板管理界面，而不是以默认模板和任意命名为核心语义。

#### Scenario: 查看系统模板列表
- **WHEN** 用户访问 Prompt 模板页面
- **THEN** 页面显示系统模板的场景、系统键、显示名称、占位符说明和更新时间

#### Scenario: 编辑系统模板
- **WHEN** 用户编辑某个系统模板
- **THEN** 页面只允许编辑该场景对应的显示名称和模板内容
- **AND** 页面提示该模板被哪个业务场景使用

#### Scenario: 预览系统模板
- **WHEN** 用户在编辑页点击预览测试
- **THEN** 页面展示样例渲染结果和校验结果
- **AND** 在校验失败时阻止保存

#### Scenario: 恢复系统默认内容
- **WHEN** 用户点击恢复系统默认
- **THEN** 页面恢复该场景的默认模板内容
- **AND** 不影响其他场景模板

### Requirement: 页面与权限元数据单一来源
前端 MUST 使用一份共享导航元数据清单作为菜单、页面和页面权限码的单一来源，避免在多个路由模块中重复维护同一批元数据。

#### Scenario: 构建菜单与页面权限
- **WHEN** 前端装配静态路由和菜单
- **THEN** 系统从共享导航元数据清单读取页面标题、菜单层级与权限码
- **AND** 不在多个路由模块重复硬编码同一批页面权限信息

### Requirement: 前端启动不依赖运行时 async-routes
前端 MUST 通过静态路由注册完成启动，而不是依赖运行时请求后端 async-routes 接口。

#### Scenario: 页面初始化
- **WHEN** 用户刷新页面或首次进入系统
- **THEN** 前端通过静态路由注册完成页面初始化
- **AND** 不再以运行时 async-routes 请求作为启动前置条件
