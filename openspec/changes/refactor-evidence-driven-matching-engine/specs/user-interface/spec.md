## MODIFIED Requirements

### Requirement: 智能填充界面
系统 SHALL 提供基于统一多阶段匹配引擎的智能匹配与文档填充界面。

#### Scenario: 匹配参数配置
- **WHEN** 用户进入匹配配置步骤
- **THEN** 系统提供 Embedding 服务、LLM 复核、高置信阈值、候选过滤阈值与复核相关配置
- **AND** 页面不再提供 `SingleStage / MultiStage` 策略切换

#### Scenario: 匹配预览
- **WHEN** 用户执行预览
- **THEN** 系统显示每行的匹配结果、最终决策状态、高置信状态与人工确认状态
- **AND** 对无法自动采用的样本给出明确提示

#### Scenario: 详情弹窗
- **WHEN** 用户查看匹配详情
- **THEN** 系统弹窗展示候选匹配列表、关键证据、冲突状态、歧义状态与复核结果

#### Scenario: LLM复核
- **WHEN** 用户开启 LLM 复核并处理高歧义样本
- **THEN** 系统流式返回复核进度
- **AND** 仅对通过门禁的结果允许自动采用

#### Scenario: 执行填充
- **WHEN** 用户确认匹配结果并点击填充
- **THEN** 系统执行填充；Word 提供结果文件下载，Excel 写回源文件后提供下载入口
- **AND** 对需要人工确认但未确认的样本阻止直接自动采用

## ADDED Requirements

### Requirement: 决策透明展示
系统 SHALL 在预览与详情界面中展示匹配决策的关键证据与风险状态。

#### Scenario: 展示硬冲突与歧义原因
- **GIVEN** 某行匹配结果存在数值冲突、型号冲突或品牌实体冲突
- **WHEN** 系统展示预览或详情
- **THEN** 页面明确展示该行存在的关键冲突
- **AND** 告知该行不能自动采用

#### Scenario: 展示复核失败状态
- **GIVEN** 某行已进入 LLM 复核流程但复核超时或失败
- **WHEN** 系统展示预览或详情
- **THEN** 页面明确展示复核失败或超时状态
- **AND** 将该行标记为需要人工确认
