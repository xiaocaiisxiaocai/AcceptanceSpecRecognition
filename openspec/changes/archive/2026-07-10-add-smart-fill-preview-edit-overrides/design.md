## Context
- 智能填充预览结果已有单行采用/不填充操作，但没有“导出前业务修订”入口。
- 当前执行契约禁止客户端透传旧 `Acceptance`、`Remark` 字段，后端会按当前最佳匹配重算并写回规格库原值。
- 本次需求明确要求：只影响本次导出结果，不修改规格主数据。

## Goals / Non-Goals
- Goals:
  - 支持预览页单行编辑 `验收标准` 与 `备注`
  - `保存并采用` 自动选中当前行
  - 导出文件与执行历史使用本次覆盖值
- Non-Goals:
  - 不开放“无匹配行手工录入”
  - 不改规格库数据
  - 不复用匹配详情弹窗承载编辑

## Decisions
- Decision: 使用独立编辑弹窗，而不是改造现有详情弹窗。
  - Alternatives considered: 详情弹窗可编辑，但会把匹配分析与业务修订混在一起，增加理解成本。
- Decision: 覆盖值存储在单行映射请求里，由执行阶段一次性消费。
  - Alternatives considered: 只存在前端本地状态，但无法保证导出链路与执行历史一致。
- Decision: `不填充` 仅取消采用状态，不清空覆盖值。
  - Alternatives considered: 同时清空覆盖值，但容易造成误删客户刚录入的内容。

## Risks / Trade-offs
- 预览结果重新生成后，旧覆盖值不再可信。
  - Mitigation: 每次重新预览时清空覆盖草稿。
- 执行历史当前默认展示规格库原值。
  - Mitigation: 在构建历史行 DTO 时优先展示本次覆盖值。

## Migration Plan
1. 扩展前端选择模型和执行 DTO。
2. 增加编辑弹窗与表格覆盖值展示。
3. 扩展后端写回链路并补集成测试。
4. 验证前端类型检查、后端定向测试和整仓构建。
