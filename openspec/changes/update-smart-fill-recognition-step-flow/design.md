## Context
智能填充默认模式当前只有三个步骤。第 0 步既发起识别又承载识别结果；只有参与填充的表全部变成 `AutoApply` 后，页面才能将 `currentStep` 推进到匹配配置。大文件或多区域确认卡会把确认操作推到视口下方，固定底栏又只呈现不可操作的禁用按钮，导致状态与下一动作不清晰。

高级模式已有四步，并与默认模式共用 `currentStep`、预览请求取消和返回逻辑，因此本次调整需要显式步骤常量，避免继续依赖分散的数字下标。

## Goals / Non-Goals
- Goals: 识别成功后立即离开上传页，进入职责单一的识别确认页。
- Goals: 用户无需在上传内容下方寻找确认入口，当前 Sheet 的问题和主操作保持清晰可见。
- Goals: 保持返回、手动处理、匹配预览、请求取消和 keep-alive 状态一致。
- Non-Goals: 不修改后端识别算法、AI 调用策略、确认学习语义或匹配接口。
- Non-Goals: 不在本次变更中重做数据导入页面流程。

## Decisions

### 1. 默认模式采用四个显式步骤
定义默认模式步骤常量：上传归属、识别确认、匹配配置、预览确认。识别成功且能够构造至少一个候选配置后，将 `currentStep` 直接设置为识别确认步骤；不再以“全部已确认”作为是否离开上传页的条件。

高级模式继续使用现有四步语义，但导航、预览步骤判断和返回逻辑改为引用具名常量，降低默认模式插入新步骤后的下标错位风险。

### 2. 上传页与确认页物理分离渲染
上传页只渲染文件、归属、AI 辅助和识别发起/失败状态。确认页渲染识别摘要与 `SmartStructureConfirmTabs`。识别中的 loading 保留在上传页；成功后切页，避免内容跳增造成视口位置混乱。

### 3. 确认页以当前 Sheet 的问题和动作作为主线
确认页顶部展示文件与归属的紧凑摘要，主体展示 Sheet Tab 和确认卡。当前 Sheet 的阻断原因必须靠近确认操作展示；确认学习或调整范围入口不得要求用户滚过整页证据后才能发现。底部下一步按钮只负责进入匹配配置，并在不可继续时显示剩余待确认数量或具体原因。

### 4. 返回保留结果，输入变化主动失效
从识别确认返回上传页时保留识别结果，便于用户查看或调整 AI 开关后主动重新识别。上传新文件、删除文件或切换客户时沿用现有重置逻辑清空旧识别结果，避免跨文件或跨客户复用。

### 5. 自动采用结果也经过确认页
即使全部 Sheet 都是 `AutoApply`，识别成功后仍进入识别确认页，让用户先看到参与/跳过范围，再主动进入匹配配置。确认页此时不增加额外确认要求，下一步按钮立即可用。

## Risks / Trade-offs
- 默认流程增加一个可见步骤，多一次用户点击；换取步骤职责清晰和识别结果可审阅。
- 默认与高级模式都为四步但第二步语义不同；通过具名常量和导航单元测试避免混淆。
- keep-alive 下返回可能保留滚动位置；进入识别确认时需要将主内容滚到顶部或当前待确认 Sheet。

## Migration Plan
纯前端流程调整，无数据迁移。若上线后出现导航回归，可回退默认步骤数组和分步渲染，不影响已经保存的模板、学习规则或执行记录。
