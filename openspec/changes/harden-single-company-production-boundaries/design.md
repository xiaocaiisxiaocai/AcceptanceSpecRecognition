## Context

系统部署目标是单公司内网环境。生产验证已经证明当前业务数据和常规重启可用，但也证明部署路径、无限预览、迁移自动化和共享出口 IP 下的刷新行为存在明确边界问题。这些问题跨越 API、数据、部署与前端兼容层，不能靠提高机器资源或隐藏错误规避。

## Goals / Non-Goals

### Goals

- 让同一份 API 在 Kestrel、Nginx 和 IIS 下保持唯一且可预测的 `/api` 外部路径。
- 防止生产启动自动执行不可逆数据库变更。
- 让所有列表、预览、上传和后台保留策略具备硬上限。
- 让单公司、不活动会话和 AI 能力状态可以被机器验证。

### Non-Goals

- 不引入多租户 `CompanyId` 全链路改造。
- 不在本变更中更换数据库、对象存储或认证协议。
- 不保证旧客户端继续使用无界整表预览。
- 不把外部 AI 不可用视为 API 进程死亡。

## Decisions

### Decision 1: 外部前缀只由代理层拥有一次

API 继续声明 `/api/...` 业务路由；IIS 使用站点根应用承载 API，或通过明确的路径基址重写把外部 `/api` 映射到内部路由，但不得把已包含 `/api` 的应用再挂载到名为 `api` 的子应用。部署验收必须覆盖登录、刷新、登出、健康检查和静态 Web 回退。

### Decision 2: 破坏性迁移显式批准

迁移元数据标记是否可能删除/重建表列或批量改写数据。生产启动只自动执行安全迁移；存在待执行的破坏性迁移时返回 NotReady 并输出迁移标识。运维通过独立命令在已完成备份和演练后显式执行。

### Decision 3: 预览与完整导出严格分离

`previewRows` 必须是正数并受服务端上限约束，`0` 不再代表无限。完整数据只通过受权限控制的导出/下载流程提供。Excel 解析优先使用临时文件和有界窗口；无法流式处理的库调用必须在进入解析前执行文件大小、解压后大小和工作表维度预算检查。

### Decision 4: 限流以安全主体为主键

登录仍以 IP 加用户名摘要分区；刷新在 Cookie 可识别后以不可逆会话摘要或用户标识分区，无法识别时回退 IP。页面启动刷新具有较小独立突发预算，持续滥用仍进入 429。

### Decision 5: 安全上下文变更及时失效

访问令牌保持短生命周期。角色、组织或账号状态变化递增用户安全版本；受保护请求发现版本不一致时拒绝，刷新会话同步撤销。后台清理按配置批量删除过期刷新会话，避免无界增长。

### Decision 6: 查询与保留统一有界

审计和执行历史页码、页大小在 API 层和仓储层双重限制；后台保留策略按年龄和最大记录数分批清理，并记录删除数量而非业务原文。

### Decision 7: 单公司是启动不变量

运行数据库必须恰好存在一个公司根记录。零个或多个公司时就绪检查失败，业务端点不进入可服务状态，并提供只读诊断信息。该决定替代多租户隔离改造，不删除或自动合并异常公司数据。

### Decision 8: 健康状态分层

`/health/live` 只表示进程存活；`/health/ready` 覆盖数据库、文件存储、迁移与单公司不变量；AI 状态作为能力字段或独立检查暴露。代理只用 ready 端点决定是否接流量，管理界面明确展示 AI degraded，而不把它伪装成全量 Healthy。

## Risks / Trade-offs

- 拒绝无界预览会影响旧客户端；发布前通过访问日志确认调用并提供有界迁移说明。
- 安全版本检查增加一次缓存或数据库读取；优先使用短 TTL 缓存并在变更时主动失效。
- 破坏性迁移改为显式步骤会增加发布操作，但避免应用启动即不可逆改库。
- 严格单公司检查可能阻断已有异常数据；只提供诊断和修复脚本，不自动合并数据。

## Migration Plan

1. 先增加观测、配置默认值和只报告不拒绝的兼容检查。
2. 在备份恢复演练通过后启用迁移分类与独立迁移命令。
3. 修正 IIS/代理拓扑并完成登录、刷新、登出和健康检查验收。
4. 统计无界预览调用，升级所有内置客户端后启用拒绝策略。
5. 启用会话分区限流、安全版本和有界清理。
6. 最后启用单公司强制就绪门禁与分层健康检查。

## Rollback Plan

- 每个阶段独立发布；异常时回退对应应用版本和代理配置。
- 数据迁移阶段必须先生成并验证备份；只允许使用经过演练的前向修复或数据库恢复，不自动执行反向破坏性迁移。
- 无界预览兼容开关只允许短期应急开启，并继续受绝对文件/解压预算保护。
