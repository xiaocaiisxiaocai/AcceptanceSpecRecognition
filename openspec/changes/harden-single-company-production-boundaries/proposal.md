# Change: 收紧单公司生产运行边界

## Why

当前实现已经能够完成核心业务流程，但生产验证暴露出数个不能作为普通缺陷补丁直接改变的运行契约：IIS 子应用会形成重复 `/api/api` 路径，启动时自动迁移没有区分破坏性迁移，旧客户端仍可用 `previewRows=0` 拉取整表，刷新限流按共享 IP 聚合，以及执行历史、审计和刷新会话缺少统一的有界保留策略。系统明确只服务单公司，因此还需要在启动时验证该不变量，避免异常数据被静默带入运行期。

这些调整会改变部署拓扑、兼容行为、安全策略或数据生命周期，必须先通过 OpenSpec 明确批准、迁移和回滚边界。

## What Changes

- 统一反向代理和 IIS 的外部 `/api` 前缀契约，应用内部只维护一份 API 路由，不再依赖会产生重复前缀的子应用布局。
- 将数据库迁移拆分为安全自动迁移与显式批准的破坏性迁移；生产启动不得自动执行未批准的破坏性步骤。
- 废弃 `previewRows=0` 的无界整表语义，为预览、文件对比和上传建立服务端硬上限、临时文件/流式处理与清晰的超限响应。
- 将刷新限流从共享 IP 调整为经过认证的会话/用户分区，并为启动刷新提供独立的短时突发预算。
- 为角色、组织和会话变更定义及时失效边界；为刷新会话、执行历史和审计日志定义可配置的分页及保留上限。
- 按单公司内网使用约束，将种子账号、创建用户和重置密码的新密码长度统一为 4 到 200 个字符；既有哈希和登录保持兼容。
- 启动时强制验证单公司根数据不变量，检测到零个或多个公司时拒绝进入可服务状态。
- 将存活、基础依赖就绪和可选 AI 能力状态分开表达，避免 AI 不可用时仍被误读为全部能力正常。

## Impact

- Affected specs: `api`, `architecture`, `data-storage`, `table-preview`
- Affected code: API 启动与健康检查、迁移执行器、认证限流与会话、分页查询、Excel 预览/对比、IIS/反向代理部署文档
- Breaking behavior: 无界预览请求将被拒绝；不符合单公司不变量的数据集将不再启动；生产破坏性迁移需要显式操作；新密码最低长度由 12 位调整为 4 位
- Rollout: 先发布兼容检查与观测，再启用拒绝策略；每项均保留独立回滚开关或部署回退步骤
