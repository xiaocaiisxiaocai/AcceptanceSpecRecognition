## ADDED Requirements

### Requirement: 生产数据库迁移区分破坏性边界

系统 MUST 在生产启动时拒绝自动执行未明确批准的破坏性数据库迁移。

#### Scenario: 存在待执行的破坏性迁移

- **WHEN** 生产实例启动并检测到可能删除、重建或批量改写数据的待执行迁移
- **THEN** 系统不自动执行该迁移
- **AND** 就绪检查返回失败并标识迁移名称

#### Scenario: 显式执行破坏性迁移

- **GIVEN** 已完成可恢复的数据库备份与迁移演练
- **WHEN** 运维使用独立命令明确执行指定迁移
- **THEN** 系统记录迁移标识、开始和结束状态
- **AND** 不把应用普通启动等同于批准

### Requirement: 刷新请求按会话安全分区限流

系统 MUST 避免同一共享出口 IP 下的正常浏览器会话互相耗尽刷新预算。

#### Scenario: 多用户从同一出口并发启动

- **WHEN** 多个有效会话从同一 IP 在短时间内执行启动刷新
- **THEN** 系统按会话摘要或用户安全主体分别计数
- **AND** 正常启动突发不会仅因共享 IP 被统一返回 429

### Requirement: 管理查询与历史数据有界

系统 MUST 对审计日志、执行历史和刷新会话实施服务端分页上限与可配置保留策略。

#### Scenario: 请求超大页

- **WHEN** 客户端请求超过配置上限的页大小
- **THEN** API 拒绝请求或收敛到明确的最大页大小
- **AND** 仓储查询不会物化无界结果集

### Requirement: 生产健康检查分层表达

系统 MUST 分别表达存活、接流量就绪和可选 AI 能力状态。

#### Scenario: 基础依赖可用但 AI 不可用

- **WHEN** 数据库、文件存储、迁移和单公司不变量正常，但外部 AI 不可用
- **THEN** ready 状态允许非 AI 基础能力按配置继续服务
- **AND** 响应明确标识 AI capability 为 degraded 或 unavailable
