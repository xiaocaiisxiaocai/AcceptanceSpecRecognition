## MODIFIED Requirements

### Requirement: 系统用户与权限接口采用单组织和菜单权限模型
系统 MUST 在系统用户管理和权限相关接口中使用单组织字段，并暴露菜单权限能力；单个用户只能归属当前公司内的一个有效组织节点。

#### Scenario: 创建用户提交单组织
- **WHEN** 管理员调用系统用户创建接口并提交当前公司内有效的 `orgUnitId`
- **THEN** 系统为该用户建立唯一组织关系，并返回单个 `orgUnitId` / `orgUnitName`
- **AND** 该组织可以是公司、事业部、部门或课别

#### Scenario: 更新用户提交旧组织数组
- **WHEN** 客户端仍以旧格式提交 `orgUnitIds`、`orgUnits` 或 `primaryOrgUnitId`
- **THEN** 系统拒绝请求并返回参数错误

#### Scenario: 用户提交无效组织
- **WHEN** 管理员提交其他公司、已停用或不存在的组织节点
- **THEN** 系统拒绝请求且不改变原用户组织归属

#### Scenario: 路由权限包含菜单权限
- **WHEN** 用户登录后拉取路由或权限数据
- **THEN** 返回结果能够区分菜单权限与页面权限，并据此控制导航容器和页面节点

### Requirement: 组织层级管理 API
系统 SHALL 提供当前公司内公司、事业部、部门和课别组成的组织层级查询与安全维护接口，同时保持唯一公司根节点。

#### Scenario: 查询组织树与平铺列表
- **WHEN** 客户端访问组织树或组织平铺接口
- **THEN** 系统返回当前公司的全部组织节点
- **AND** 树接口按父子关系返回嵌套结构，平铺接口按深度、排序和 ID 稳定排序

#### Scenario: 新增下级组织
- **WHEN** 管理员在有效父节点下新增类型更低的事业部、部门或课别
- **THEN** 系统创建节点并生成正确的 `ParentId`、`Path` 与 `Depth`
- **AND** 系统允许向下跳级但拒绝同级、反向层级、第二个公司根节点及课别下级

#### Scenario: 更新组织节点
- **WHEN** 管理员更新当前公司内组织节点的编码、名称、排序或状态
- **THEN** 系统保存合法修改
- **AND** 系统不允许通过更新接口移动节点或修改组织类型

#### Scenario: 停用受保护组织
- **WHEN** 管理员停用公司根节点、存在有效下级节点或存在有效用户归属的组织节点
- **THEN** 系统拒绝请求且不改变组织状态

#### Scenario: 删除未引用叶子节点
- **WHEN** 管理员删除没有下级、用户归属、角色范围或业务数据引用的非根叶子节点
- **THEN** 系统删除该节点并记录审计日志

#### Scenario: 删除受保护节点
- **WHEN** 管理员删除根节点、非叶子节点或仍被任何业务关系引用的节点
- **THEN** 系统拒绝删除并返回具体引用原因

#### Scenario: 保存角色组织范围
- **WHEN** 管理员为角色保存组织节点、组织子树或自定义节点集合范围
- **THEN** 系统只接受当前公司内有效组织节点
- **AND** 运行时数据范围按节点路径包含正确的组织集合
