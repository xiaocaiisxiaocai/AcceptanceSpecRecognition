## MODIFIED Requirements

### Requirement: 权限与组织管理界面
系统 SHALL 提供角色、用户、权限与层级组织的 Web 管理页面；系统用户仅允许配置一个角色和一个组织归属，组织管理界面提供当前公司完整组织树的安全维护能力。

#### Scenario: 角色管理
- **WHEN** 用户访问角色管理页面
- **THEN** 系统显示角色列表，并支持维护页面级、按钮级和 API 级权限
- **AND** 数据范围可选择单个组织、组织子树、自定义组织节点或全部数据

#### Scenario: 用户管理
- **WHEN** 用户访问用户管理页面
- **THEN** 系统显示用户列表，并支持分配单个角色与单个有效组织归属

#### Scenario: 创建或编辑用户选择角色
- **WHEN** 管理员在新增或编辑用户弹窗中配置角色
- **THEN** 页面使用单选组件，且不允许提交空角色

#### Scenario: 创建或编辑用户选择组织
- **WHEN** 管理员在新增或编辑用户弹窗中配置组织
- **THEN** 页面显示当前公司全部有效层级节点并使用单选组件
- **AND** 不允许提交空组织、其他公司组织或已停用组织

#### Scenario: 组织层级管理
- **WHEN** 用户访问组织管理页面
- **THEN** 系统以树形表格显示公司、事业部、部门和课别
- **AND** 有权限的管理员可新增合法下级、编辑节点及删除未引用叶子节点

#### Scenario: 新增组织选择类型
- **WHEN** 管理员选择父组织并新增下级
- **THEN** 页面仅提供比父节点层级更低的组织类型
- **AND** 课别节点不显示新增下级操作

#### Scenario: 删除组织确认
- **WHEN** 管理员请求删除组织节点
- **THEN** 页面明确提示不可级联删除，并要求二次确认
- **AND** 服务端拒绝时显示具体的下级或引用原因

#### Scenario: 权限字典查看
- **WHEN** 用户访问权限字典页面
- **THEN** 系统显示当前页面、按钮与 API 权限编码清单
