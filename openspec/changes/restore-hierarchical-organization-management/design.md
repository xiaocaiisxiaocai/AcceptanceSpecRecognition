## Context

系统曾具备多层组织树管理，后续正式契约被收敛为单公司根组织。当前实体、外键、组织路径、角色数据范围和查询过滤仍具备层级能力，但 API、权限种子、用户归属校验和界面主动屏蔽了下级节点。

本次恢复层级组织，但不恢复多组织用户：每个用户仍只有一个组织归属。该约束由现有数据库唯一索引继续保证。

## Goals / Non-Goals

- Goals:
  - 管理公司、事业部、部门和课别组成的组织树。
  - 用户可归属任意一个有效组织节点。
  - 角色可按节点、子树、自定义节点集合或全部数据授权。
  - 删除和停用不会制造悬空引用或不可解释的权限状态。
  - 保留历史组织、用户、角色和业务数据。
- Non-Goals:
  - 不允许一个用户同时归属多个组织。
  - 不支持移动已有节点或修改已有节点的组织类型。
  - 不支持级联删除组织及其关联数据。
  - 不新增公司根节点或跨公司移动节点。

## Decisions

### Decision: 保持单用户单组织，恢复任意层级归属

`AuthUserOrgUnits.UserId` 唯一约束保持不变。创建或更新用户时，`orgUnitId` 必须指向当前公司内的有效组织节点，不再限制为公司根节点。

Alternatives considered:

- 多组织用户：会改变认证快照、DTO、唯一索引和权限合并语义，超出已确认范围。
- 仅恢复组织页面：会让组织树与用户/角色权限脱节，形成不可用的能力面。

### Decision: 组织类型允许向下跳级

组织类型顺序固定为 `Company < Division < Department < Section`。新节点必须有当前公司内的有效父节点，且子类型数值必须大于父类型；因此允许公司直接挂部门或课别，但禁止同级、反向挂载，课别无法再挂子节点。

每公司只允许一个 `Company` 根节点。新增接口只创建非公司节点。

### Decision: 节点位置和类型创建后不可修改

更新接口只允许修改编码、名称、排序和启用状态，不接收 `ParentId` 或 `UnitType`。这样避免移动节点时批量重写自身与全部后代的 `Path`、`Depth`，也避免权限范围在一次普通编辑中发生大面积变化。

### Decision: 删除和停用采用拒绝式保护

- 根节点不能停用或删除。
- 存在下级节点时不能删除。
- 被用户组织关系、角色数据范围、验收规格或文件归属引用时不能删除。
- 节点存在有效用户归属或有效下级节点时不能停用。
- 删除不级联处理任何业务引用。

数据库外键仍作为最后一道一致性保护，应用服务返回具体中文原因。

### Decision: 角色范围复用现有数据范围类型

- `Self`: 仅本人数据。
- `OrgNode`: 指定一个组织节点。
- `OrgSubtree`: 指定一个组织节点及其全部后代。
- `CustomNodes`: 指定一个或多个组织节点。
- `All`: 当前公司全部数据。

角色范围中出现的组织节点必须属于当前公司且有效。现有 `AuthDataScopeService` 的路径展开逻辑继续作为运行时唯一实现。

### Decision: 历史组织直接恢复可见，不做数据重建

现有 `OrgUnits` 记录按 `ParentId`、`Path`、`Depth`、`Sort` 重新组成树。新增节点使用：

- `Depth = parent.Depth + 1`
- 首次保存取得 ID 后，`Path = parent.Path + id + "/"`

本次不新增迁移。若历史记录存在非法父级或路径，应拒绝对异常节点执行破坏性操作并由测试和运行诊断暴露，不自动重写历史数据。

## Risks / Trade-offs

- 恢复历史下级节点后，管理员可能看到此前被隐藏的数据。
  - Mitigation: 仅查询当前公司，保留原 ID 和引用，不自动修改。
- 组织停用可能影响用户登录和数据范围。
  - Mitigation: 有有效用户或有效下级节点时拒绝停用，要求先迁移归属。
- 自定义多节点角色范围增加配置复杂度。
  - Mitigation: 用户归属仍为单选；仅角色范围在明确选择 `CustomNodes` 时启用多选。
- 当前工作区已有其他未提交修改。
  - Mitigation: 本变更只按准确文件暂存和验证，不覆盖或混入既有修改。

## Migration Plan

1. 先恢复 API、应用服务和权限种子，并通过 SQLite 集成测试。
2. 恢复用户任意有效节点归属和角色层级范围校验。
3. 恢复前端树形 CRUD 与角色范围选择。
4. 在本地 MySQL 上验证历史根组织及下级组织读取，不执行删除性迁移。
5. 重新启动当前项目并进行组织新增、用户分配、范围查询和安全删除冒烟验证。

## Rollback

代码可回退到单根组织契约；本次不修改数据库结构，也不自动创建历史之外的数据。若管理员在功能上线后新增下级节点，回退后这些节点会重新被隐藏但不会被删除。
