## ADDED Requirements
### Requirement: 匹配知识配置采用分组式维护界面
系统 SHALL 在匹配知识配置页使用面向业务语义的分组式维护模型，而不是直接暴露运行时内部的别名字典与单对冲突词结构。

#### Scenario: 实体别名显示为实体组
- **GIVEN** 用户进入匹配知识配置页的实体分类
- **WHEN** 页面展示当前配置
- **THEN** 页面按“实体组”逐行展示多个同一实体的叫法
- **AND** 每组首项被视为标准实体
- **AND** 页面不再要求用户手工维护 `ABB -> ABB` 这类自映射

#### Scenario: 单位别名显示为单位组
- **GIVEN** 用户进入匹配知识配置页的单位分类
- **WHEN** 页面展示单位别名配置
- **THEN** 页面按“单位组”逐行展示多个同一标准单位的写法
- **AND** 每组首项被视为标准单位
- **AND** 单位换算区域仍单独展示，不并入单位组输入

#### Scenario: 字段别名显示为字段组
- **GIVEN** 用户进入匹配知识配置页的字段分类
- **WHEN** 页面展示字段配置
- **THEN** 页面按“字段组”逐行展示多个同一标准字段的写法
- **AND** 每组首项被视为标准字段
- **AND** 页面不再要求用户手工维护 `功率 -> 功率` 这类自映射

#### Scenario: 冲突词显示为左右冲突组
- **GIVEN** 用户进入匹配知识配置页的冲突分类
- **WHEN** 页面展示冲突配置
- **THEN** 每行显示“左冲突组”和“右冲突组”两个输入区域
- **AND** 左右两组内部表示同义词集合
- **AND** 左组与右组之间表示冲突关系

#### Scenario: 分组输入提示统一
- **WHEN** 用户在匹配知识配置页新增或编辑任一分组
- **THEN** 页面提示用户可使用 `、`、`，` 或 `,` 分隔组内词项
- **AND** 对实体组、单位组、字段组提示“首项作为标准值”

#### Scenario: 页面回显不暴露内部展开细节
- **GIVEN** 当前数据库中已保存展开后的别名字典与冲突词对
- **WHEN** 页面加载并展示分组视图
- **THEN** 用户看到的是聚合后的实体组、单位组、字段组和左右冲突组
- **AND** 页面不直接显示运行时内部展开后的逐条映射
