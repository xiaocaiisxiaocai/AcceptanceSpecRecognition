## Context
当前智能填充已经支持单文件或单次多表格执行，但其结果快照只够回放到原始文件本身。用户新的诉求不是“把已填文档当模板保存下来”，而是“刚填完一份后，立刻将本次已确认的填充结果复用到另外多份完全相同的文件”。这一能力对“严格一致性校验”要求高，对 AI 和匹配链路要求低。

## Goals / Non-Goals
- Goals:
  - 支持基于当前填充结果发起一次性严格复用。
  - 复用前提供可解释的逐文件预检结果。
  - 复用执行时不调用 AI、不重新匹配。
  - 多目标文件执行后提供统一下载结果。
- Non-Goals:
  - 不提供长期模板保存、模板管理页面或历史模板列表。
  - 不支持宽松模式、模糊匹配、行顺序自动纠偏。
  - 不支持跨文件类型复用（Word 到 Excel 或 Excel 到 Word）。

## Decisions
- Decision: 复用来源绑定到“当前刚完成的填充任务”，而不是反解析已下载文档。
  - Why: 已填文档可能经过浏览器下载重命名、外部编辑或格式变化，直接反解析稳定性差；而填充任务本身已经持有最终采用的写回值和行位置。

- Decision: 严格模式以“表格配置 + 整个数据区行签名”做完整校验。
  - Why: 仅校验已填充行不足以发现行偏移或中间插入/删除，必须校验整个数据区的项目+规格顺序才能保证安全回放。

- Decision: 执行复用时直接采用来源任务快照中的 `Acceptance` / `Remark` 写回值。
  - Why: 用户要的是复用“已确认结果”，而不是复用一次查询；直接写入最终值可以彻底去掉 AI 和数据库实时重新匹配依赖。

- Decision: 复用会话为短期临时对象，生命周期与填充任务快照一致或更短。
  - Why: 用户明确不要长期模板，系统也无需增加模板管理复杂度。

- Decision: 多文件结果统一打包下载。
  - Why: 严格模式典型场景就是一次性处理多份同模板文档，逐个下载体验差，打包更符合批量操作预期。

## Risks / Trade-offs
- 风险: 严格模式会拒绝“看起来差不多但并非完全一致”的文件，可能让部分用户觉得过严。
  - Mitigation: 在预检结果中明确列出失败原因，例如表格数不一致、数据区行数不一致、某行项目/规格不一致。

- 风险: Word 和 Excel 的批量产物组织方式不同，统一下载链路会增加实现复杂度。
  - Mitigation: 统一以“批量结果包”抽象处理，单文件时可直接返回文件，多文件时返回压缩包。

- 风险: 如果来源填充任务缺少复用所需的表格配置或行签名信息，后续无法安全复用。
  - Mitigation: 在第一次执行填充成功时同步保存严格复用所需的最小快照，不依赖后续再推导。

## Migration Plan
1. 扩展填充任务快照，使其能承载严格复用所需的表格配置、行签名和写回值。
2. 增加严格模式复用预检与执行 API。
3. 在智能填充完成区域增加一次性复用入口和多文件批量流程。
4. 增加测试、校验下载链路并补充错误提示文案。
