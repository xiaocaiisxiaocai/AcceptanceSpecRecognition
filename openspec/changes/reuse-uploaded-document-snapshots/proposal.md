# Change: 复用已上传文档解析快照

## Why
固定 Excel 样本的导入链路中，首次元数据解析约 2370ms，智能结构识别约 5498ms（其中 AI 约 2512ms、非 AI 约 2986ms），预览和导入还会分别产生额外文档读取。同一 `FileId` 在元数据、识别、预览和导入请求之间被重复打开和解析，是当前模型已驻留后仍然等待较久的主要可消除成本。

## What Changes
- 为已上传且内容未变化的 Word/Excel 文档提供跨请求、短生命周期的完整表格快照复用。
- 使用 `FileId + FileHash + FileType` 标识内容版本；文件内容变化、缓存过期或未命中时重新解析。
- 合并同一内容版本的并发解析，且仅缓存成功完成的结果；失败和取消结果不得进入缓存。
- 使用独立、有容量上限的缓存，并跳过超过单条目预算的快照，避免影响全局内存缓存和文档解析资源门禁。
- 每次读取缓存前继续执行现有文件数据范围和客户权限校验；删除或无权文件不得因缓存命中而可见。
- 通过只读缓存值和调用方隔离的投影结果，保持表格元数据、结构化单元格、合并单元格和坐标语义一致。
- 不修改 Prompt、AI 调用策略、列映射规则、匹配排序、置信度、自动采用条件、HTTP 响应字段或导入业务判断。

## Impact
- Affected specs: `api`
- Affected code: 上传文档快照访问端口、API 文档解析适配器、智能结构识别、表格元数据/预览/导入读取、文件变更后的缓存失效、定向测试与诊断日志
- Compatibility: 不变更数据库结构和 HTTP 契约；缓存未命中或禁用时保持现有解析路径
- Related change: `optimize-excel-recognition-pipeline` 已完成单请求快照复用，本变更补充其明确排除的跨请求复用
