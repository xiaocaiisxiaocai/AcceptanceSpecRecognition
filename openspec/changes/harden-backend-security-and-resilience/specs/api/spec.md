## MODIFIED Requirements

### Requirement: 单角色模型下保留管理员边界保护

系统 MUST 在单角色模型下原子阻止最后一个当前有效或未来连续覆盖所需的 `admin` 用户被降级、停用、删除或设置为无效角色区间。

#### Scenario: 尝试移除最后一个当前有效 admin

- **WHEN** 管理员更新、停用或删除系统中最后一个当前有效的 `admin` 用户
- **THEN** 系统拒绝请求并返回明确错误

#### Scenario: 使用角色有效期绕过保护

- **WHEN** 管理员把最后一个有效 `admin` 的角色开始时间设置为未来，或把结束时间设置为当前之前
- **THEN** 系统拒绝请求
- **AND** 提交后当前时刻仍至少存在一个有效管理员

#### Scenario: 管理员角色区间形成未来空档

- **WHEN** 管理员变更会使已知角色时间边界之间出现没有有效 `admin` 的时间段
- **THEN** 系统拒绝请求并指出管理员覆盖区间不连续

#### Scenario: 并发移除多个管理员

- **GIVEN** 当前存在两个有效管理员
- **WHEN** 两个请求并发尝试分别降级、停用或删除这两个管理员
- **THEN** 系统在公司级原子边界内串行校验并提交
- **AND** 至多一个请求成功
- **AND** 最终仍至少存在一个有效管理员

## ADDED Requirements

### Requirement: 批量匹配预览进度按公司和用户隔离

系统 MUST 将匹配预览进度绑定到发起请求的公司和用户，不能仅凭客户端请求标识读写全局进度。

#### Scenario: 所属用户查询进度

- **WHEN** 发起预览的用户使用原请求标识查询进度
- **THEN** 系统返回该用户在当前公司下的进度快照

#### Scenario: 其他 owner 查询相同标识

- **WHEN** 其他用户或其他公司的用户查询相同请求标识
- **THEN** 系统返回 404
- **AND** 不泄露该标识是否由其他 owner 使用

#### Scenario: 重复启动运行中标识

- **WHEN** 同一用户使用仍在运行的请求标识再次启动预览
- **THEN** 系统拒绝覆盖原进度并返回冲突错误

#### Scenario: 预览失败信息脱敏

- **WHEN** 预览因数据库、文件或外部 AI 异常失败
- **THEN** 进度接口仅返回安全的用户可读错误
- **AND** 不返回原始异常、内部路径、连接信息或外部响应正文

### Requirement: 系统用户新密码执行统一安全长度

系统 MUST 对创建用户和重置密码使用同一服务端密码策略，新密码长度为 12 至 200 字符，同时保持已有账号登录兼容。

#### Scenario: 提交过短新密码

- **WHEN** 管理员创建用户或重置密码时提交少于 12 字符的新密码
- **THEN** 系统返回参数错误且不写入新密码哈希

#### Scenario: 已有短密码账号登录

- **GIVEN** 历史账号的现有密码少于 12 字符
- **WHEN** 用户使用正确旧密码登录
- **THEN** 系统仍按现有认证规则处理登录
- **AND** 不因本次新写入策略直接锁死历史账号
