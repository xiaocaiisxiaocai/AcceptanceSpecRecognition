## MODIFIED Requirements

### Requirement: 批量回复临时文件存储

系统 SHALL 为批量回复流程以有界、可取消的流式方式保存来源文档、目标文档和执行结果所需的临时文件，并在会话结束、过期、失败或取消后清理对应文件。

#### Scenario: 保存批量回复临时上传文件

- **WHEN** 用户在批量回复页面上传来源文档和目标文档
- **THEN** 系统将这些文件保存到服务器临时存储位置
- **AND** 这些文件不作为正式导入文档写入长期业务主流程

#### Scenario: 整批上传预算

- **WHEN** 上传文件数量、单文件大小或整批总字节超过配置预算
- **THEN** 系统在读取完整文件内容前拒绝请求
- **AND** API、代理和 Application 使用一致的可解释限制

#### Scenario: 顺序流式落盘

- **WHEN** 系统接收多个批量回复目标文件
- **THEN** 系统以顺序或明确的小并发预算逐文件流式落盘和校验
- **AND** 不同时把整批文件复制为托管内存中的 `byte[]`

#### Scenario: 上传失败或取消补偿

- **WHEN** 任一文件保存、解析失败或请求被取消
- **THEN** 系统删除本次尚未提交会话的临时文件
- **AND** 不发布部分更新的 manifest

#### Scenario: 清理过期临时文件

- **WHEN** 批量回复会话执行完成或会话超过保留时间
- **THEN** 系统清理对应的临时来源文件、临时目标文件和中间产物
- **AND** 不影响最终可下载结果文件的生命周期
