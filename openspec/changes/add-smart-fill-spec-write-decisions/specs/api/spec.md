## ADDED Requirements

### Requirement: 智能填充验收规格回填 API 支持显式写入决策

系统 SHALL 在智能填充验收规格回填请求中支持显式的覆盖、新增和跳过决策，并在写入前完成完整校验。

#### Scenario: 完整覆盖匹配规格
- **GIVEN** 请求项选择覆盖并提供可访问的匹配规格 ID
- **WHEN** 系统处理回填请求
- **THEN** 系统使用当前行的项目、规格、验收标准和备注完整更新该规格
- **AND** 使该规格已有的 Embedding 缓存失效

#### Scenario: 保留匹配规格并新增
- **GIVEN** 请求项选择新增并提供当前行四个业务字段
- **WHEN** 系统处理回填请求
- **THEN** 系统保留匹配到的原规格不变
- **AND** 在当前客户、机型、制程和业务组织归属下新增一条验收规格

#### Scenario: 跳过不写库
- **GIVEN** 请求项选择跳过
- **WHEN** 系统处理回填请求
- **THEN** 系统不更新或新增任何验收规格

#### Scenario: 混合批次先校验后写入
- **GIVEN** 同一请求包含覆盖、新增和跳过决策
- **WHEN** 任一非跳过项不存在、越权或缺少必填字段
- **THEN** 系统拒绝整个回填请求
- **AND** 不提交部分写入

#### Scenario: 旧请求保持兼容
- **GIVEN** 旧客户端未发送显式写入决策
- **WHEN** 系统处理回填请求
- **THEN** 系统继续按照现有 `SpecId` 与编辑字段规则执行更新或新增
