## Context

结构模板由智能配置确认流程自动生成，主记录保存在 `DocumentTemplates`，一个模板可关联多个 `DocumentTemplateRegions`。现有应用服务只面向识别流程提供查找、保存和计数能力，API 仅提供识别与确认端点。

## Goals / Non-Goals

- Goals:
  - 让管理员能够查找、查看和删除客户级结构模板。
  - 使用 A1 坐标呈现多区域结构，与导入确认页保持一致。
  - 明确区分“结构模板”和“表格路由规则”。
- Non-Goals:
  - 不允许在管理页直接编辑区域坐标；坐标修正仍通过实际文件的“调整范围 → 确认并学习”完成。
  - 不新增模板启停状态或数据库迁移。
  - 不改变表格路由规则的匹配和推荐逻辑。

## Decisions

- Decision: 新增独立的只读查询 DTO，不直接向前端暴露 EF 实体或 JSON 字段。
- Decision: 列表接口采用分页，并支持客户与关键字筛选；详情接口返回有序区域。
- Decision: A1 坐标由前端基于零起始列索引和行索引统一转换，接口保留内部数值语义，避免持久化重复展示字段。
- Decision: 管理页只提供查看与删除。需要修正的模板应在上传真实文件后调整范围并重新确认，以保证表头和合并单元格解析参与反推。
- Decision: `Template` 仅在展示层翻译为“历史模板”，保持现有 API 与后端候选来源枚举兼容。

## Risks / Trade-offs

- 删除模板会降低同结构文件的后续识别速度或置信度；通过危险操作确认框展示客户、模板名和区域数降低误删风险。
- 旧模板可能只有主记录而没有区域；详情接口兼容旧字段并合成为一个展示区域。
- 模板名称通常来自工作表名，可能重复；列表同时展示客户、模板 ID、更新时间和区域数用于区分。

## Migration Plan

无需数据库迁移。发布后读取现有模板数据；删除操作依赖现有级联关系删除区域。
