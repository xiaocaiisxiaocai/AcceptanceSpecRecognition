## Context

现有组织模型通过 `ParentId` 表达直接父级，通过物化路径 `Path` 和 `Depth` 支持树查询与组织子树数据范围。用户、角色范围、验收规格和历史文件都引用稳定的组织节点 ID。普通编辑接口刻意不接收父级，以避免一次常规字段修改隐式改变整棵子树。

新增事业部后把已有部门移入事业部，必须保持节点 ID 和业务引用不变，同时原子更新该部门及全部后代的路径；否则运行中的数据范围可能读取到部分新、部分旧的层级状态。

## Goals / Non-Goals

- Goals:
  - 允许管理员在同一公司内移动非根组织节点及其完整子树。
  - 保证父级、路径和深度在一次事务中同时生效。
  - 保持用户归属、角色范围节点引用和业务数据归属 ID 不变。
  - 防止循环层级、跨公司移动和类型倒挂。
  - 让权限范围变化在操作前对管理员可见，并留下审计记录。
- Non-Goals:
  - 不支持公司根节点移动、跨公司移动或修改组织类型。
  - 不提供拖拽排序或批量移动多个不相邻节点。
  - 不自动改写用户、角色或业务数据的组织 ID。
  - 不新增数据库结构或数据迁移。

## Decisions

### Decision: 使用独立移动端点，不扩展普通编辑请求

新增 `PUT /api/org-units/{id}/move`，请求只包含 `newParentId`。接口使用独立 `move` 权限和审计动作；普通编辑继续只维护编码、名称、排序和状态。

Alternatives considered:

- 在现有更新请求中增加 `parentId`：会让普通编辑隐式触发整棵子树重写，也无法单独授权和审计高影响操作。
- 前端删除后重建：会改变组织 ID 并破坏用户、角色和业务数据外键引用。

### Decision: 移动整棵子树并原子重写物化路径

服务在事务内重新读取源节点、目标父级和源节点全部后代。设旧路径为 `oldPath`，新路径为 `newParent.Path + source.Id + "/"`：

- 源节点更新 `ParentId = newParentId`、`Path = newPath`。
- 后代保留相对路径后缀，将 `oldPath` 前缀替换为 `newPath`。
- 所有受影响节点的 `Depth` 加上统一深度差，并更新 `UpdatedAt`。
- 若新上级等于当前上级，则作为幂等成功返回当前节点，不产生层级变化。

事务提交前任何校验或写入失败都整体回滚，不允许保存部分路径。移动不修改节点 ID，因此用户归属、角色范围节点、验收规格和文件归属引用无需迁移。

### Decision: 目标上级同时满足公司、状态、循环和类型约束

服务端始终执行以下校验，前端过滤只用于改善体验：

- 源节点和目标上级都属于当前登录公司的组织树。
- 源节点不是公司根节点，目标上级处于启用状态。
- 目标上级不是源节点自身，也不在源节点的 `Path` 子树内。
- `source.UnitType > newParent.UnitType`，继续允许向下跳级；课别不能成为任何节点的新上级。

移动节点内部的子树关系和组织类型不变，只校验移动根与新上级之间的新边。

### Decision: 保留引用，但明确子树权限会即时变化

角色的 `OrgNode` 和 `CustomNodes` 引用稳定节点 ID，移动后仍指向同一节点。`OrgSubtree` 以及以祖先路径计算的业务可见范围会根据新 `Path` 立即重新计算：旧祖先不再包含该子树，新祖先开始包含该子树。这是移动的预期业务语义。

移动更新所有受影响节点的 `UpdatedAt`，使现有组织范围缓存的时间戳失效。界面在确认前显示源组织、目标上级和受影响节点数量，并提示组织子树数据范围将随层级变化。

### Decision: 采用明确弹窗而不是拖拽树

组织表格增加“移动”操作。弹窗使用树形单选展示合法的新上级，禁用自身、后代、停用节点、类型不合法节点和当前上级；底部使用明确确认按钮。该交互降低误拖动风险，也适合当前 Element Plus 管理后台的操作习惯。

## Risks / Trade-offs

- 移动较大子树需要批量更新多行。
  - Mitigation: 只加载源路径下的节点并一次事务保存；当前组织规模较小，不引入后台任务。
- 组织子树角色范围会改变可见数据集合。
  - Mitigation: 操作前提示影响，服务端记录移动审计；稳定节点引用和业务归属 ID 不变。
- 两个管理员并发移动相关节点可能造成陈旧校验。
  - Mitigation: 移动在事务中重新读取并校验源节点、目标节点和子树；测试覆盖循环与失败回滚。
- 历史非法路径可能导致无法安全计算后缀。
  - Mitigation: 检测源节点路径格式及后代前缀一致性，异常时拒绝移动并保持原数据。

## Migration Plan

1. 不执行数据库迁移，部署新 API 和权限种子。
2. 应用启动后为管理员角色同步新增移动权限；其他角色由管理员显式授权。
3. 前端发布后显示“移动”入口。
4. 使用测试组织树执行可恢复移动，核对 `ParentId`、`Path`、`Depth`、用户归属和业务归属 ID。

## Rollback

源码回退会移除移动入口和 API，不改变已经完成移动的合法组织层级。若需要撤销某次移动，应在新版本中再次选择原上级执行反向移动，而不是直接修改数据库。

## Open Questions

- 无。当前需求按“同公司内移动完整子树、保留所有稳定引用”实现。
