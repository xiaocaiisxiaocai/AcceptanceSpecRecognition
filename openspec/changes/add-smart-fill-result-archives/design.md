## Context
系统已有两类相关数据，但生命周期不同：

- `ExecutionHistoryRecord` 与智能填充回放用于长期查询，当前默认保留 365 天。
- `MatchingFillTask` 的下载产物用于执行后立即下载与恢复，当前仅保留 24 小时。

现有 `uploads/execution-history/smart-fill` 保存的是超大回放 JSON 归档，不是用户可下载的最终 Word/Excel 文件。因此本变更需要为最终结果文件建立独立、明确的长期所有权。

## Goals / Non-Goals
- Goals: 每次成功填充保留一份最终结果文件；可从“其他”菜单查询、查看摘要和下载；普通用户查看本部门记录，管理员查看当前公司全部部门记录；Word 与 Excel 行为一致；失败和重试不重复归档。
- Non-Goals: 不补算旧记录的结果文件；不扩大到数据导入或批量回复；不改变智能填充匹配、回填验收规格库或源文件写回规则；不允许跨公司访问。

## Decisions
- Decision: 新增独立的结果存档命名空间 `uploads/execution-history/smart-fill-results/{date}/`，不与 24 小时任务下载产物共用物理文件。
  - Reason: 任务快照清理会主动删除其下载产物，共用路径会造成历史记录指向已删除文件。独立副本使所有权和清理边界清晰。
  - Alternative considered: 直接复用 `MatchingFillTask.DownloadArtifactRelativePath`。该路径只有 24 小时生命周期，且清理服务不了解执行历史引用，不能满足长期存档。
- Decision: 在 `ExecutionHistoryRecord` 上保存结果存档的相对路径、原始下载文件名、内容类型、文件大小和 SHA-256，而不是把路径藏在回放 JSON 中。
  - Reason: 列表查询、完整性检查、下载响应和清理都需要稳定的结构化元数据；同时 API 不向前端暴露服务器路径。
- Decision: 结果文件写入和执行记录数据库写入属于同一次最终提交编排。数据库提交失败时立即清理本次新建文件；进程中断留下的无引用文件由孤儿文件巡检回收。
- Decision: 以任务标识作为幂等关联键。一条成功智能填充执行记录最多关联一份结果存档，重复请求返回既有结果，不创建第二份文件。
- Decision: 新增“其他 > 填充存档”专用页面，只展示智能填充存档；现有“执行记录”页面继续承担智能填充回放和批量回复历史，不复制复杂回放界面。
- Decision: 存档页面使用紧凑表格，主要字段为来源文件、所属部门、操作人、文件类型、执行时间、填充/跳过数量、存档状态和操作。详情在当前页面内展示摘要，不使用抽屉。
- Decision: 访问范围以执行时保存的 `OwnerOrgUnitId` 归属快照裁决。普通用户只能访问本部门记录；管理员可以访问当前公司全部部门并按部门、操作人筛选。管理员身份必须由后端现有角色/权限上下文裁决，前端筛选条件不能扩大权限。
- Decision: 旧记录没有部门归属快照时，普通用户只允许访问本人创建的记录；管理员仍可在当前公司范围访问，避免空归属意外扩大普通用户权限。

## Data And API
- 数据库迁移为执行历史增加可空存档元数据字段，确保旧记录兼容。
- 列表 API 支持 `smart-fill` 类型、来源文件关键词、开始时间、结束时间、部门和操作人筛选，并返回 `hasResultArchive`、所属部门、创建人等结构化字段。
- 新增按执行记录 ID 下载结果存档的只读接口；服务端先校验记录归属、任务类型、允许的存储命名空间和文件存在性，再以归档文件名返回流。
- 下载接口不接受客户端文件路径，不返回内部相对路径；普通用户只能下载本部门记录，管理员可以下载当前公司全部部门的记录，任何角色都不能跨公司访问。

## Failure And Lifecycle
- 文件写入失败：整次填充最终提交失败，不产生成功执行记录。
- 数据库提交失败：删除本次新建的结果存档；若进程在清理前退出，由孤儿巡检发现无引用文件。
- 文件被外部删除或损坏：列表仍保留执行记录并显示存档异常；下载返回明确错误，不重新执行填充。
- 执行历史按 365 天保留策略删除后，结果存档失去引用，由孤儿文件巡检回收。
- 历史旧记录的存档字段为空，页面显示“无结果文件”，但原有回放详情继续可用。

## Risks / Trade-offs
- 磁盘占用增加：每次成功填充额外保存一份文件。通过 365 天历史保留策略、数量上限和孤儿巡检控制增长。
- 文件系统与数据库无法原子提交：通过失败补偿、幂等任务键、命名空间校验和孤儿巡检降低不一致风险。
- 新页面与执行记录内容有部分重叠：新页面只解决“按份找文件并下载”，复杂逐行回放仍留在现有执行记录页。

## Migration Plan
1. 增加可空的执行历史结果存档元数据字段，不回填旧数据。
2. 部署 API 后，新成功任务开始产生结果存档；旧客户端仍可使用原下载接口。
3. 部署前端导航和页面后，用户可从“其他 > 填充存档”查询新存档。
4. 回退应用版本时保留新增字段和存档文件；旧版本会忽略它们，不删除用户文件。
