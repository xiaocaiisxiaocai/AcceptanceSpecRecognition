## ADDED Requirements
### Requirement: 智能填充结果存档查询 API
系统 SHALL 提供智能填充结果存档的分页查询能力，并按普通用户本部门范围或管理员当前公司范围返回有权访问的执行记录和结构化存档摘要。

#### Scenario: 查询每次智能填充存档
- **WHEN** 用户请求智能填充结果存档列表
- **THEN** 系统按执行时间倒序返回一次成功任务一条记录
- **AND** 每条记录包含来源文件、文件类型、执行时间、填充摘要和存档可用状态

#### Scenario: 按文件名和时间查询
- **WHEN** 用户提交来源文件关键词、开始时间或结束时间筛选
- **THEN** 系统只返回符合条件且用户有权访问的智能填充记录
- **AND** 时间筛选遵循系统既有 UTC 接口契约

#### Scenario: 普通用户只能查询本部门存档
- **GIVEN** 当前用户不是管理员
- **WHEN** 用户查询智能填充结果存档
- **THEN** 系统只返回执行时归属于当前用户所在部门的记录
- **AND** 忽略或拒绝任何试图扩大到其他部门的筛选条件

#### Scenario: 普通用户查询空部门归属旧记录
- **GIVEN** 某条旧记录没有部门归属快照
- **AND** 当前用户不是管理员
- **WHEN** 用户查询智能填充结果存档
- **THEN** 仅当该记录由当前用户本人创建时才允许返回
- **AND** 不把空部门归属解释为当前公司公开记录

#### Scenario: 管理员查询当前公司存档
- **GIVEN** 当前用户是管理员
- **WHEN** 管理员查询智能填充结果存档或按部门、操作人筛选
- **THEN** 系统返回当前公司内符合条件的记录
- **AND** 每条记录包含可展示的所属部门和操作人信息

#### Scenario: 拒绝跨公司查询
- **WHEN** 任意用户尝试查询其他公司的存档
- **THEN** 系统不返回该记录及其存档元数据
- **AND** 不泄露服务器文件路径

### Requirement: 智能填充结果存档下载 API
系统 SHALL 允许用户按执行记录标识下载当时归档的最终结果文件，并在打开文件前验证记录归属和存储路径。

#### Scenario: 下载 Word 或 Excel 存档
- **GIVEN** 用户有权访问的智能填充记录存在有效结果存档
- **WHEN** 用户请求下载该记录的结果文件
- **THEN** 系统以保存的文件名和正确内容类型返回文件流
- **AND** 返回内容与记录的文件大小及 SHA-256 元数据一致

#### Scenario: 普通用户下载本部门存档
- **GIVEN** 目标记录归属于当前用户所在部门
- **AND** 当前用户不是管理员
- **WHEN** 用户请求下载该记录的结果文件
- **THEN** 系统允许下载
- **AND** 拒绝下载其他部门的记录

#### Scenario: 管理员下载当前公司存档
- **GIVEN** 目标记录归属于当前公司内的其他部门
- **AND** 当前用户是管理员
- **WHEN** 管理员请求下载该记录的结果文件
- **THEN** 系统允许下载
- **AND** 仍拒绝访问其他公司的记录

#### Scenario: 历史记录没有结果存档
- **GIVEN** 目标记录是功能上线前产生的旧记录
- **WHEN** 用户请求下载结果存档
- **THEN** 系统返回明确的存档不可用结果
- **AND** 不重新执行填充来生成文件

#### Scenario: 拒绝非法存档路径
- **GIVEN** 记录中的存档路径为空、越界或不属于智能填充结果存档命名空间
- **WHEN** 用户请求下载
- **THEN** 系统拒绝读取文件
- **AND** 不向客户端返回内部绝对路径
