## ADDED Requirements
### Requirement: 其他菜单提供填充存档入口
系统 SHALL 在“其他”菜单下提供独立的“填充存档”入口，用于查询和下载每次智能填充保存的最终结果文件。

#### Scenario: 打开填充存档页面
- **WHEN** 有页面权限的用户点击“其他 > 填充存档”
- **THEN** 系统在主内容区打开填充存档页面
- **AND** 页面不使用抽屉承载主流程

#### Scenario: 无权限时隐藏入口
- **WHEN** 用户缺少填充存档页面权限
- **THEN** 导航中不显示该入口
- **AND** 后端仍独立执行资源归属校验

### Requirement: 填充存档页面简洁查询每份结果
系统 SHALL 以紧凑、可扫描的列表展示每次智能填充结果存档，并允许普通用户查询本部门记录、管理员查询当前公司全部部门记录，在当前页面查看摘要和下载文件。

#### Scenario: 查看存档列表
- **WHEN** 用户进入填充存档页面
- **THEN** 页面按执行时间倒序展示来源文件、所属部门、操作人、文件类型、执行时间、填充数、跳过数、存档状态和操作
- **AND** 一次成功执行只显示一条记录

#### Scenario: 查询存档
- **WHEN** 用户按来源文件名或执行时间范围筛选
- **THEN** 页面展示匹配的存档记录和总数
- **AND** 无结果时显示明确空状态

#### Scenario: 管理员按部门和操作人查询
- **GIVEN** 当前用户是管理员
- **WHEN** 管理员选择当前公司内的部门或操作人
- **THEN** 页面只展示符合条件的存档记录
- **AND** 部门和操作人筛选不会出现其他公司的数据

#### Scenario: 普通用户查看本部门记录
- **GIVEN** 当前用户不是管理员
- **WHEN** 用户进入填充存档页面
- **THEN** 页面只展示本部门存档
- **AND** 不显示用于切换到其他部门的筛选

#### Scenario: 在当前页面查看摘要
- **WHEN** 用户选择一条存档记录
- **THEN** 页面在当前主内容区展示该次执行的关键摘要
- **AND** 不要求跳转到其他业务页面或打开抽屉

#### Scenario: 下载可用存档
- **GIVEN** 记录存在有效结果存档
- **WHEN** 用户点击下载
- **THEN** 浏览器下载当时归档的 Word 或 Excel 文件
- **AND** 页面保持当前筛选和分页状态

#### Scenario: 展示旧记录或异常存档
- **WHEN** 记录没有结果存档或服务器文件已不可用
- **THEN** 页面以文字和状态图标明确说明不可下载原因
- **AND** 不显示可执行的下载按钮
