## Context
当前识别请求先调用 `GetTablesAsync`，再调用 `ExtractAllTablesDataAsync`，导致同一文档至少解码两次；复杂表头会继续按表重新解码。前端随后按工作表串行请求预览。关闭 LLM 只能移除模型等待，不能消除这些本地解析成本。

## Goals / Non-Goals
- Goals: 单次智能结构识别只解码一次源文档，并保持现有识别输出语义。
- Goals: 降低多工作表预览的串行等待，同时限制并发资源占用。
- Goals: 保持文件切换、取消、失败提示和结果归属安全。
- Non-Goals: 引入跨请求或持久化文档缓存。
- Non-Goals: 修改识别算法、AI 调用策略或导入业务规则。

## Decisions

### 1. 使用请求级文档快照
解析器新增一次性返回 `TableInfo` 与 `TableData` 的快照操作。Word 与 Excel 均在一个底层文档对象生命周期中提取两类结果，应用服务不再组合两个独立解析调用。

### 2. 复杂表头从完整数据投影
识别所需的表头重定位只改变表头与数据起始位置。系统从已展开合并单元格的完整 `TableData` 生成新视图，不再次读取源文件。

### 3. 预览使用固定并发上限
前端按最多 2 个并发任务加载待预览工作表。每个结果仍在写回前校验文件标识和配置对象是否有效；任一失败沿用现有整体失败提示。

### 4. 规则规范化使用请求级会话缓存
区域扫描需要让大量单元格与列头规则比较。匹配语义保持不变，但同一请求内相同表头文本和规则模式只执行一次简繁与空白规范化；缓存仅存在于当前识别操作，不跨请求保留客户文本。

## Risks / Trade-offs
- 快照会在单次请求内同时持有表信息与完整表数据；这与当前完整识别已经持有全部 `TableData` 的内存级别一致。
- 受控并发会增加瞬时文件读取量；固定上限 2 避免按工作表数量无限放大。
- 表头投影必须保持原始行坐标和合并单元格坐标；通过多行表头和行计数回归测试保护。
- 请求级规范化缓存有固定容量，避免大文件导致无界增长；超出容量时仍返回与原规则匹配相同的结果。

## Migration Plan
无需数据库或配置迁移。回退时恢复独立解析调用和串行预览即可。
