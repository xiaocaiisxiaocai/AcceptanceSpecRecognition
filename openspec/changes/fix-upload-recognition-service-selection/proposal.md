# Change: 修复文件上传状态与智能结构识别服务选择

## Why
当前文件上传接口会在文件已经保存成功后返回 `tableCountReady=false`，页面把该状态持续显示为“正在读取工作表结构”，即使后台的表结构请求已经完成也不会同步回上传卡片，造成上传偶发卡住的错觉。数据导入页面还会在隐藏步骤中提前发起表结构读取，用户可同时点击智能识别，形成重复解析和状态竞争。

智能结构识别请求目前没有携带用户是否启用 AI 增强或系统采用了哪个 LLM。后端把缺失的服务标识解释为遍历所有已启用 LLM，因此用户未配置服务选择时仍可能等待不可用服务超时，并且多表文件会重复等待同一故障服务。

## What Changes
- 将文件保存、表结构读取、读取失败拆分为独立可恢复状态；文件保存成功后不再继续显示为“正在上传”。
- 数据导入与智能填充统一显式加载表结构，复用同一个进行中的请求和结果，阻止表结构就绪前重复触发智能识别。
- 为文件上传和表结构读取设置符合大文件场景的独立超时，并提供明确的失败重试提示。
- 智能结构识别新增显式 AI 增强开关和 LLM 服务标识；页面存在可用 LLM 时默认开启并自动采用 AI 服务配置中优先级最高的已启用服务，不要求用户选择模型；没有可用 LLM 时提示前往配置，用户主动关闭时只执行规则、模板和确定性识别。
- 开启 AI 增强时只调用系统自动采用且已启用的一个 LLM，不再自动遍历其他服务。
- 同一次文档识别中，所选 LLM 首次出现认证、连接或超时失败后立即停止后续表格的 LLM 调用，继续返回规则识别结果和可解释问题。
- 对当前已启用 AI 服务执行完整连接测试，并将确认不可用的配置标记为禁用；Embedding 与 LLM 按各自用途独立判断。

## Impact
- Affected specs: `api`, `matching-engine`, `user-interface`
- Affected code: 文件上传与表选择状态、智能结构识别请求契约、LLM 辅助识别选择与失败处理、AI 服务配置状态
- Compatibility: 识别 API 仅新增可选字段；页面显式提交自动采用的可用服务，旧客户端未传字段时仍采用更安全的纯规则识别，不再隐式调用全部 LLM
- Related changes: 与 `add-multi-region-smart-recognition` 的区域识别结果兼容，不改变区域契约、确认和学习语义
