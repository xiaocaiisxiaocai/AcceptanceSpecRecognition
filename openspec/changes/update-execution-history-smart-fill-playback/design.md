## Context
现有执行记录来自 `ExecutionHistoryRecord.DetailJson`，重点是“任务级汇总 + 文件/Sheet/行结果”，适合查有没有执行成功，但不适合复盘智能填充过程。智能填充真正的关键信息散落在预览页响应、LLM 复核状态、执行映射和覆盖值里，执行记录目前没有把这些内容整体固化下来。

用户已经明确：
- 智能填充执行记录需要尽可能还原智能填充页面。
- 标签允许并存，不互斥。
- 标签展示顺序固定为：`完全匹配 > AI匹配 > 人工确认 > 人工写入 > 未采用/未匹配`。
- 批量回复详情可以简化显示。
- 本次改造不得为了展示历史详情而新增 AI 调用或重新匹配。

## Goals / Non-Goals
- Goals:
  - 在智能填充执行记录中同时保留“预览时系统如何判断”和“执行时用户最终如何选择”。
  - 让执行记录详情在不重算的前提下尽可能复用智能填充现有展示结构。
  - 为前端提供稳定的展示标签和摘要统计，避免页面自己拼装复杂判断。
  - 保持批量回复详情轻量，不把两条业务线强行揉成同一套复杂模型。
- Non-Goals:
  - 不改造现有匹配与执行门禁逻辑。
  - 不为历史旧记录补算完整回放数据。
  - 不把执行记录拆成多张明细关系表。
  - 不引入新的 AI 调用、匹配调用或后台补算任务。

## Decisions
- Decision: 继续沿用 `ExecutionHistoryRecord` 作为任务入口，不新增新的主存储表。
  - Why: 当前列表筛选、权限边界、任务级汇总都已围绕该实体建立，继续扩展 `DetailJson` 的版本化结构成本最低。
  - Alternatives considered:
    - 新建“执行回放归档表”：结构更独立，但迁移与查询整合成本更高。
    - 直接复用 `MatchingFillTask`：现有快照偏下载与断点恢复，不保存完整预览回放信息。

- Decision: 智能填充详情改为“双快照”归档。
  - Why: 用户要同时看“系统原本怎么判”和“最后用户怎么定”，单一结果快照会丢信息。
  - Details:
    - `previewSnapshot` 保存执行前预览页看到的匹配结果、候选、AI 复核与选定方式。
    - `executionSnapshot` 保存执行时最终选择、人工确认、人工写入和最终写回值。

- Decision: 保存展示标签的原始判定字段，并额外保存排好序的 `displayTags`。
  - Why: 前端既需要可解释的原始字段，也需要稳定的最终展示顺序。
  - Details:
    - 原始字段至少包含 `matchOrigin`、`isManualConfirmed`、`isManualEdited`。
    - `displayTags` 由服务端按顺序生成：`完全匹配 > AI匹配 > 人工确认 > 人工写入 > 未采用/未匹配`。

- Decision: 查看执行记录详情时只读取已归档数据，不重跑任何匹配或 AI。
  - Why: 用户已明确禁止为新详情能力新增 AI/匹配调用；同时避免历史结果随运行时知识或配置变化而漂移。

- Decision: 历史旧记录走降级视图，而不是事后补算。
  - Why: 旧记录没有完整预览归档，强行补算会引入不一致和额外 AI/匹配调用。
  - Details:
    - 详情结构增加版本与能力标记。
    - 没有智能填充完整回放归档时，前端显示“历史记录，缺少预览归档”，并回退到现有简版详情。

- Decision: 批量回复保持简化详情。
  - Why: 批量回复没有智能填充那样的候选与 AI 预览链路，强行统一只会增加噪音。

## Risks / Trade-offs
- 智能填充执行记录详情 JSON 会显著增大。
  - Mitigation: 只在任务详情单条读取时加载；列表仍依赖结构化摘要字段。
- 执行链路需要拿到完整预览归档数据。
  - Mitigation: 直接复用执行前页面已有预览与选择结果，把它们作为执行记录归档源，不在服务端事后重建。
- 前端复用智能填充组件时，历史查看和实时预览的数据契约可能不同。
  - Mitigation: 增加执行记录专用适配层，复用展示组件和格式化函数，不复用实时数据流和交互状态。

## Migration Plan
1. 为执行记录详情定义新版本归档结构，并保留旧版兼容读取。
2. 扩展智能填充执行链路，在保存执行记录时同时固化预览归档与执行归档。
3. 扩展执行记录列表摘要字段与详情 DTO。
4. 重构执行记录页面骨架为任务下拉 + 摘要 + 详情回放。
5. 为历史旧记录提供降级展示与提示。
6. 补充后端和前端测试。
