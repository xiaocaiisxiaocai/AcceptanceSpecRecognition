## ADDED Requirements

### Requirement: 验收规格内容版本快照不可变持久化

系统 SHALL 使用现有内容版本号为每个可追溯版本保存不可变的完整正文快照，并保持当前实体、引用统计和版本快照一致。

#### Scenario: 新建规格保存初始版本
- **WHEN** 任一正式业务入口成功创建验收规格
- **THEN** 系统在同一业务提交中保存该规格当前版本的完整正文快照
- **AND** 初始快照包含变更来源、UTC 时间和可追溯操作者

#### Scenario: 实质内容变化生成新版本
- **GIVEN** 验收规格当前版本为 Vn
- **WHEN** 项目、规格内容、验收标准或备注发生归一化后的实质变化
- **THEN** 系统将当前版本递增为 Vn+1
- **AND** 清零当前版本引用次数
- **AND** 保存 Vn+1 的完整正文快照
- **AND** 实体更新和快照写入处于同一事务

#### Scenario: 等价内容不生成空版本
- **WHEN** 更新后的四个正文字段与当前正文在既有归一化规则下等价
- **THEN** 系统不递增版本
- **AND** 不清零引用次数
- **AND** 不新增内容快照

#### Scenario: 所有修改入口使用同一版本规则
- **WHEN** 内容变化来自手工编辑、Word/Excel 文档导入覆盖、智能填充回填或部门备注批量替换
- **THEN** 系统使用相同的不变量生成新版本快照
- **AND** 不允许任何入口只修改当前正文而缺少对应快照

#### Scenario: 历史快照不可改写
- **WHEN** 内容版本快照已经提交
- **THEN** 系统不提供修改、删除或重编号该快照的应用接口
- **AND** 后续恢复或再次编辑只能创建更高版本

#### Scenario: 并发修改只允许一个版本提交
- **GIVEN** 两个业务入口同时基于相同当前版本修改同一规格
- **WHEN** 第一个事务已经提交新版本
- **THEN** 第二个事务因内容版本并发冲突而整体失败
- **AND** 不产生重复版本、孤立快照或静默覆盖

### Requirement: 迁移前内容历史边界真实可辨

系统 MUST 为现有规格保存迁移时当前正文基线，并明确区分无法重建的更早版本正文。

#### Scenario: 迁移当前 V1 规格
- **GIVEN** 现有规格当前版本为 V1
- **WHEN** 内容版本迁移执行
- **THEN** 系统为 V1 保存当前正文迁移基线
- **AND** 不伪造操作者或更早正文

#### Scenario: 迁移当前高版本规格
- **GIVEN** 现有规格当前版本为 Vn 且 n 大于 1
- **WHEN** 内容版本迁移执行
- **THEN** 系统只为 Vn 保存当前正文迁移基线
- **AND** 将 V1 到 Vn-1 标识为正文不可追溯
- **AND** 不根据引用事件或当前正文复制缺失版本

#### Scenario: 迁移基线与当前版本一致
- **WHEN** 迁移完成
- **THEN** 每条现有规格恰有一个版本号等于当前版本的内容快照
- **AND** 相同规格和版本不存在重复快照

### Requirement: 恢复旧正文保留单调版本历史

系统 SHALL 将恢复操作实现为创建新版本，不得回退版本号或覆盖已有历史。

#### Scenario: 恢复可用旧版本
- **GIVEN** 当前版本为 V5 且用户选择可用的 V2 快照
- **WHEN** 恢复事务成功
- **THEN** 系统创建正文等于 V2 的 V6
- **AND** V6 记录恢复来源为 V2
- **AND** V6 保存可选恢复原因
- **AND** V2 到 V5 的快照保持不变
- **AND** 当前引用次数清零

#### Scenario: 恢复事务失败
- **WHEN** 恢复过程中的实体更新、快照写入、缓存失效或审计前置处理失败
- **THEN** 系统回滚恢复事务
- **AND** 不留下新版本快照或部分当前正文
