## ADDED Requirements

### Requirement: 验收规格内容版本提供受保护的查询与差异接口

系统 SHALL 在验收规格读取权限和数据范围内提供分页版本历史、版本详情和字段级差异查询。

#### Scenario: 分页查询版本历史
- **WHEN** 有权用户请求规格内容版本列表
- **THEN** 系统按最早或最新顺序稳定分页返回版本、来源、操作者、UTC 时间和变更字段摘要
- **AND** 每页数量限制为 1 到 100
- **AND** 响应包含当前版本、最早可用版本和是否存在不可追溯旧正文

#### Scenario: 查询单个版本正文
- **WHEN** 有权用户请求一个可用内容版本
- **THEN** 系统返回该版本的项目、规格内容、验收标准、备注和变更元数据
- **AND** 不返回其他组织或无权规格的数据

#### Scenario: 比较两个可用版本
- **WHEN** 有权用户请求比较两个可用版本
- **THEN** 系统对四个正文字段分别返回前值、后值和是否变化
- **AND** 响应以普通文本表示内容，不返回可执行 HTML

#### Scenario: 请求不可追溯旧正文
- **WHEN** 用户请求迁移前未保存的内容版本
- **THEN** 系统返回明确的不可用错误
- **AND** 不以当前正文替代缺失版本

#### Scenario: 无权查看版本历史
- **WHEN** 用户不具备目标规格的读取权限或数据范围
- **THEN** 系统拒绝版本列表、详情和差异请求
- **AND** 不泄露版本数量、正文或操作者信息

### Requirement: 验收规格更新使用内容版本并发保护

系统 SHALL 支持调用方提交期望当前版本，并在版本不一致时拒绝静默覆盖。

#### Scenario: 期望版本匹配
- **GIVEN** 更新请求携带的期望版本等于数据库当前版本
- **WHEN** 用户提交实质内容修改
- **THEN** 系统应用修改并返回递增后的当前版本

#### Scenario: 期望版本过期
- **GIVEN** 用户打开编辑表单后该规格已被其他操作更新
- **WHEN** 用户携带旧期望版本提交
- **THEN** 系统返回 409 冲突
- **AND** 不修改当前正文、引用次数或版本快照

#### Scenario: 非交互入口发生数据库并发冲突
- **GIVEN** 文档导入、智能填充回填或备注批量替换与其他入口同时修改同一规格
- **WHEN** 当前内容版本并发令牌不再匹配
- **THEN** 系统返回或记录明确的业务冲突并整体回滚该事务
- **AND** 不盲目重试非幂等写入

#### Scenario: 兼容旧调用方
- **WHEN** 既有调用方未提供可选期望版本字段
- **THEN** 系统保持现有更新契约
- **AND** 正式 Web 客户端仍必须发送打开表单时的版本号

### Requirement: 有权限用户可将旧版本恢复为新版本

系统 SHALL 提供独立权限保护、可审计且带并发校验的内容版本恢复接口。

#### Scenario: 成功恢复旧版本
- **GIVEN** 用户具备版本恢复权限且期望当前版本匹配
- **WHEN** 用户确认恢复一个正文不同的旧版本
- **THEN** 系统创建更高的新版本并返回更新后的规格
- **AND** 新版本记录恢复来源
- **AND** 清理该规格 Embedding 缓存
- **AND** 审计记录规格 ID、来源版本、新版本和可选原因
- **AND** 新版本快照保存可选恢复原因

#### Scenario: 无恢复权限
- **WHEN** 用户只有规格读取权限而没有版本恢复权限
- **THEN** 系统拒绝恢复请求
- **AND** 不产生任何数据或缓存变化

#### Scenario: 恢复时当前版本已变化
- **WHEN** 恢复请求的期望当前版本与数据库不一致
- **THEN** 系统返回 409 冲突并要求刷新
- **AND** 不创建新版本

#### Scenario: 恢复为等价当前正文
- **WHEN** 目标旧版本正文与当前正文在归一化规则下等价
- **THEN** 系统返回 422
- **AND** 不创建无意义版本
