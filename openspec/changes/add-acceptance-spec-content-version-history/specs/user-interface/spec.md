## ADDED Requirements

### Requirement: 验收规格版本标签进入完整内容历史

系统 SHALL 让用户从验收规格列表和详情中的当前版本标签进入内容版本工作台，并与引用时间入口保持语义分离。

#### Scenario: 从列表打开版本历史
- **WHEN** 用户点击列表中的 `Vn` 版本标签
- **THEN** 系统打开该规格的内容版本工作台
- **AND** 默认选中当前版本
- **AND** 不打开引用时间抽屉

#### Scenario: 从详情打开版本历史
- **WHEN** 用户点击详情中的当前版本标签
- **THEN** 系统打开同一内容版本工作台
- **AND** 保留当前规格上下文

#### Scenario: 从引用次数查看引用历史
- **WHEN** 用户点击引用次数
- **THEN** 系统继续打开引用时间明细
- **AND** 不把引用记录伪装成正文版本历史

### Requirement: 内容版本工作台清晰展示时间线与历史边界

系统 SHALL 以紧凑、可扫描且响应式的界面展示版本列表、完整正文和迁移前历史缺口。

#### Scenario: 查看当前和历史版本
- **WHEN** 版本工作台加载成功
- **THEN** 界面显示当前版本、可用版本时间线、变更来源、操作者和本地化时间
- **AND** 有修改原因时展示该原因
- **AND** 用户选择任一可用版本后可查看四个字段的完整正文

#### Scenario: 存在迁移前正文缺口
- **WHEN** 当前规格存在未保存的更早版本正文
- **THEN** 界面明确显示“版本记录功能上线前的正文不可追溯”
- **AND** 不创建可点击的伪版本内容

#### Scenario: 长文本和窄屏布局
- **WHEN** 版本正文包含长文本或用户使用窄屏
- **THEN** 文本在容器内换行且保持可读
- **AND** 时间线、正文、操作区和抽屉底部不重叠

#### Scenario: 加载与失败状态
- **WHEN** 版本列表或详情正在加载、为空、失败或无权访问
- **THEN** 界面显示对应的稳定状态
- **AND** 不残留上一规格的版本正文或恢复按钮

### Requirement: 用户可比较两个内容版本

系统 SHALL 允许用户选择两个可用版本并查看字段级变化。

#### Scenario: 选择两个版本比较
- **WHEN** 用户选择起始版本和目标版本
- **THEN** 界面展示项目、规格内容、验收标准和备注的前后值
- **AND** 明确标识未变化、增加、删除和修改的字段

#### Scenario: 比较顺序交换
- **WHEN** 用户交换起始版本和目标版本
- **THEN** 界面按新的方向重新展示前后值
- **AND** 不复用方向错误的旧差异结果

#### Scenario: 版本不可用
- **WHEN** 任一版本正文不可追溯或已不存在
- **THEN** 界面阻止发起无效比较
- **AND** 明确说明不可比较原因

### Requirement: 版本恢复提供权限和并发安全反馈

系统 SHALL 仅向有权限用户提供恢复操作，并明确恢复会创建新版本。

#### Scenario: 确认恢复旧版本
- **GIVEN** 用户选择非当前版本且具备恢复权限
- **WHEN** 用户点击恢复
- **THEN** 确认框显示来源版本和将创建的新版本号
- **AND** 用户可以填写可选恢复原因
- **AND** 用户确认后提交打开工作台时的当前版本

#### Scenario: 恢复成功
- **WHEN** 恢复接口成功返回新版本
- **THEN** 界面刷新列表、详情、版本时间线和引用次数
- **AND** 新版本成为当前选中版本
- **AND** 显示恢复来源

#### Scenario: 恢复并发冲突
- **WHEN** 恢复接口返回当前版本冲突
- **THEN** 界面提示内容已被更新并刷新版本数据
- **AND** 不显示恢复成功

#### Scenario: 无恢复权限
- **WHEN** 用户没有版本恢复权限
- **THEN** 界面不显示恢复按钮
- **AND** 仍允许在读取范围内查看历史和差异
