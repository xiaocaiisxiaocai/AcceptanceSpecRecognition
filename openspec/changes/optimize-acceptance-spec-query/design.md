## Context

当前 MySQL 5.7 本地库包含 8,878 条验收规格，最大单组约 1,849 条。只读实测中，单组前 100 条分页约 6ms，但执行计划显示组合筛选后仍有 `Using filesort`；全局普通关键词查询的计数和列表合计约 85ms。前端默认每页 100 条，可切换至 1,000 条，并且多个并发 `loadData` 请求没有最新请求判定。

## Goals / Non-Goals

- Goals:
  - 快速切换分组或连续触发查询时，旧响应不得覆盖最新查询结果。
  - 分页继续支持 500 条，同时避免 1,000 条多行记录带来的渲染压力。
  - 让客户、制程、机型分组内按导入时间倒序分页能够使用同一组合索引完成筛选与排序。
- Non-Goals:
  - 不改变关键词匹配字段或模糊匹配语义。
  - 不引入 MySQL FULLTEXT、搜索服务或缓存层。
  - 不改变 API 请求参数、响应 DTO 或默认每页 100 条。

## Decisions

### 前端请求只允许最新结果生效

`SpecTable.vue` 为每次 `loadData` 生成递增请求序号。请求完成后，只有序号仍等于最新序号时才能写入 `tableData`、`total` 和 `loading`。不要求底层 HTTP 客户端支持取消，避免扩大公共请求封装的改动范围。

### 分页保留 500 条

分页选项固定为 `100 / 200 / 500`，默认仍为 100。500 是用户明确要求保留的批量查看能力；移除 1,000 是为了控制 Element Plus 普通表格在多行内容下的 DOM 和布局开销。

### 组合索引覆盖稳定排序

新增索引列顺序：

`CustomerId, ProcessId, MachineModelId, ImportedAt, Id`

前三列对应分组等值筛选，后两列对应稳定的导入时间倒序分页。查询排序同步增加 `Id` 作为相同导入时间下的确定性次序。MySQL 5.7 可以反向扫描升序 BTree，无需声明降序索引。

保留独立 `ImportedAt` 索引，用于未指定分组的全局列表倒序查询。原有三列组合索引由新索引覆盖后移除，避免重复索引写放大。

## Risks / Trade-offs

- 新组合索引比原三列索引更大，会略微增加导入和更新成本；通过替换原索引而不是并存降低该成本。
- 请求序号保护不会主动中断数据库执行，只保证界面状态正确；当前查询耗时较低，不引入更复杂的取消链路。
- 关键词 `%keyword%` 查询仍会随数据量线性增长；本次保留现有语义，后续仅在数据量或 P95 延迟达到阈值时单独设计全文检索。

## Migration Plan

1. 在迁移前创建当前本地数据库备份并验证备份文件非空。
2. 通过 EF Core Migration 删除旧三列组合索引并创建五列组合索引。
3. 应用迁移后使用 `SHOW INDEX` 核对列顺序。
4. 使用 `EXPLAIN` 验证典型分组分页不再出现额外 `filesort`。
5. 若需要回滚，执行迁移的 `Down`，恢复原三列组合索引。
