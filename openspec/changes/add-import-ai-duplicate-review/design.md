## Context
导入流程当前存在三类问题：

- 规则判重过于刚性，无法识别“语义相同但文本不完全一致”的既有规格。
- 确认弹窗虽然展示了左右对照，但“确认导入”实际仍是新增记录，与“覆盖已有”的界面语义不一致。
- Word 与 Excel 导入逻辑几乎重复，实现新能力时需要尽量抽出公共判断规则，避免两端继续分叉。

## Goals / Non-Goals
- Goals:
  - 在导入阶段增加可选的 AI 疑似重复识别。
  - 对确认覆盖的记录执行更新已有规格，而不是继续新增。
  - 保持 Word / Excel 导入行为一致。
- Non-Goals:
  - 本阶段不支持在确认弹窗中直接编辑右侧导入值。
  - 本阶段不调整 Embedding 缓存表结构，不为导入判重新增持久化缓存投影。

## Decisions
- Decision: 规则层优先，AI 只处理规则未命中的导入行。
  - Why: 完全重复和项目+规格完全相同本身就是高确定性规则，不需要额外调用 AI。

- Decision: 导入语义统一为“覆盖已有 / 跳过”，覆盖时更新已有记录。
  - Why: 用户目标是避免数据库污染，继续新增重复记录会违背该目标。

- Decision: AI 判重只使用“项目 + 规格”组合作为语义输入。
  - Why: 当前导入判重关注的是是否为同一条规格，而不是验收/备注内容是否相同。

- Decision: 导入判重不复用现有持久化 EmbeddingCache。
  - Why: 当前缓存键只有 `SpecId + ModelName`，无法区分“语义搜索投影”和“导入判重投影”，复用会污染现有缓存语义。

## Risks / Trade-offs
- 风险: 不使用持久化缓存会增加导入阶段的 Embedding 调用成本。
  - Mitigation: 仅对规则未命中的行触发 AI，并在单次请求内复用候选向量。

- 风险: LLM 复核开启后，导入耗时会增加。
  - Mitigation: 默认只对 Embedding TopK 候选复核，并允许关闭 LLM 只使用 Embedding。

## Migration Plan
1. 先扩展 DTO 与 OpenSpec。
2. 增加导入判重服务并接入 DocumentsController。
3. 修改前端导入页 UI 与确认弹窗。
4. 增加测试并完成构建验证。
