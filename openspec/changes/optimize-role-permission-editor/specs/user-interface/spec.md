## ADDED Requirements

### Requirement: 角色权限按业务资源分组维护

系统 SHALL 在角色编辑界面中按权限类型和业务资源组织权限项，使管理员能够在不改变既有授权语义的前提下高效维护大量按钮与 API 权限。

#### Scenario: 按类型和资源浏览权限
- **WHEN** 管理员打开可编辑角色的权限选择区
- **THEN** 页面按菜单、页面、按钮和接口区分权限类型
- **AND** 在每个类型内按业务资源分组展示权限项
- **AND** 页面展示各类型与各资源的已选数量和总数

#### Scenario: 搜索和仅看已选
- **WHEN** 管理员按名称、权限编码、资源或动作搜索，或启用“仅看已选”
- **THEN** 页面只过滤当前可见权限项
- **AND** 已选但被筛选隐藏的权限不会被取消或丢失

#### Scenario: 分组批量调整
- **WHEN** 管理员对某一业务资源执行分组全选或清空
- **THEN** 页面只调整该资源分组内的权限
- **AND** 其他资源分组的选择状态保持不变

#### Scenario: 业务文案与技术编码并存
- **WHEN** 页面展示按钮或接口权限
- **THEN** 权限业务名称作为主要文案
- **AND** 完整权限编码作为次要信息供管理员核对

#### Scenario: 保存契约保持兼容
- **WHEN** 管理员保存调整后的角色权限
- **THEN** 前端仍以去重后的 `permissionCodes` 集合提交
- **AND** 系统不自动联动、不隐式增加权限，也不改变后端授权校验语义
