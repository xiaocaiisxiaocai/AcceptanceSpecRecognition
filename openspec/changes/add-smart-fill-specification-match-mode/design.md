## Context

本变更的原始目标是让用户在智能填充时可手动选择“仅规格”匹配。实际实现同时收口了同步预览阶段的 AI 调用策略：把稳定、可解释的语义等价与硬冲突前移到确定性代码层，LLM 只处理规则层无法判定的灰区。

## Goals / Non-Goals

- Goals:
  - 默认保持“项目+规格”匹配，只有用户显式选择时才启用“仅规格”。
  - “仅规格”命中必须标记匹配依据为规格；同规格多候选必须人工确认。
  - 稳定等价（单位换算、品牌别名、同义符号、格式差异）优先走规范化直达，跳过 Embedding 与 LLM。
  - 明确硬冲突（数值/单位、比较符、温度跨温标、方向/极性反义）必须强制人工确认。
  - 同步 LLM 只作为灰区兜底，并受批次预算限制。
- Non-Goals:
  - 不把所有行业语义都沉淀成规则字典。
  - 不让 LLM 生成新的验收标准或修改历史规格。
  - 不在本变更中做复杂的“约束满足”推理；当前规则层按语义等价优先，灰区保守转人工。

## Decisions

- Decision: 增加 `MatchingMode.SpecificationOnly`。
  - 用户未选择时仍按项目+规格匹配，避免自动扩大命中范围。
  - 仅规格模式下，同规格多候选标记 `IsAmbiguous=true`，结果为 `ManualReview`。

- Decision: 引入规范化直达层。
  - 对项目和规格执行单位、品牌、同义符号、格式归一。
  - 首批覆盖非标自动化常见品牌与单位，包括电气/机械/气动/视觉/机器人相关品牌别名，以及扭矩、压力、流量、转速等常见单位换算。
  - 规范化键命中时构造 `ExactShortcut` 结果；若冲突扫描发现 hard conflict，则放弃直达，交回后续匹配链路。

- Decision: 引入确定性硬冲突扫描。
  - `SemanticConflictScanner` 只负责高确定性的冲突：数值/单位、比较符方向、温度跨温标、尺寸元组位置、方向/极性反义。
  - hard conflict 优先级高于 Embedding、LLM 与高置信阈值，最终一律人工确认。

- Decision: 对未覆盖的结构化 token 增加自动通过门禁。
  - 若文本中出现规则库无法识别的单位 token，且源项与候选项不一致，追加 `unknown_unit_token` warning。
  - 若文本在“品牌/厂家/供应商/vendor/brand”等上下文中出现未知英文品牌差异，追加 `unknown_brand_token` warning。
  - warning 不等同 hard conflict，不直接否定候选；它只阻断确定性自动通过，让结果进入 LLM 或人工确认。

- Decision: 启用确定性自动通过。
  - 当无 hard conflict、无人工关注证据、非歧义，且 Embedding 与最终分均达到高置信阈值时，直接 `AutoApply`。
  - 该路径由 `EnableDeterministicAutoApply` 控制，默认开启。

- Decision: LLM 重排与等价裁决共享批次预算。
  - `LlmMaxCallsPerBatch` 控制同步匹配阶段的 LLM 调用总量。
  - 预算耗尽后，未裁决的灰区行转人工确认，避免大批量预览被 LLM 拖慢。

## Risks / Trade-offs

- 规则层会成为长期维护核心。新增品牌、单位或反义词必须保持“高确定性、低歧义”，不能把灰区写成硬规则。
- 数值集合比较偏严格。对“可选值、或条件、范围满足关系”可能保守转人工；这是安全取舍，不是自动推理能力。
- 未知品牌/单位门禁会降低部分长尾样本的自动通过率；这是为非标自动化行业的长尾品牌、单位和缩写保留安全边界。
- LLM 预算由重排和等价裁决共享。预算较小时，重排可能先消耗裁决机会；前端已提示该取舍。
- 规范化直达可能提升自动通过率，也会放大规则误配影响。因此直达后仍执行 hard conflict 安全网。

## Validation

- OpenSpec 严格校验。
- Core 匹配测试覆盖：仅规格多候选人工确认、规范化直达进度、非标自动化品牌/单位规范化、未知品牌/单位门禁、硬冲突短路、确定性自动通过、LLM 预算共享。
- API 测试覆盖：配置 DTO/审批令牌、仅规格匹配依据、仅规格多候选。
- Web 类型检查覆盖新增配置字段。
