## ADDED Requirements

### Requirement: 验收规格引用历史与累计同事务落库

系统 SHALL 在智能填充最终成功提交时，为每个采用已有验收规格的最终行记录对应内容版本的引用时间，并与引用次数累计保持同一事务。

#### Scenario: 单次执行按最终采用行记录引用时间
- **GIVEN** 一个填充执行有多行最终采用同一条包含有效填充内容的验收规格
- **WHEN** 该执行成功提交
- **THEN** 系统按最终采用行数写入多条逐次引用历史
- **AND** 每条记录分配同一任务和规格内的稳定序号
- **AND** 每条历史的引用时间为该执行的 UTC 成功提交时间

#### Scenario: 历史与累计共同提交
- **WHEN** 引用历史、引用次数、执行记录或文件最终状态任一写入失败或事务回滚
- **THEN** 系统不保留本次执行的引用历史
- **AND** 系统不增加本次执行的引用次数

#### Scenario: 幂等重放不重复记录
- **GIVEN** 某个执行请求已经成功提交引用历史和引用次数
- **WHEN** 客户端使用同一执行请求标识重放请求
- **THEN** 系统返回既有执行结果
- **AND** 不新增重复引用历史
- **AND** 不再次增加引用次数

#### Scenario: 并发执行不丢失历史或累计
- **GIVEN** 两个独立填充执行并发采用同一条未发生内容变化的验收规格
- **WHEN** 两个执行均成功提交
- **THEN** 系统分别保留两个任务的引用历史
- **AND** 当前版本引用次数原子累计两个任务的全部采用行数

#### Scenario: 匹配后内容并发变化
- **GIVEN** 填充执行采用验收规格的某个内容版本
- **AND** 该规格在填充最终提交前已经发生实质内容变化并进入新版本
- **WHEN** 填充执行成功提交
- **THEN** 本次引用历史归属实际采用的旧内容版本
- **AND** 系统不把本次引用增加到新内容版本的引用次数
