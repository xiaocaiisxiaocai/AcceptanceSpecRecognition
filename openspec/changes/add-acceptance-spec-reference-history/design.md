## Context

当前 `ReferenceCount` 表示验收规格“当前内容版本”在智能填充最终成功提交后被采用的行次数。Excel 与 Word 两条执行路径均在最终提交事务内按规格分组，使用数据库端原子加法累计；任务快照和请求指纹负责阻止同一执行请求重放时重复累计。

一条智能填充任务可能有多行采用同一规格，这些行在同一次最终提交中同时生效。验收规格内容还可能通过手工编辑、文档导入、智能填充回填和备注批量替换发生变化，现有统一策略会在实质变化时清零 `ReferenceCount`。

本变更需要在不伪造旧时间、不破坏并发累计和幂等语义的前提下，为当前版本及后续版本保存可分页查询的逐次时间历史。

## Goals / Non-Goals

- Goals:
  - 按每个最终采用行记录一次规格引用及其成功提交时间。
  - 保证引用历史与累计值处于同一事务，失败或取消不留下单边数据。
  - 内容变化后保留旧版本历史，同时让列表累计值继续只表示当前版本。
  - 明确区分迁移前已有但无法得知具体时间的引用次数。
  - 复用现有验收规格读取权限和组织数据范围。
  - 支持按最早或最新时间稳定分页，避免大历史一次性加载。
- Non-Goals:
  - 不猜测、推算或批量伪造迁移前引用时间。
  - 不改变引用次数的统计单位；仍按最终采用行数计数。
  - 不展示操作者、来源文件、行号或匹配证据；这些仍由执行记录负责。
  - 不提供人工新增、修改或删除引用历史的 API。
  - 不在本变更中引入自动归档或过期清理；规格存在期间保留其引用历史。

## Decisions

### 每个最终采用行对应一条引用历史

新增 `AcceptanceSpecReferenceEvents` 表，每条记录包含：

- `Id BIGINT`：主键。
- `AcceptanceSpecId INT`：所属验收规格，删除规格时级联删除历史。
- `ReferenceVersion BIGINT`：该次引用对应的内容版本。
- `TaskId VARCHAR(64) NULL`：产生引用的智能填充任务标识；迁移基线为空。
- `TaskOccurrenceIndex INT NULL`：同一任务内采用此规格的稳定序号；迁移基线为空。
- `OccurrenceCount BIGINT`：该记录代表的引用次数；未来逐次记录固定为 1，迁移基线可大于 1。
- `ReferencedAtUtc DATETIME(6) NULL`：最终成功提交时刻；仅迁移基线允许为空。

同一任务中同一规格被多行采用时分别写入记录，`TaskOccurrenceIndex` 从 1 递增，每条未来记录的 `OccurrenceCount` 固定为 1。所有行都在同一最终提交中生效，因此引用时间可能相同，但任务内序号和主键保证第 1 次、第 2 次等记录仍可稳定区分。

对未来记录建立 `(TaskId, AcceptanceSpecId, ReferenceVersion, TaskOccurrenceIndex)` 唯一索引，作为现有任务幂等门禁之外的数据库兜底。查询索引使用 `(AcceptanceSpecId, ReferenceVersion, ReferencedAtUtc, Id)`，支持当前版本过滤和最早/最新记录分页。

### 使用单调版本号保留内容变更前的记录

在 `AcceptanceSpecs` 增加 `ReferenceVersion BIGINT NOT NULL DEFAULT 1`。统一内容变化策略在项目、规格、验收或备注实质变化时执行：

1. `ReferenceVersion = ReferenceVersion + 1`；
2. `ReferenceCount = 0`；
3. 不删除旧版本引用历史。

等价空白归一化更新不递增版本，也不清零计数。所有现有内容更新入口继续复用同一策略，避免版本漂移。

列表中的 `ReferenceCount` 始终只表示当前 `ReferenceVersion`。引用历史界面默认查询当前版本，并允许用户切换为包含历史版本；历史项明确显示版本及是否为当前版本。

### 迁移已有次数为“时间不可追溯”基线

迁移创建历史表后，对 `ReferenceCount > 0` 的规格插入一条基线记录：

- `ReferenceVersion = 1`
- `TaskId = NULL`
- `OccurrenceCount = ReferenceCount`
- `ReferencedAtUtc = NULL`

该记录保留已有累计值与历史合计的一致性，但不会编造发生时间。前端将空时间显示为“记录功能上线前，时间不可追溯”。新建规格不产生基线记录。

当前版本保持以下不变量：

`ReferenceCount = SUM(当前 ReferenceVersion 下所有历史记录的 OccurrenceCount)`

### 在最终提交事务内同时写历史和累计

现有按规格分组的增量计算继续作为唯一计数来源。每个分组在 Excel 或 Word 最终提交事务内：

1. 使用执行开始时匹配到的规格 `ReferenceVersion`，按最终采用行创建逐次引用历史；
2. 使用同一版本作为条件，执行数据库端 `ReferenceCount = ReferenceCount + 采用行数`；
3. 保存历史后再提交现有最终事务。

引用时间使用可测试的 `TimeProvider` 获取 UTC 提交时间，同一任务内的历史共享同一时间值，并通过 `TaskOccurrenceIndex` 稳定区分。

条件版本更新可处理内容并发修改：若匹配后规格内容已进入新版本，本次引用仍记录在它实际采用的旧版本下，但不会增加新版本的 `ReferenceCount`。两个独立填充任务并发引用同一未变化版本时仍使用数据库端原子加法，不丢失增量。

任何历史插入、累计更新、执行记录或文件最终状态失败时，事务整体回滚；客户端取消也不得留下只有累计或只有历史的状态。任务重放由现有快照门禁直接返回既有结果，唯一索引额外阻止重复历史。

### 新增受数据范围保护的分页只读接口

新增：

`GET /api/specs/{id}/reference-history?page=1&pageSize=20&includePreviousVersions=false&sort=newest`

接口先按现有 `SpecAccessContext` 校验用户能否读取该规格，再查询历史。无权访问返回 403，不存在返回 404。`pageSize` 限制为 1 到 100，支持 `oldest` 和 `newest` 两种排序；相同时间使用任务内序号和记录 ID 稳定排序，迁移基线单独作为不可追溯次数返回。

响应包含：

- 当前内容版本和当前引用次数；
- 所选版本范围内已记录时间的引用次数；
- 所选版本范围内时间不可追溯的引用次数；
- 分页历史项：当前版本内引用序号、内容版本、是否当前版本和引用时间。

未来每条分页历史项代表一次引用，因此 `total` 表示已记录时间的引用次数。迁移前不可追溯次数通过独立汇总字段返回，不伪装成带时间的逐次记录。

### 引用次数作为明细入口

列表和规格详情中的非零引用次数改为可点击入口；当前次数为 0 但存在旧内容版本时也保留入口，以便查看旧历史。打开抽屉后显示：

- 当前版本累计、已记录时间次数、时间不可追溯次数；
- “仅当前版本 / 包含历史版本”筛选；
- “最早在前 / 最新在前”排序；
- 引用序号、内容版本和引用时间；
- 服务端分页。

引用次数为 0 且仍为初始内容版本时保留只读数字，不发起无意义请求。时间统一按现有 `formatApiUtcDateTime` 在浏览器本地时区显示；空时间使用明确中文说明，不显示伪日期。

### 列表展示所有版本的最近可追溯引用时间

验收规格分页列表在取得当前页数据后，针对本页规格 ID 对引用历史执行一次分组聚合，返回所有内容版本中最大的非空 `ReferencedAtUtc` 作为 `LastReferencedAtUtc`。该时间表示该规格任一内容版本最近一次被智能填充最终采用的成功提交时刻；内容变化后仍保留旧版本的最近引用时间，避免将“当前版本尚未引用”误解为“该规格从未使用”。

列表聚合继续以引用历史表为单一事实来源，不在 `AcceptanceSpecs` 冗余保存最新时间，也不加载逐次历史集合。迁移前只有不可追溯基线、从未引用或当前页没有已知时间记录时返回 `null`，前端显示 `-`，不推算或伪造时间。

## Risks / Trade-offs

- 历史表会按最终采用行持续增长；索引和分页避免列表查询退化，但长期容量需要监控。
- 列表每页增加一次按规格 ID 分组的最新时间聚合查询；复用现有规格/版本/时间索引并限定为当前页 ID，避免逐行查询和全历史加载。
- 一个任务内多行采用同一规格会产生多条时间相同的记录；这是逐次查询第 1 次、第 2 次引用所需的存储成本。
- 旧数据只能保留次数，无法恢复具体时间；界面必须持续明确这一边界。
- 内容并发修改时，引用可能进入历史版本而当前计数不增加，这是“引用实际采用的内容版本”语义的必然结果。
- `Down` 迁移会删除引用历史和版本字段，回滚前必须确认是否接受时间历史永久丢失。

## Migration Plan

1. 新增 `AcceptanceSpecs.ReferenceVersion BIGINT NOT NULL DEFAULT 1`。
2. 创建 `AcceptanceSpecReferenceEvents`、外键、唯一索引和分页索引。
3. 将现有非零 `ReferenceCount` 写为时间为空的版本 1 基线历史，并核对基线合计与累计值一致。
4. 部署兼容新结构的 API 后，验证迁移历史、列和索引存在，并确认无待应用迁移。
5. 验证新引用、批量采用、并发执行、幂等重放、失败回滚、内容变更和权限边界。
6. 验证列表/详情入口、当前/历史版本切换、空时间提示和分页。
7. 回滚会删除历史表和版本字段；执行前必须备份并明确接受引用时间历史丢失。

## Open Questions
