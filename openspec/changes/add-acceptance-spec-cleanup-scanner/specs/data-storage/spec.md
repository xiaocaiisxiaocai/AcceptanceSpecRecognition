## ADDED Requirements

### Requirement: 持久化验收规格扫描快照

系统 SHALL 持久化扫描任务及其逐规格判定快照，以支持真实进度、稳定分页和动作前并发校验。

#### Scenario: 保存扫描条件和进度
- **WHEN** 系统创建并执行扫描任务
- **THEN** 任务保存扫描时间、阈值、范围摘要、状态、总数、已处理数和分类计数
- **AND** 进度计数仅在对应批次结果成功持久化后增加

#### Scenario: 保存逐项判定依据
- **WHEN** 系统完成一条规格的扫描
- **THEN** 结果保存规格 ID、扫描内容版本、引用汇总、关键时间、分类和原因码
- **AND** 同一任务与规格最多存在一条结果

#### Scenario: 清理过期扫描结果
- **WHEN** 扫描任务超过配置的保留期
- **THEN** 系统可分批删除任务及结果
- **AND** 不修改、隔离或删除任何验收规格

### Requirement: 持久化验收规格隔离生命周期

系统 MUST 持久化规格的 Active/Quarantined 状态、忽略元数据和隔离元数据，并保证现有数据迁移后保持 Active。

#### Scenario: 现有规格安全迁移
- **WHEN** 数据库应用清理功能迁移
- **THEN** 所有现有规格初始化为 Active
- **AND** 不根据现有引用数据自动隔离或删除规格

#### Scenario: 隔离保留历史
- **WHEN** Active 规格进入隔离区
- **THEN** 系统保存隔离时间、到期时间、操作人、原因、来源扫描和内容版本
- **AND** 规格正文、内容版本和引用历史继续保留

#### Scenario: 内容变化解除忽略
- **GIVEN** Active 规格已设置忽略后续扫描
- **WHEN** 项目、规格、验收或备注发生实质变化并生成新内容版本
- **THEN** 系统在同一事务中解除忽略标记

### Requirement: 隔离规格统一不可用于业务消费

系统 MUST 让所有普通验收规格读取和消费者默认只使用 Active 规格。

#### Scenario: 隔离后不再参与匹配
- **WHEN** 规格成功进入隔离区
- **THEN** 智能填充候选、语义搜索、重复排查和严格复用不再返回该规格
- **AND** 常规规格列表与详情也不再返回该规格

#### Scenario: 隔离后缓存失效
- **WHEN** 规格成功进入隔离区
- **THEN** 其 Embedding 缓存被删除或标记失效
- **AND** 缓存预热不为隔离规格重新生成缓存

#### Scenario: 恢复后重新可用
- **WHEN** 隔离规格被恢复为 Active
- **THEN** 普通业务查询可再次返回该规格
- **AND** Embedding 缓存可按既有按需或预热机制重建

### Requirement: 永久删除保留最小审计留痕

系统 MUST 在永久删除规格正文与专属历史后保留不含正文的删除记录。

#### Scenario: 事务性永久删除
- **WHEN** 已到期隔离规格通过永久删除门禁
- **THEN** 系统在同一事务内删除其缓存、引用事件、内容版本、关联扫描结果和规格本体
- **AND** 任一步失败时不得留下部分删除状态

#### Scenario: 删除留痕不保存正文
- **WHEN** 系统记录永久删除结果
- **THEN** 留痕包含原规格 ID、归属、操作人、时间、来源扫描和计数摘要
- **AND** 留痕不包含项目、规格、验收或备注正文
