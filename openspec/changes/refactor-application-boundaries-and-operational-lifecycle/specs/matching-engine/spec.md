## ADDED Requirements

### Requirement: 匹配与填充流水线遵守取消和并发预算
系统 MUST 为高成本的候选生成、Embedding、LLM 复核、文档解析与写回子任务设置可配置并发预算，并从 API 请求或宿主生命周期传播取消信号；资源治理不得改变既有匹配排序和决策语义。

#### Scenario: 等待匹配并发预算时取消
- **GIVEN** 高成本匹配任务已达到配置并发上限
- **WHEN** 等待中的请求被客户端取消
- **THEN** 系统停止等待且不启动新的 Embedding、LLM 或文档处理子任务
- **AND** 已取得的 keyed lease 或 semaphore permit 被释放

#### Scenario: 匹配处理中收到取消
- **WHEN** 匹配、复核或填充流水线收到取消信号
- **THEN** 系统在可安全中断的批次边界停止调度后续候选和行
- **AND** 已启动且支持取消的外部调用接收同一取消信号
- **AND** 不把取消结果写成成功任务快照或完整填充产物

#### Scenario: 并发预算不改变决策
- **GIVEN** 两次请求使用相同输入、候选数据和匹配配置
- **WHEN** 系统分别在不同允许范围内的并发预算下完成处理
- **THEN** 两次请求产生相同的候选排序、证据和最终决策
- **AND** 并发预算只影响吞吐与等待时间

### Requirement: 匹配资源治理具备压力与故障回归
系统 MUST 对匹配和填充资源治理执行可重复的压力与故障测试，验证峰值并发、取消和外部服务失败不会泄漏 permit、文件句柄或后台任务。

#### Scenario: 峰值并发后资源回落
- **WHEN** 测试并发执行多文件、多表和多行匹配请求并等待全部结束
- **THEN** 活跃匹配 permit、文档文件句柄和临时任务数量回落到基线
- **AND** 后续请求仍能取得预算并正常执行

#### Scenario: 外部 AI 调用失败
- **WHEN** Embedding 或 LLM 调用超时、失败或被取消
- **THEN** 系统按既有失败/人工确认策略返回
- **AND** 释放并发预算且不继续调度不必要的后续工作
