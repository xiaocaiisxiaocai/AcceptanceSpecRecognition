## Context

规则识别目前只返回每个业务字段的最终列。多个同分高置信候选会因扫描顺序静默保留较早列，用户无法看到其他有效候选，也无法在文件级确认学习前纠正。

## Goals / Non-Goals

- Goals: 返回可解释的字段候选；只在无法可靠区分时拦截；用户选择直接更新最终确认草稿；保留无冲突流程。
- Non-Goals: 不改变底层 Excel；不为低置信噪声候选频繁弹框；不新增数据库表。

## Decisions

- 后端在识别结果中按字段返回候选列表，候选包含列索引、表头、置信度和数据样例。
- 仅当至少两个候选达到高置信阈值且分差处于歧义窗口时标记为未解决冲突。
- 前端在结构识别完成并确定默认已选 Sheet 后立即集中处理冲突；冲突解决前不得生成正式匹配配置或进入匹配预览。
- 用户选择更新现有确认草稿和字段置信信息，后续仍使用既有确认 API 与模板学习链路。
- 弹框按 Sheet 和字段分组，候选用单选卡片展示 Excel 列标、范围与样例；推荐项默认预选。
- 预选结果只有在用户点击文件级确认后才生效；无推荐项的冲突保持未选。

## Risks / Trade-offs

- 候选样例增加响应体积：每列最多返回三条截断后的非空样例。
- 多 Sheet 可能产生多个冲突：按 Sheet 顺序集中在一个弹框中处理，确认后一次性进入结构确认页。
- 用户后续勾选此前未选的冲突 Sheet：文件级主操作保留兜底门禁，不允许未解决冲突进入匹配配置。
- 历史前端可能忽略新增字段：识别响应只增不删，保持兼容。

## Migration Plan

无需数据迁移。旧识别结果没有候选字段时按无冲突流程处理。
