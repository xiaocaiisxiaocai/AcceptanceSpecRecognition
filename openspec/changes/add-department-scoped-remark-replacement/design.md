## Context

备注会参与关键词搜索与 AI 语义搜索，批量修改不仅是数据库写入，还必须同步处理部门授权、确认时效和 Embedding 缓存。当前管理员可以查看公司总体或指定部门，普通用户只能访问本人部门。

## Goals / Non-Goals

- Goals: 在一个明确部门内安全预览并批量替换备注中的固定文本；所有搜索入口保持相同部门边界。
- Non-Goals: 不提供跨部门替换、不支持正则表达式、不修改项目/规格/验收列、不新增后台异步任务。

## Decisions

- Decision: 采用“预览 + 确认执行”两个接口。预览返回影响数量与确认指纹，执行时在事务内重新计算并校验，避免使用过期预览。
- Decision: 管理员必须提交当前公司内有效的具体部门，普通用户忽略客户端扩大范围的意图并拒绝其他部门。
- Decision: 替换采用区分大小写的字面文本语义；替换值可为空，查找值不可为空。
- Decision: 只返回有限样例且不把完整备注写入审计日志；审计记录部门、操作者和实际修改数量。
- Decision: 修改成功后删除受影响规格的 Embedding 缓存，使下一次 AI 搜索按新备注重建向量。

## Risks / Trade-offs

- 大范围同步更新可能增加事务时间 -> 先统计影响规模，使用集合化查询并设置现有请求取消与资源边界。
- 预览后数据可能变化 -> 执行阶段校验确认指纹/数量，不一致则要求重新预览。
- 字面替换可能误匹配更长词组 -> 预览显示样例和匹配次数，用户二次确认后才执行。

## Migration Plan

不需要数据库迁移。接口和权限上线后按钮按权限出现；回退时移除新增接口和前端入口即可，已完成的备注修改属于用户确认后的业务数据变更，不自动回滚。
