## Context

确认页当前由文件级页面组合多个 Sheet Tab，每张结构卡片独立维护范围编辑草稿。单 Sheet 已实现确认、学习与导入串联，但多 Sheet 仍按卡片分别提交，导致文件级操作被拆散。

## Goals / Non-Goals

- Goals: 数据导入侧只保留一个文件级主操作；提交所有已勾选 Sheet 的最终草稿；全部确认成功后统一刷新并导入；提供可定位的失败和进度状态。
- Non-Goals: 不自动勾选识别失败或未知类型的 Sheet；不学习未勾选 Sheet；不改变智能填充的逐表确认行为；不新增后端批量事务接口。

## Decisions

- Decision: 结构卡片持续负责范围编辑和请求构建，但通过草稿变更事件把当前确认请求同步到文件级 Map，保证切换 Tab 后草稿不丢失。
- Decision: 数据导入侧隐藏卡片确认按钮，在 Tabs 外只展示一个文件级主操作；智能填充继续使用现有卡片按钮。
- Decision: 前端按 tableIndex 顺序串行调用现有确认接口。自动采用的已勾选 Sheet 直接跳过，未勾选 Sheet 不进入队列。
- Decision: 单张确认期间不重复刷新预览；全部确认成功后统一应用最新结构、刷新一次完整预览并调用现有导入流程。
- Decision: 批量操作不是跨请求数据库事务。中途失败时保留已经完成的学习结果，停止导入并允许幂等重试。

## Risks / Trade-offs

- 多次网络请求可能部分成功 → 页面明确显示失败 Sheet，正式导入只允许在全部成功后启动；模板保存现有幂等逻辑保证安全重试。
- 非活动 Tab 的编辑状态可能遗漏 → 卡片初始化和每次范围/列映射变化都同步完整确认草稿。
- 批量确认时间增加 → 展示“正在确认第 n/m 张 Sheet”并锁定选择、编辑和重复点击。

## Migration Plan

仅调整前端编排和展示，不迁移数据库或历史模板；现有确认 API 和智能填充流程保持兼容。
