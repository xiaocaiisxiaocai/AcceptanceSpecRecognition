## 1. 文档概述

### 1.1 项目背景

随着企业产品质量要求的不断提升，验收规格（Acceptance Specification）的管理已成为制造业、检测认证行业质量管理的核心环节。传统模式下，验收工程师需要：

1. 从历史 Word/Excel 文档中手动查找相关验收规格
2. 根据经验判断新旧规格是否对应
3. 手动填写验收标准和备注信息

这种模式存在以下痛点：

- **效率低下**：每份新文档需要反复查阅历史文档，人工查找成本高
- **一致性差**：不同工程师对相似规格的判定标准不统一
- **错误率高**：人工比对容易遗漏关键差异或错误匹配相似但不同的规格
- **维护困难**：历史规格积累后难以有效复用

### 1.2 项目目标

本系统旨在通过 **AI 智能匹配技术**，帮助验收工程师：

1. **快速提取历史验收规格**：从 Word/Excel 文档中自动解析并结构化存储
2. **智能匹配新文档内容**：基于项目与规格文本，自动从历史库中查找最匹配的验收标准
3. **自动填充结果**：将匹配到的验收标准和备注自动写入目标文档
4. **可解释的匹配决策**：提供清晰的匹配依据和置信度说明，便于人工复核

### 1.3 目标用户

| 用户角色 | 职责描述 |
|---------|---------|
| **验收工程师** | 使用系统的核心用户，执行导入、匹配、填充操作 |
| **系统管理员** | 配置 AI 服务、Prompt 模板、列映射规则等 |
| **数据管理员** | 维护客户、制程、机型等基础数据 |
| **质量主管** | 审核匹配结果，查看执行记录和审计日志 |

### 2.2 数据组织模型

系统按 **客户 → 制程** 的组合维度组织验收规格数据：

```
客户 (Customer)
    └── 制程 (Process)
            └── 验收规格 (AcceptanceSpec)
                    ├── 项目 (Project)      ← 查找键
                    ├── 规格 (Specification) ← 查找键
                    ├── 验收标准 (Acceptance) ← 填充目标
                    └── 备注 (Remark)        ← 填充目标
```

**说明**：
- 查找键：用于与新文档中的项目+规格进行匹配
- 填充目标：匹配成功后，将对应的验收标准和备注写入新文档

### 2.3 文档处理需求

#### 2.3.1 支持的文档格式

| 格式 | 用途 | 处理方式 |
|------|------|---------|
| **Word (.docx)** | 导入历史验收规格 / 填充目标 | OpenXml SDK 解析与写入 |
| **Excel (.xlsx)** | 导入历史验收规格 / 填充目标 | ClosedXML 解析与写入 |

#### 2.3.2 Word 文档处理

- 自动识别表格结构
- 通过列映射规则自动识别项目、规格、验收、备注列
- 支持多表格文档
- 填充时保留原文档样式和格式

#### 2.3.3 Excel 文档处理

- 支持多 Sheet 文档
- 用户手动选择 Sheet 和列映射
- 填充时直接修改源文件（保留格式）
- 提供结果文件下载

#### 3.3.3 AI 等价裁决（新功能）

**问题背景**：
- 换行、普通标点、`≈/约等于/约为` 等表达差异会影响匹配体验
- 客户不希望继续维护规则词表

**解决方案**：
- 对达到中置信门槛（≥0.6）且无硬冲突的当前最佳候选，固定触发 AI 等价裁决
- AI 返回结构化结论：等价（equivalent）、不同（different）、不确定（uncertain）
- 裁决结果包含原因类型：格式差异、标点差异、等价表达、符号等价、语义差异、符号冲突、不确定

**裁决结果处理**：

| 裁决结论 | 置信度处理 | 前端展示 |
|---------|-----------|---------|
| Equivalent | 不降低置信度 | 显示"AI 判断为等价表达/格式差异"提示 |
| Different | 保持或转为人工确认 | 显示"AI 判断为不同"提示 |
| Uncertain | 转人工确认 | 显示"AI 无法确定"提示 |

#### 3.3.4 置信度分级

| 等级 | 分数范围 | 颜色 | 说明 |
|------|---------|------|------|
| 高置信 | ≥ 0.98 | 绿色 | 用于结果分层展示，是否自动采用以后端 decision 为准 |
| 中置信 | 0.6 ~ 0.98 | 黄色 | 进入服务端重排，并固定执行 Top1 AI 等价裁决 |
| 低置信 | < 0.6 | 红色 | 不自动采用 |

## 5. 用例分析

### 5.1 核心用例

#### UC-001: 导入历史验收规格

**参与者**：验收工程师  
**前置条件**：已登录系统  
**基本流程**：

1. 上传包含验收规格的 Word/Excel 文件
2. 选择目标表格
3. 配置列映射（项目、规格、验收、备注）
4. 选择客户和制程
5. 预览待导入数据
6. 确认并执行导入

**异常流程**：
- 检测到疑似重复记录 → 弹出冲突处理对话框
- 文件格式不支持 → 提示错误信息

#### UC-002: 执行智能填充

**参与者**：验收工程师  
**前置条件**：已存在目标客户的验收规格数据  
**基本流程**：

1. 上传待填充的 Word/Excel 文件
2. 选择目标表格和列映射
3. 选择客户和制程
4. 配置匹配参数
5. 执行预览
6. 查看匹配结果（自动采用 / 人工确认）
7. 对需要确认的行进行确认或调整
8. 执行填充
9. 下载填充结果

#### UC-003: 批量复用填充结果

**参与者**：验收工程师  
**前置条件**：已完成一次智能填充  
**基本流程**：

1. 在填充完成后点击"应用到相同验规"
2. 上传多个目标文件
3. 系统执行严格复用预检
4. 查看预检结果（可应用 / 不可应用）
5. 确认执行批量复用
6. 下载结果文件

#### UC-004: 配置 AI 服务

**参与者**：系统管理员  
**前置条件**：已登录系统，具有配置权限  
**基本流程**：

1. 进入 AI 服务配置页面
2. 点击新增服务
3. 选择服务类型（OpenAI / Azure / Ollama / LM Studio）
4. 填写服务参数（名称、API Key、端点、模型等）
5. 保存并测试连接
6. 配置服务优先级

#### UC-005: 管理用户权限

**参与者**：系统管理员  
**前置条件**：已登录系统，具有用户管理权限  
**基本流程**：

1. 进入用户管理页面
2. 查看用户列表
3. 创建新用户（分配角色和组织）
4. 编辑用户信息
5. 重置用户密码
6. 禁用/删除用户
