# 架构边界与质量基线（2026-07-10）

本文记录 `refactor-application-boundaries-and-operational-lifecycle` Phase 0/1 的可复查基线。它不是 Phase 2+ 已完成声明；协议层剩余用例迁移、运行生命周期、容器加固和生产等价验证仍按该 change 的后续阶段执行。

## 1. 项目依赖与物理所有权

当前项目引用图：

```text
AcceptanceSpecSystem.Api
└── AcceptanceSpecSystem.Application
    ├── AcceptanceSpecSystem.Core
    └── AcceptanceSpecSystem.Data

AcceptanceSpecSystem.Core  （无项目引用）
AcceptanceSpecSystem.Data  （无项目引用）
```

Phase 1 前共有 6 个跨项目编译入口；现已迁移为唯一物理归属：

| 原物理位置 | 新的唯一归属 | 说明 |
|---|---|---|
| `Data/Providers/CoreProviderAdapters.cs` | `Application/Providers/CoreProviderAdapters.cs` | Application 拥有 Core 端口到 Data 仓储的 adapter 与 DI |
| `Api/DTOs/AuthRoleDtos.cs` | `Application/Contracts/AuthRoleDtos.cs` | RBAC 共享契约 |
| `Api/DTOs/OrgUnitDtos.cs` | `Application/Contracts/OrgUnitDtos.cs` | 组织共享契约 |
| `Api/DTOs/SystemUserDtos.cs` | `Application/Contracts/SystemUserDtos.cs` | 用户共享契约 |
| `Api/DTOs/DocumentDtos.cs` | `Application/Contracts/DocumentDtos.cs` | 文档/导入共享契约 |
| `Api/DTOs/ExcelImportDtos.cs` | `Application/Contracts/ExcelImportDtos.cs` | Excel 导入共享契约 |

所有 `.csproj` 已移除对应的 `Compile Include/Link` 和 `Compile Remove`。架构测试会解析全部项目文件，禁止重新引入跨项目源码编译。

## 4. 兼容性基线

### 4.1 API JSON 契约

- `ApplicationContractJsonBaselineTests` 固化迁移契约的 camelCase JSON 属性名，覆盖角色、组织、系统用户、文件上传、Word 导入和 Excel 导入。
- 现有 `WebApplicationFactory` 集成测试继续覆盖登录、文件上传/预览/导入、智能结构识别、匹配、执行历史与权限拒绝。
- DTO 只改变程序集/命名空间归属，不改变 HTTP 路径、JSON 属性名、默认值或枚举序列化方式。

### 4.2 数据库 migration

- 当前包含 39 个非 Designer migration，最新迁移为 `20260711010000_EnforceDatabaseCollation`。
- `MySqlMigrationSmokeTests` 在显式提供真实 MySQL 环境时验证完整迁移链；SQLite/InMemory 仍只作为快速反馈。
- Phase 1 不修改实体、migration 或 `AppDbContextModelSnapshot`。

### 4.3 核心页面

当前回归基线覆盖：登录与权限导航、数据导入确认工作区、智能填充、BatchReply、配置管理、审计日志与执行历史。前端 Vitest、Node tests、类型检查和生产构建共同作为页面兼容信号；Phase 1 不改页面路由和交互。

## 5. 资源使用基线

本阶段只记录限制，不引入任意性能阈值：

- 单文件客户端/服务端校验上限：50 MiB。
- multipart 请求总上限：单文件上限的 10 倍，用于批量上传。
- LLM 单行默认超时：120 秒，可配置范围 5–300 秒。
- 外部 AI 长请求 HttpClient 上限仍为 12 小时；Phase 3 将结合取消、并发闸门和压测数据治理。
- 真实大文件峰值内存、解析耗时、并发等待时间尚无可信生产等价数据，明确保留为 Phase 3/5 测量项，不能把开发机构建耗时当作生产基线。

## 6. 覆盖率与 CI artifact

- 后端：`dotnet test --collect:"XPlat Code Coverage"` 生成 Cobertura，上传 `backend-coverage` artifact。
- 前端：Vitest V8 coverage 生成 Cobertura 与 `coverage-summary.json`，上传 `frontend-coverage` artifact；Node tests 仍在同一 CI 测试步骤执行。
- 不设置任意绝对百分比阈值。`docs/COVERAGE-NO-REGRESSION-POLICY.md` 已确定同工具、同采集范围下对最近成功 `main` artifact 的各维度不回退策略，并规定采集稳定期、fail-closed 条件及有负责人和到期日的例外审批记录。
