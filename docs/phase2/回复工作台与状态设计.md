# 二期回复工作台与状态设计

状态：详细设计草案，供实现拆分与验收使用  
适用界面：现有 Vue 3、TypeScript、Element Plus 管理后台  
业务依据：[二期需求讨论确认稿](../二期需求讨论确认稿-2026-09-21.md)  
总体方案：[二期详细设计与实施方案](../二期详细设计与实施方案-2026-09-21.md)

## 1. 设计目标

回复工作台承接结构确认后的多人分工回复，目标是让少量业务人员在同一任务内完成以下工作：

1. 看清本次任务、当前修订版、参与部门和处理范围。
2. 按部门认领、接手、取消认领或转交条目。
3. 在原文、当前答案、历史候选和来源条件之间就地核对。
4. 可靠保存草稿，明确处理并发、断线和过期页面。
5. 由部门成员确认完成，由任务负责人生成正式文件。
6. 正式完成后通过修订版继续处理，旧正式结果保持可追溯。

本设计不增加部门内二次审批、必填／选填配置、任务中途更换源文件、离线编辑回传或 AI 自由生成答案。

## 2. 核心对象与状态口径

### 2.1 对象关系

- `ReplyTask`：任务身份聚合，保存稳定任务编号、来源文件身份、发起信息和当前修订版引用。
- `ReplyTaskRevision`：一次可独立确认、正式生成和追溯的任务版本。
- `ReplyItem`：当前修订版中的独立填写单元；一条仅有一个当前负责部门。
- `ReplyItem.AnswerJson`：条目答案字段组正文；人工修改与采用来源分别关联版本及 `ReplyItemAdoption`，不额外维护另一份可独立写入的答案。
- `ReplySourceSelection`：本次任务默认来源范围，以及条目级调整后的实际来源范围。
- `ReplyCandidateSnapshot`：一次匹配返回的完整候选及其内容版本，不拆成跨候选自动组合。
- `ReplyResult`：正式文件及其生成所绑定的修订版、答案快照和文件校验信息，与数据设计采用同一命名。

任务列表中的“任务状态”取当前 `ReplyTaskRevision.State`，不在 `ReplyTask` 上维护另一套可独立变化的业务状态。

### 2.2 修订版状态

| 状态 | 业务含义 | 允许的主要动作 |
| --- | --- | --- |
| `Preparing` | 上传后的结构、区域、字段组和参与部门仍在准备 | 配置区域、排除范围、选择部门、开始已确认区域的准备工作 |
| `Working` | 当前版本已进入认领与填写 | 认领、接手、保存、匹配、确认完成、来源核对、下载草稿 |
| `Generating` | 已冻结本次正式生成快照，后台正在生成文件 | 查看进度、等待、失败后重试；不接受对冻结版本的答案修改 |
| `Finalized` | 正式文件已生成并留存 | 下载同一正式版本、查看差异、创建修订版 |
| `Cancelled` | 当前版本已明确取消 | 只读查看；不认领、不填写、不生成正式文件 |
拟采用：`Preparing` 中已确认的区域可以先进入条目准备和填写入口；只要仍有范围疑问，当前版本不得进入正式生成。

### 2.3 条目工作状态

| `Item.WorkState` | 含义 | 当前负责部门 |
| --- | --- | --- |
| `Unclaimed` | 尚无部门负责，或原负责部门退出后等待接手 | 空 |
| `InProgress` | 已由一个部门认领，正在填写或等待再次确认 | 必须有且仅有一个 |
| `Completed` | 所有选中的答案字段已填完，且部门成员确认了当前保存版本 | 保留确认时部门快照；该部门退出后可无有效认领 |
| `NotApplicable` | 部门成员确认整条无需回复／不适用，并填写原因 | 保留确认时部门快照；该部门退出后可无有效认领 |
`NeedsSourceReview` 是独立布尔值，不扩展 `WorkState`：

- 来源正文、适用范围或可用状态在最后确认后发生相关变化时置为 `true`。
- 它保留条目的已确认答案快照和 `Completed`／`NotApplicable` 事实。
- `NeedsSourceReview=true` 时阻止正式生成。
- 当前负责部门确认继续使用已保存旧答案，或替换答案后重新完成，才清除该标记。
- 原负责部门已退出时，条目转为 `Unclaimed`，保留原答案和历史记录供接手人核对。

### 2.4 状态不变量

1. `Completed` 绑定答案内容版本；答案内容变化后立即回到 `InProgress`。
2. `InProgress` 必须有当前有效认领部门。已完成／不适用条目可以保留已退出部门的历史确认；一旦需要修改或核对且无有效负责部门，再转为 `Unclaimed`。
3. `NotApplicable` 必须有简短原因，不以空答案替代原因。
4. 认领属于部门，实际保存、接手、完成和核对操作记录到个人。
5. `Generating` 绑定一个不可变生成快照；生成失败不解冻或改写该快照。
6. `Finalized` 的修改只能发生在新修订版，旧正式文件和旧答案不变化。
7. 范围疑问、未完成条目、未认领条目或 `NeedsSourceReview=true` 均阻止正式生成。

## 3. 页面入口与整体布局

### 3.1 任务列表

沿用现有管理后台的筛选栏、`el-table`、分页和状态标签，不建立独立视觉体系。
建议列：任务编号、文件名、当前版本、状态、发起人、参与部门、条目进度、来源待核对数、范围疑问数、更新时间、操作。
筛选项：关键词、当前状态、参与部门、“只看与我部门有关”、来源待核对。关键词输入占弹性宽度，其余控件保持完整标签。
主要入口：

- `Preparing`：显示“继续配置”。
- `Working`：显示“进入回复”。
- `Generating`：显示“查看生成进度”。
- `Finalized`：显示“查看结果”。
- `Cancelled`：显示“查看记录”。

空数据与筛选无结果分别展示；筛选无结果保留筛选栏和重置按钮。

### 3.2 回复工作台框架

工作台采用三段式布局：

1. 顶部任务栏：任务名称、版本、修订版状态、保存状态、参与部门、草稿下载和正式生成入口。
2. 左侧条目栏：区域树、状态统计、过滤器和条目列表。
3. 中间主工作区：需求原文、答案编辑区、候选与来源核对。

右侧候选详情和原文预览优先使用 `el-drawer`，避免长期压缩主编辑区。需要并排比较时在主工作区内使用上下或双列布局，并保证窄屏退化为上下排列。
顶部任务栏保持可见，正式生成按钮只对任务负责人显示；不可生成时按钮禁用并通过旁侧摘要列出阻塞数量，而不是点击后才逐项报错。

### 3.3 左侧区域与条目栏

区域树按 Sheet／表格／区域显示：

- 已确认区域：正常进入条目列表。
- 存在疑问：使用警告标签，可继续查看和配置，不计入可正式生成范围。
- 已排除区域：只读显示排除原因，可由有权限的负责人恢复。
- 尚未识别完成：显示加载或失败状态，不伪装成空区域。

条目筛选使用紧凑标签或下拉框：全部、待认领、我部门处理中、待确认、已完成、不适用、来源待核对。
每条列表项展示需求摘要、负责部门、工作状态、来源核对标记和保存异常标记。长文本换行两至三行后省略，悬停可看完整内容。
批量操作支持认领、取消认领、按相同来源范围重新匹配，以及用户明确发起的批量确认完成。批量确认逐条执行与单条相同的服务端校验，返回成功和未完成原因；不把一次操作变成自动忽略冲突或清除未核对来源。批量选择前展示范围，避免将筛选以外条目计入。

## 4. 准备阶段与分区域配置

### 4.1 页面步骤

沿用现有步骤条和智能结构确认组件，建议步骤为：

1. 上传文件与选择本次对象。
2. 识别 Sheet、表格和区域。
3. 确认需求字段组、答案字段组和不参与字段。
4. 确认处理范围与参与部门。
5. 进入回复工作台。

每个区域独立保存配置草稿，显示“未保存、保存中、已保存、保存失败”。区域切换前先尝试保存；失败时保留当前编辑内容并阻止静默切换。

### 4.2 区域状态和批量调整

- 结构相同的多个区域可以批量采用同一字段用途和映射。
- 批量应用前显示受影响区域及当前差异，不覆盖已有人工作出的不同配置。
- 模板命中且结构核对一致时可以自动配置；疑问字段仍逐项突出。
- 一个区域未确认不阻止其他已确认区域进入填写。
- 任务顶部持续显示“仍有 N 个范围疑问，不能生成正式文件”。

拟采用：`Preparing` 到 `Working` 的切换不要求所有区域一次性确认；第一个区域产生可填写条目后即可进入 `Working`，范围疑问作为独立生成门禁保留。

## 5. 认领、接手、取消和转交

### 5.1 认领

- 参与部门成员可以认领 `Unclaimed` 条目。
- 批量认领必须逐条由服务端检查当前状态，返回成功、已被认领、无权限三类结果。
- 部分成功时保留成功结果，并在结果对话框中列出失败条目和当前负责部门。
- 认领成功后 `WorkState=InProgress`，记录部门、操作人和时间。

### 5.2 同部门接手

拟采用：同一条目同一时刻只有一个活动编辑会话，认领仍归部门。

- 本部门其他成员进入时先以只读方式查看，显示当前编辑人和最近保存时间。
- 点击“接手编辑”后建立新编辑会话，旧会话立即过期。
- 接手不清空已保存草稿，也不改变负责部门。
- 旧页面后续保存必须被拒绝，并提示查看最新版本；不能以最后到达请求覆盖新内容。
- 接手是填写权切换，不是部门内部审批。

### 5.3 取消认领与转交

| 操作 | 前置条件 | 结果 |
| --- | --- | --- |
| 取消认领 | `InProgress`，本部门有权限，未生成正式快照 | 转为 `Unclaimed`；已保存草稿保留供后续接手核对 |
| 转交部门 | 目标部门属于当前参与部门，操作者有协调权限 | 负责部门改为目标部门，状态为 `InProgress`，目标部门重新确认 |
| 移除未完成部门 | 负责人明确确认影响 | 条目转为 `Unclaimed`，保存草稿和操作记录 |
| 移除已完成部门 | 默认保留已确认结果 | 未受影响时保持完成；后续修改或核对时转为 `Unclaimed` |
取消任务与取消认领分开命名。取消任务使当前修订版进入 `Cancelled`，必须显示影响摘要；它不删除任务、文件、答案版本或审计记录。

## 6. 多范围匹配与候选展示

### 6.1 来源范围

任务默认来源范围与本次对象分开显示。来源范围是一组客户、制程、机型组合，查询取并集并继续执行权限过滤。
条目级调整采用 `el-drawer`：

- 顶部显示任务默认范围。
- 下方列出本条新增或排除的范围。
- 保存后只对当前条目重新匹配。
- 重新匹配不覆盖当前答案、人工修改、完成状态或来源核对状态。

范围标签过多时显示第一个完整标签和 `+N`，展开后显示完整组合；“全部”与“范围未知”使用不同文案和标签类型。

### 6.2 候选分组

候选按完整历史记录分组，每组展示：来源部门、客户、制程、机型、版本、适用条件、完整答案字段组、原文入口和差异。
系统不得把候选 A 的字段一与候选 B 的字段二组成默认答案。多份合理但不同的候选并列展示，不按最新时间自动选定。
候选状态：

- 可自动进入草稿：明确适用、无冲突、符合复用资格。
- 需选择：多个合理候选或与当前答案有差异。
- 仅供参考：来源缺失、范围未明确或条件不确定。
- 已停用、隔离的记录不作为新有效候选；已保存的采用快照可显示当前状态变化。无权访问的记录不返回正文或元数据，不能以禁用候选方式泄露。

### 6.3 答案原文和补空白一致性

系统按整个答案字段组判断能否自动带入：

1. 整组为空时，可带入一份明确适用候选的完整原答案。
2. 部分字段已有内容时，必须先将当前字段与同一候选对应字段逐项比较。
3. 已有内容一致且字段映射明确，才自动补齐该候选的空白字段。
4. 已有内容不同、无法对应或语义边界不可靠时，只展示完整候选和差异。
5. 自动补齐不得覆盖已有单元格，不得修改未选中的列、公式或需求内容。
6. 人工选择不同来源字段形成新组合时，按人工回复记录并要求重新确认完成。

候选原文与当前答案采用“当前／候选”对照卡；变化字段用现有主题色和轻量底色突出，不仅依靠颜色表达差异。
字段来源至少显示“已有文件内容、候选原文、人工修改”三类。能够准确追踪时保存字段级来源；不能准确拆分时保存整组候选来源和人工修改事实，不伪造字段级溯源。

## 7. 编辑、保存和并发冲突

### 7.1 编辑区

需求字段只读展示；答案字段按原顺序编辑。所有选中的答案字段均参与完成检查，不显示必填／选填开关。
占位内容只有“请填写、待确认、后续补充”等时不视为填完；明确“不支持、不满足”可以是有效答案。实质内容中包含待确认字样时显示提醒，由填写人判断，不按关键词直接阻止。

### 7.2 保存协议

每次读取条目返回答案版本号和编辑会话标识。保存请求携带：条目标识、答案版本号、编辑会话标识、字段内容和客户端操作标识。
服务端按条目、版本和当前编辑会话校验：

- 版本一致：保存新答案版本，返回新版本号和保存时间。
- 版本过期：拒绝覆盖，返回当前版本摘要。
- 会话过期：拒绝保存，提示已被他人接手。
- 权限或负责部门变化：拒绝保存，刷新条目状态。
- 重复请求：返回第一次保存结果，不重复产生内容版本。

前端状态固定为“未保存、保存中、已保存、保存失败、存在冲突”。输入后短延迟自动保存；切换条目、关闭抽屉、确认完成前执行立即保存。
保存失败时保留本地编辑内容。网络恢复后不能直接覆盖，应先拉取服务端版本；版本未变才重试，版本已变进入冲突处理。

### 7.3 冲突处理

冲突对话框展示“我的未保存内容”和“服务端最新内容”，提供：

- 复制我的内容。
- 载入最新内容。
- 在获得当前编辑权后逐字段人工合并并再次保存。

不提供静默自动合并，也不让 AI 生成合并答案。完成状态不得在冲突保存后沿用。

## 8. 完成、不适用与来源核对

### 8.1 确认完成

点击“确认完成”时依次执行：

1. 立即保存当前编辑内容。
2. 服务端验证编辑会话和答案版本仍为最新。
3. 验证所有选中答案字段已填完且不只有占位内容。
4. 核对实际采用来源的相关修订；存在尚未核对变化时返回具体原因，引导来源核对，不在确认完成动作中自动清除标记。
5. 写入确认人、确认时间和确认答案版本。
6. 将 `WorkState` 置为 `Completed`。

确认完成不是审批；同部门任一有填写权限的成员均可执行。
完成后默认只读。点击“继续修改”取得编辑权后，条目立即回到 `InProgress`，防止修改后的内容继续显示为已完成。

### 8.2 标记不适用

“无需回复／不适用”使用对话框收集简短原因。成功后 `WorkState=NotApplicable`，答案字段不强制填写。再次编辑时先撤销不适用状态并回到 `InProgress`。

### 8.3 来源核对

`NeedsSourceReview=true` 时，在条目顶部显示不关闭的警告条和变化摘要：旧来源版本、当前来源版本或停用／删除状态、变化时间。
填写部门可以：

- “继续使用已保存答案”：确认实际看到的来源变化，保留答案内容和完成状态，清除核对标记。
- “查看新版本并替换”：展示完整差异，采用后回到 `InProgress`，保存并重新确认完成。

核对动作绑定当时看到的来源版本或状态。如果核对过程中来源再次变化，旧核对不能顺带清除新变化。

## 9. 正式生成、失败恢复与修订

### 9.1 生成门禁

任务负责人点击“生成正式文件”前，页面汇总检查：

- 是否仍有未认领、处理中条目。
- 是否所有条目为 `Completed` 或 `NotApplicable`。
- 是否存在 `NeedsSourceReview=true`。
- 是否仍有处理范围疑问或结构配置未解决。
- 是否存在保存中、保存失败或冲突状态。

门禁不通过时保持 `Working`，按类型提供可跳转的阻塞清单；不增加逐级审批。

### 9.2 冻结与生成

生成命令在服务端事务边界内再次检查上述条件，并冻结修订版号、条目答案版本、来源核对结果和结构配置版本，然后将状态改为 `Generating`。
生成过程只读取冻结快照，不重新匹配、不重新选择候选、不读取资料库当前答案替换任务答案。
`Generating` 页面显示阶段、开始时间和失败原因。刷新页面后从服务端恢复进度，不依赖浏览器内存继续。

最终登记正式结果时，再用短事务校验生成代次、修订版状态及采用来源的相关变更标识。渲染期间若发生影响采用依据的来源变化，不登记正式成功；保留本次生成快照供审计，当前版本回到 `Working` 并将受影响条目标记待核对。负责人或部门核对后建立新生成快照，不能复活旧代次直接发布。

生成中仍允许负责人取消尚未正式完成的版本：取消和最终登记在服务端竞争同一版本状态。取消先提交则停止后续发布、拒绝迟到结果，已写出的文件仅作临时失败产物处理；正式登记先提交则已是 `Finalized`，取消请求返回当前状态，不删除正式结果。

### 9.3 失败恢复

拟采用：生成失败后修订版保持 `Generating`，记录失败尝试；负责人可对同一冻结快照执行“重试生成”或“返回工作中”。

- 同一生成请求的网络重发使用同一幂等键，返回已有生成记录。失败后的显式重试可以使用新的操作幂等键，但复用同一逻辑生成 ID 和冻结快照，增加执行尝试，不重复建立正式版本。
- 失败后返回工作中终止该生成代次、解除生成锁并回到 `Working`，此前失败产物标记为临时且不可下载为正式文件；旧工作线程的迟到结果不能再登记成功。
- 已成功生成正式文件但前端超时，重新查询应返回现有正式结果，不能再次生成新版本。
- 文件存储成功而数据库登记失败时，本次不显示成功；后台按幂等标识完成登记或清理孤立临时文件。

### 9.4 正式完成与修订

正式文件登记成功后状态进入 `Finalized`。下载始终取得该正式版本存档，不现场重新生成。
创建修订版时：

- `ReplyTask` 身份不变，新建一个 `ReplyTaskRevision`。
- 复制未受影响条目的确认快照、结构配置和来源记录。
- 复制后按当前来源状态检查是否有尚未核对的相关变化；旧正式版仍不改变，新修订版需要核对的条目设置独立标记，不能盲目沿用全部可导出资格。
- 被修改的条目回到 `InProgress`；没有当前负责部门则为 `Unclaimed`。
- 原部门已退出时保留历史署名，不自动把责任交给任务负责人。
- 需求、公共条件或表头配置变化时，只将实际受影响条目标为待处理。
- 旧修订版和旧正式文件继续只读可查。

修订版不允许上传新源文件替换任务源文件；需要另一份源文件时创建新任务。

## 10. 任务状态转换表

| 当前状态 | 动作 | 条件 | 下一状态 |
| --- | --- | --- | --- |
| `Preparing` | 产生首批可填写条目 | 至少一个区域配置已确认 | `Working` |
| `Preparing` | 取消当前版本 | 负责人明确取消 | `Cancelled` |
| `Working` | 生成正式文件 | 所有生成门禁通过并冻结成功 | `Generating` |
| `Working` | 取消当前版本 | 负责人明确取消 | `Cancelled` |
| `Generating` | 生成成功并登记正式文件 | 冻结快照与产物校验成功 | `Finalized` |
| `Generating` | 取消当前版本 | 取消先于正式登记提交 | `Cancelled` |
| `Generating` | 来源相关变化使原核对失效 | 最终登记校验未通过 | `Working`，受影响条目待核对 |
| `Generating` | 对同一快照重试 | 上次生成失败 | `Generating` |
| `Generating` | 放弃本次生成 | 上次生成失败，负责人选择返回工作中并终止旧代次 | `Working` |
| `Finalized` | 创建修订版 | 有修订权限 | 新版本 `Working` 或 `Preparing` |
若修订涉及结构重新核对，新版本从 `Preparing` 开始；仅修改答案时从 `Working` 开始。

## 11. 条目状态转换表

| 当前状态 | 动作或事件 | 下一状态 | 附加结果 |
| --- | --- | --- | --- |
| `Unclaimed` | 部门认领 | `InProgress` | 设置负责部门和活动编辑会话 |
| `InProgress` | 取消认领 | `Unclaimed` | 清空当前负责部门，保留草稿 |
| `InProgress` | 转交其他参与部门 | `InProgress` | 更换负责部门，原编辑会话失效 |
| `InProgress` | 确认完成 | `Completed` | 绑定确认答案版本 |
| `InProgress` | 标记不适用 | `NotApplicable` | 保存原因和确认人 |
| `Completed` | 修改答案 | `InProgress` | 清除当前完成绑定 |
| `NotApplicable` | 撤销不适用并编辑 | `InProgress` | 保留原操作记录 |
| `Completed`／`NotApplicable` | 来源相关变化 | 状态不变 | `NeedsSourceReview=true`，阻止正式生成 |
| 任意活动状态 | 负责部门被移除且需继续处理 | `Unclaimed` | 保留原答案、确认和来源记录 |

## 12. 权限与只读表现

- 非参与部门可以按任务访问规则查看，不显示编辑、认领和来源核对按钮。
- 参与部门只能修改本部门当前负责条目，不能修改其他部门条目。
- 任务负责人负责范围、参与部门、协调和正式生成，不因此自动拥有各部门答案编辑权。
- `Generating`、`Finalized`、`Cancelled` 的当前修订版正文统一只读；取消、重试、转交负责人等管理动作分别按状态和权限校验，不把正文只读理解为所有管理动作都禁止。
- 按钮隐藏用于无权限，按钮禁用于有权限但当前状态不允许；禁用按钮必须说明原因。
- 原文预览和候选来源按已确认的同公司共享规则执行文件级与资料级访问校验，不能用前端条目可见性替代服务端公司及读取权限检查。

## 14. 验收场景

### 14.1 区域与准备

1. 一个 Sheet 有两个已确认区域和一个疑问区域时，已确认区域可填写，顶部持续提示疑问，正式生成被阻止。
2. 批量配置三个同结构区域时，其中一个有人工作过，系统不覆盖该区域并说明原因。
3. 区域配置保存失败后切换区域，当前编辑不丢失，页面不显示已保存。

### 14.2 认领与接手

1. 两部门同时认领同一条，仅一个成功，失败方看到当前负责部门。
2. 同部门成员 B 接手后，成员 A 的迟到自动保存被拒绝，B 的内容不被覆盖。
3. 取消认领后条目回到待认领，下一部门能看到已保存草稿和原操作记录。
4. 移除已完成部门后，未受影响答案保留；该条进入修订时回到待认领。

### 14.3 候选与答案一致性

1. 整组答案为空且只有一份明确候选时，完整原答案进入草稿，但不自动完成。
2. 当前“节拍 3 秒”、备注为空，候选“节拍 5 秒＋需要双工位”时，只展示差异，不补入备注。
3. 当前已填字段与同一候选一致且映射明确时，只补空白，不覆盖已有内容。
4. 两份合理候选存在时完整并列，系统不按时间选最新，也不跨候选拼字段。
5. 人工组合字段后记录为人工回复，修改使状态回到 `InProgress`。

### 14.4 保存与完成

1. 刷新、短暂断网后，最后一次服务端成功保存的草稿可恢复。
2. 保存失败时页面持续显示失败，本地内容仍可复制，不显示成功。
3. 所有选中字段非空但只有占位内容时，不能确认完成。
4. 明确“不支持”可以确认完成，不被占位关键词规则误伤。
5. 完成后继续修改，条目立即回到处理中，旧完成标记不保留。
6. 显式批量确认时，符合完成条件的条目成功，存在缺答、冲突或未核对来源的条目返回具体原因，不随批次一并通过。

### 14.5 来源核对

1. 确认后来源正文更新，条目保留答案并出现待核对，正式生成被阻止。
2. 部门确认继续使用旧答案后清除核对标记，记录所见来源版本。
3. 核对过程中来源再次更新，第一次核对不能清除第二次变化。
4. 仅来源名称修改且不影响适用性时只提示，不使完成失效。
5. 原部门已退出时，来源变化使条目回到待认领，原答案仍可查看。

### 14.6 正式生成与修订

1. 正式生成与最后一次保存并发时，只能冻结完成状态所绑定的答案版本。
2. 生成请求超时但服务端已成功时，刷新后返回同一正式文件，不创建重复版本。
3. 生成失败后重试使用同一快照；返回工作中后才能继续修改。
4. 正式文件生成后资料库内容变化，再次下载仍取得原存档。
5. 创建修订版后未受影响条目沿用确认结果，修改条目重新确认，旧正式文件保持不变。
6. 来源正文在渲染期间变化，最终登记前检出，任务回到工作中并要求核对，不发布已过期依据的临时结果。
7. 生成中取消与成功登记并发时只有一个结果生效；取消成功后旧线程不得发布正式文件，正式登记已完成时取消不得删除结果。

## 15. 主要设计风险

1. Word／Excel 的多行、合并单元格和字段分列可能使“映射明确”判断过宽；实现前必须用真实样本固定可自动补空的边界。
2. 自动保存、接手和确认完成同时发生时，若服务端不以版本和编辑会话统一校验，仍可能出现内容与完成状态错位。
3. 来源变化事件若只按资料主记录通知而未绑定采用版本，会产生漏核对或重复核对。
4. 正式生成若先写文件、后冻结答案，可能得到无法证明对应内容的产物；冻结必须先于生成且可幂等恢复。
5. 区域可先行填写会增加范围门禁漏检风险；正式生成必须重新汇总服务端区域状态，不能只相信前端统计。

## 16. 实施边界

本文给出页面行为、状态约束和验收场景。具体数据库表、接口路径、任务队列和文件生成器由总体实施方案统一落地，但不得改变本文状态语义。
拟采用的交互选择包括：单活动编辑会话、`Preparing` 中已确认区域先行、生成失败保持冻结快照并允许返回工作中。实现评审若调整这些选择，需要同步更新本文和需求追溯，不得以技术实现静默改变业务结果。
