# 匹配知识 AI 草稿生成设计

## 目标
在匹配知识配置页为每个分类增加 AI 辅助录入入口，让用户基于文本或文档样本生成“可审核、可编辑、可选择”的草稿，再导入到自定义扩展，降低人工整理术语成本。

## 设计结论
- 入口放在各分类 Tab 内，按当前分类单独生成，不做一次性全分类生成。
- 支持三种输入来源：
  - 粘贴文本
  - 已上传文档
  - 临时上传文档
- 生成结果先进入弹窗草稿区，用户勾选、删除、编辑后再导入。
- 导入只写入“自定义扩展”，不修改系统内置层。
- 单位规则仅生成“单位别名”，不生成单位倍率。

## 交互流程
1. 用户进入某个分类 Tab，点击 `AI 生成候选`
2. 弹窗显示当前分类、输入来源和生成区域
3. 用户选择来源并提供输入内容
4. 系统调用后端生成接口，返回当前分类的候选草稿
5. 弹窗内按表格显示候选，带上命中片段、理由和冲突状态
6. 用户勾选/编辑/删除后，点击导入
7. 选中项合并到当前分类的“自定义扩展”

## 数据规则
- 同 key 同 value：自动去重
- 同 key 不同 value：标记为冲突待确认，不自动导入
- 冲突词对左右互换：视为同一条
- 草稿生成接口只返回候选，不落库

## 风险控制
- 冲突词对误报风险最高，需在 UI 上默认保守处理
- 临时上传文档必须复用现有上传权限和文件类型校验
- LLM 输出必须是结构化 JSON，后端先校验再回前端
- 第一版不做草稿持久化，避免先引入额外状态复杂度
