# Prompt 模板管理设计

## 目标
把 Prompt 模板从“任意命名 + 默认模板”的松散管理方式，收敛为“按系统场景管理 + 保存前强校验”的稳定方式，避免页面语义和运行时行为继续脱节。

## 设计结论
- 模板固定为三个系统场景：
  - `matching-review`
  - `import-duplicate-review`
  - `matching-generate`
- 运行时按场景读取系统模板，不再依赖 `IsDefault`。
- 保存或预览模板时，必须完成占位符校验、样例渲染和结构化输出校验。
- Prompt 模板页面改为系统模板管理页，只保留编辑、预览测试和恢复默认。

## 影响范围
- 后端：Prompt 模板实体、仓储、控制器、LLM 辅助服务、导入重复识别服务
- 前端：Prompt 模板 API 与配置页面
- 数据库：Prompt 模板增加场景元数据
- 测试：新增场景拆分、校验失败、预览成功/失败覆盖

## 风险控制
- 旧模板按名称自动映射到新场景，避免直接丢失已有配置。
- 先通过测试锁定旧行为与新行为，再实现运行时切换。
- 不把 AI 可用性治理、关键字接入等无关议题混入本次改造。
