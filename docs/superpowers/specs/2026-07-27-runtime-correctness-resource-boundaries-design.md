# 运行时正确性与资源边界加固设计

## 背景

本次审计确认系统主流程和现有数据隔离总体有效，但在审计日志、并发缓存、异步页面状态、文件生命周期、高成本计算和 AI 出站访问方面仍存在可复现的正确性或资源风险。部分问题会把已处理的业务冲突记录为成功，部分问题会让过期响应污染当前页面，部分问题则可能在并发或大数据量下产生 500、内存峰值或数据库与文件系统状态不一致。

本设计使用一个 OpenSpec 变更统一管理，并按四个可独立回滚的实施切片交付：

1. 审计、错误响应与 API 正确性。
2. 前端异步流程与执行记录回放。
3. 后端并发、文件生命周期、资源预算与 AI 端点安全。
4. 依赖、测试和规范治理。

## 目标

- 审计记录反映最终 HTTP 状态，并且审计写入失败不复用已污染的业务 `DbContext`。
- API 使用真实 HTTP 状态表达业务错误，未知异常不向客户端暴露内部细节。
- 并发生成 Embedding 缓存时，唯一键竞争的失败方复用胜出记录而不是返回 500。
- 所有前端异步结果只能写回其发起时的业务上下文。
- 恢复智能填充执行历史的完整逐行回放、服务端分页和请求竞态保护。
- 文件删除、文件比较和重复分析具备明确、可配置、可取消的资源与一致性边界。
- AI 出站请求只允许访问配置端点的精确 Origin，并统一禁用代理、重定向和 Host 覆盖。
- 修复当前依赖漏洞与脆弱测试，使最终质量门禁可重复通过。

## 非目标

- 不改变 Embedding 主匹配、LLM 辅助裁决的业务排序规则。
- 不新增服务端“预览令牌”协议；批量回复执行仍由后端重新校验当前请求。
- 不把 Ollama 或 LM Studio 的合法本地访问统一封禁。
- 不在本次工作中全面拆分所有超大类或 Vue 页面。
- 不把本地或 Docker 验证冒充真实内网受控发布证据。
- 不归档仍缺少真实部署证据的既有 OpenSpec 变更。

## 决策一：审计与错误响应

### 审计阶段

`AuditOperationFilter` 在 Action 阶段只采集操作、主体、请求和业务上下文，在 Result 阶段读取最终响应状态并写入审计。未处理异常由异常路径记录为 500。每个请求最多形成一条控制器操作审计。

审计持久化通过新的依赖注入作用域获取独立 `DbContext`/应用服务，不复用业务工作单元。业务保存发生并发冲突后，审计写入不再重放业务实体。审计写入失败只写结构化日志，不覆盖原始业务响应。

### HTTP 状态和错误边界

`BaseApiController.Error(code, message, details)` 根据错误码映射真实状态，至少区分：

- 400：输入、格式和校验错误。
- 401/403：认证与权限错误。
- 404：资源不存在。
- 409：并发、唯一约束和业务状态冲突。
- 413：上传体积超限。
- 422：请求合法但超过处理预算或无法按业务规则处理。
- 429：限流或高成本资源繁忙。
- 500：未知服务端错误。

未知异常只返回稳定中文提示、错误码和 `traceId`。内部异常类型、堆栈、SQL 和路径仅进入结构化日志。

## 决策二：并发与数据一致性

### Embedding 缓存

数据库唯一约束 `(SpecId, ModelName, Usage)` 继续作为最终裁决。混合批次插入发生目标唯一键冲突时，精确分离本服务本批次的全部缓存变更，再逐键读取胜出记录或重放独立键；不得只依赖异常携带的实体子集，也不得清空调用方的其他跟踪实体。其他唯一约束、外键或数据库错误不得被吞掉。整个调用链传递 `CancellationToken`。

### 文件删除

真实持久文件删除采用可恢复状态机：

1. 事务内把记录标记为 `PendingDeletion`，保存请求时间和待删除路径标识。
2. 幂等后台清理器删除物理文件。
3. 文件不存在或删除成功后，删除或归档元数据。
4. 失败时记录失败原因、重试次数和下次重试时间。

迁移只新增状态和索引，不在数据库迁移中删除物理文件。回滚时可以停止清理任务并保留待删除记录。

上传工作区中的“删除”只表示移出当前流程。界面文案改为“移出当前流程”或“更换文件”，且不得调用真实删除 API。

## 决策三：前端异步流程

### 执行历史

列表改为服务端分页和远程查询，不固定只取前 200 条。切换任务时取消旧请求并递增请求代次，只有任务 ID 和代次都匹配的响应可以更新页面。

智能填充详情先读取轻量任务概要，再按需加载完整逐行回放 API，展示来源行、候选、证据、AI 裁决、人工覆盖和最终写回值。完整接口不可用时明确展示降级说明，不把轻量数据伪装成完整回放。批量回复继续使用既有简化详情。

### 语义搜索

每次搜索保存不可变作用域键，至少包含客户、机型、制程和查询文本。作用域变化立即取消请求并清空结果；响应到达时再次校验作用域键。编辑动作绑定结果自身的规格 ID 和所属作用域，不从当前页面标题反推目标。

### 批量回复

预览有效性绑定上传会话、目标文件、目标表和配置指纹。任何相关配置变化立即取消旧预览并使 `canApply` 失效。执行请求仍提交完整当前配置，由后端重新校验。

“执行成功”和“下载成功”是两个状态：执行成功后保存 `taskId` 和结果文件信息；下载失败只提示下载失败，并提供重试下载，不把已成功的业务执行标记为失败。

### SmartFill 生命周期

页面 `onDeactivated` 时取消上传、识别、轮询和 SSE 连接，但保留安全的本地步骤状态和 `taskId`。`onActivated` 时按任务状态接口重新对账，不盲目恢复旧连接或旧响应。

## 决策四：资源预算

### 重复项分析

- `MaxDuplicateCandidates` 默认 2,000。
- `MaxDuplicatePairComparisons` 默认 1,000,000。
- 先按精确归一化键分组，再按项目词元等稳定特征分桶，只在候选桶内计算近似相似度。
- 复用高成本匹配并发闸门，并使用独立端点限流策略。
- 超出候选或比较预算返回 422，要求缩小筛选范围；不得返回未标明的不完整结果。
- 枚举和比较循环都检查 `CancellationToken`。

### 文件比较

- 单文件继续受 50 MiB 上传上限约束。
- 上传流写入请求隔离临时目录，不再把完整文件复制为额外 `byte[]`。
- `MaxFileCompareCells` 默认 1,000,000。
- `MaxFileCompareDiffItems` 默认 100,000。
- 超限返回 422 和稳定中文错误码。
- 解析、比较和结果投影全过程持有资源租约。
- 下载结果使用流式写入；临时目录在成功、失败和取消路径均清理。

## 决策五：AI 出站精确 Origin 约束

配置保存只做确定性 URI 结构校验；连通性测试、模型列表、readiness、chat 和 embedding
共用统一受限客户端。

- 允许结构合法的 HTTP 或 HTTPS 配置端点；应用不按提供商、地址族或网络位置分类。
- 每个请求的 scheme、规范化 host 和有效端口必须与配置 Endpoint 完全一致。
- 禁止显式 Host 覆盖，固定禁用代理和自动重定向。
- HTTPS 使用系统 SNI 和证书验证。
- 不维护 CIDR、IANA/元数据地址表或 provider 端口白名单，不自定义 DNS resolver、
  Socket connector，也不承诺 DNS rebinding 防护。
- 客户端与 Semantic Kernel 服务缓存都保持 64 项确定性 LRU；淘汰或关闭不打断活跃调用，
  最后一个调用结束后仅释放一次。

## 决策六：依赖与规范治理

- `postcss` 升级到不低于 `8.5.18`。
- `brace-expansion` 升级到不低于 `5.0.8`。
- NuGet 通配版本改为本次验证通过的精确版本，并使用锁文件固定解析结果。
- GitHub Actions 使用完整提交 SHA，并保留可读版本注释。
- npm registry 默认官方源，通过构建参数显式允许镜像覆盖。
- 密码长度统一为 4～200，并同步后端、部署脚本、示例配置和文档。
- 删除无效的 `ElResult` 全局注册。
- 将依赖源码文本或正则的测试改为行为或契约测试。
- 新变更明确：`combine-smart-fill-sheet-confirm` 的文件级统一确认覆盖较早的逐 Sheet 可见确认交互。

## 迁移与回滚

1. 先交付审计和错误边界，不包含数据库迁移；回滚为恢复旧过滤器注册和错误映射。
2. 再交付前端竞态修复和执行历史回放；所有变更以现有 API 为主，可按页面独立回滚。
3. 然后交付 Embedding 并发、文件删除迁移、资源预算和 AI 精确 Origin 约束。数据库先升级再启用清理器；回滚时先停清理器，再回滚应用与迁移。
4. 最后交付依赖、锁文件、测试和 CI 治理。

任何切片失败时只回滚该切片，不回滚已经验证通过且数据兼容的前置切片。

## 测试与验收

每个缺陷使用 TDD：先编写能稳定复现的失败测试，确认失败原因正确，再做最小实现并运行定向测试。

定向测试至少覆盖：

- 400、409、500 的最终审计状态；业务并发失败后的独立审计；审计写入失败不覆盖业务响应。
- Embedding 同键并发插入只有一条记录且两个调用成功读取相同结果。
- 执行历史快速切换、分页和完整逐行回放。
- 语义搜索作用域 A 切换到 B 后，A 的响应和编辑动作都不能污染 B。
- 批量预览配置变化失效、执行成功后下载失败可重试。
- SmartFill 页面失活取消后台工作，恢复后通过任务状态对账。
- 重复分析候选/比较预算、取消和不返回部分结果。
- 文件比较临时文件清理、预算超限和流式下载。
- HTTP/HTTPS 配置端点的精确 Origin、Host 覆盖、代理、自动重定向和正常 TLS。
- 文件删除迁移、幂等清理、失败重试和回滚。

最终验证包括 .NET 全量测试与严格构建、前端测试和所有静态门禁、OpenSpec 严格校验、npm/NuGet 漏洞检查、真实 MySQL 集成测试、定向浏览器流程以及生产式 Docker 启动和迁移回滚演练。只有真实目标环境发布完成后，才能勾选既有变更中的受控发布任务。

## 交付和 Git 边界

- 四个实施切片分别提交，提交前检查 `git status` 和 `git diff`。
- 不混入无关工作区内容。
- 未经用户再次明确授权，不推送远端、不合并到 `main`、不执行生产部署。

## 已解决的设计歧义

- 上传区移除文件只影响当前流程，不删除服务器持久文件。
- 批量预览不增加服务端预览令牌；使用客户端指纹和后端执行时重校验。
- 超出资源预算返回 422，而不是返回可能误导用户的部分结果。
- AI 出站不按提供商或网络位置设置例外，只执行精确 Origin 和统一传输边界。
- 旧 OpenSpec 变更在缺少真实部署证据时不归档。
