# Excel 区域行列配置与 A1 坐标统一设计

## 背景

当前数据导入确认页能够展示 AI 识别出的 Sheet、区域、字段列和 A1 范围，并通过“调整范围”进入编辑。现有 Excel 编辑界面只提供项目、规格、验收、备注四个 `B2:B7` 形式的输入框，保存时再由这些范围反算字段列和数据行，并向数据区上方搜索表头。

这种方式隐藏了用户实际需要确认的结构信息：

- 表头从哪一行开始、占几行；
- 数据从哪一行开始、到哪一行结束；
- 项目、规格、验收、备注分别是哪一列。

项目内部其实已经使用区域结构对象表达上述信息，A1 文本只是界面层临时转换。当前问题不是缺少数据模型，而是 Excel 界面把 A1 文本变成了唯一入口，并把已有的行号和列选择控件隐藏到了非 Excel 分支，造成 AI 配置与人工配置看起来是两套互相冲突的机制。

## 目标

- 在当前“确认/预览”页面内直接提供表头、数据行范围和四个业务列的人工配置。
- AI 识别和人工修改共用同一份区域草稿，不再存在两个入口、两份配置或相互覆盖。
- `B2:B7` 继续可见且可编辑，但只作为同一区域结构的 Excel 坐标表达。
- 行号、列选择与 A1 坐标双向同步，任何一种编辑都原子更新同一区域结构。
- 预览、确认、模板学习和最终导入只读取用户当前看到的最终区域草稿。
- 保持现有多区域、仅规格模式、模板学习和旧单区域兼容能力。

## 非目标

- 不修改 AI/规则识别算法、Embedding、LLM 或匹配排序。
- 不允许项目、规格、验收、备注使用不同的数据起止行。
- 不支持任意单元格集合或不规则掩码。
- 不新增独立的“AI 导入”和“手动导入”入口。
- 不新增数据库迁移；现有区域契约已经能够保存本设计所需信息。
- 不改变 Word 的行列配置语义。

## 核心决策

### 1. 区域结构是唯一业务真相

每个逻辑区域只保存一份结构化草稿：

```text
regionId
headerStartRow
headerRowCount
dataStartRow
dataEndRow
projectColumn
specificationColumn
acceptanceColumn
remarkColumn
isSpecificationOnly
```

其中：

- 页面行号和 Excel 坐标使用 1-based 工作表绝对位置；
- 现有识别与确认 API 继续使用 0-based 已用区域相对索引；
- 绝对坐标与相对索引只允许在 API 适配边界转换一次；
- A1 文本不进入确认、预览或导入契约，不作为第二份持久化状态。

允许 A1 输入框在用户输入尚未完成时保留临时文本，但只有完整校验通过后才能原子写入区域草稿。临时文本不是业务状态，不能被预览、确认或导入读取。

### 2. A1 表示字段数据范围，不包含表头

四个字段的 A1 范围由同一区域结构实时计算：

```text
项目范围 = 项目列字母 + 数据起始行 : 项目列字母 + 数据结束行
规格范围 = 规格列字母 + 数据起始行 : 规格列字母 + 数据结束行
验收范围 = 验收列字母 + 数据起始行 : 验收列字母 + 数据结束行
备注范围 = 备注列字母 + 数据起始行 : 备注列字母 + 数据结束行
```

示例：

```text
表头起始行：1
表头行数：1
数据起始行：2
数据结束行：7
项目列：B       -> B2:B7
规格列：C       -> C2:C7
验收列：F       -> F2:F7
备注列：G       -> G2:G7
```

如果第 1 行是表头，`B1:B7` 会错误包含表头，正确的数据范围是 `B2:B7`。只有数据确实从第 1 行开始时，才显示 `B1:B7`。

### 3. AI 与人工操作写入同一草稿

流程固定为：

1. AI/规则识别返回区域列表。
2. 前端把识别结果转换为可编辑的最终区域草稿。
3. 页面所有行号、列下拉和 A1 坐标都读取该草稿。
4. 用户修改仍写回该草稿，并标记为人工调整。
5. 预览、确认、模板学习和导入只读取该草稿。

不得继续保留“识别配置”和“手动配置”两个可分别变化的对象。识别结果只作为初始值和“重置为识别结果”的不可变快照，不得在异步识别、预览刷新或 Sheet 切换后覆盖用户已经修改的草稿。

## 页面设计

### 1. 直接在当前确认卡中编辑

当前 Sheet 的确认卡增加“结构与列映射”区域，不再要求用户进入另一套手动配置流程。

- 待确认、缺少必填列或范围异常的区域默认展开。
- 已完整识别的区域默认折叠，只显示范围摘要，可按需展开。
- 原“调整范围”按钮改为展开或收起当前卡内的同一编辑区，不再打开只包含 A1 输入框的独立配置入口。
- 多区域按“区域 1、区域 2……”分别展示，可在同一编辑区新增、复制和删除。

每个区域采用紧凑布局：

```text
区域 1

表头起始行 [ 1 ]  表头行数 [ 1 ]
数据起始行 [ 2 ]  数据结束行 [ 7 ]

项目列 [B 项目]       A1 [B2:B7]
规格列 [C 规格]       A1 [C2:C7]
验收列 [F 验收标准]   A1 [F2:F7]
备注列 [G 备注]       A1 [G2:G7]

仅规格表（没有独立项目列） [关闭]
```

列下拉选项统一显示为：

```text
[B] 项目
[C] 规格/型号
[F] 验收标准
```

列字母使用工作表绝对列；表头文字来自当前区域选定的表头行。合并或多行表头继续使用现有展开后的组合表头结果。

用户开启“仅规格表”时，项目列和项目 A1 清空并禁用；关闭后必须重新选择项目列。系统不得仅因 AI 没有识别到项目列就自动开启该状态，疑似漏识别时仍要求用户明确确认。

### 2. 行号与 A1 双向同步

用户修改行号时：

- 修改 `dataStartRow` 或 `dataEndRow` 后，四个非空字段的 A1 范围立即同步更新；
- 修改表头起始行或表头行数时，只重新加载当前区域表头和列选项，不改变数据范围；
- 表头结束位置必须严格早于数据起始行。

用户修改列下拉时：

- 只更新对应字段列；
- 对应 A1 范围立即使用新列字母和当前数据起止行重新生成；
- 不改变其他字段列和数据起止行。

用户直接修改某个 A1 范围时：

- 解析列字母、起始行和结束行；
- 校验通过后，在一次状态提交中更新对应字段列以及本区域共享的数据起止行；
- 重新生成四个字段的 A1 范围；
- 当行范围发生变化时，在编辑区显示“已同步本区域全部字段的数据行为第 X–Y 行”，避免静默修改。

用户正在输入无效或不完整 A1 时：

- 只在该输入框显示错误；
- 不修改区域草稿，不连带修改其他字段；
- 不允许确认或导入。

### 3. 表头由用户配置优先

AI 可以预填表头起始行和行数，但用户一旦修改，最终值必须以人工配置为准。Excel 保存时不得再通过向上扫描自动替换用户明确选择的表头。

表头行变化后，前端仅请求当前区域所需的轻量表头预览：

- 请求只用于刷新表头文字和列选项；
- 不得覆盖最终合并预览、已加载数据行或其他区域缓存；
- 请求失败时保留用户草稿，并提示该区域表头加载失败；
- Sheet 切换或连续修改时使用请求版本保护，旧响应不得覆盖新选择。

## 业务规则与校验

保存和确认前必须同时满足：

- 表头起始行位于当前 Sheet 已用范围内；
- 表头行数至少为 1；
- 表头结束行严格早于数据起始行；
- 数据结束行不早于数据起始行，且二者均不越界；
- 项目列在普通模式下必填，仅在用户明确确认“仅规格表”时允许为空；
- 规格列和验收列必填；
- 备注列可选；
- 四个非空字段列不得重复；
- 四个非空 A1 范围必须共享相同的数据起止行；
- A1 必须是单列、正序、合法且位于当前 Sheet 已用范围内；
- 同一 Sheet 的多个逻辑区域不得重叠；
- 删除区域后至少保留一个有效区域。

错误必须落在具体区域和字段上，例如：

```text
区域 2：数据起始行必须晚于表头结束行
区域 1：规格列不能与项目列重复
区域 3：验收范围超出当前 Sheet 已用范围
```

页面不得只显示笼统的“配置无效”。

## 数据流

```text
识别响应
  -> normalizeRecognizedRegions()
  -> finalRegionDrafts（唯一可变业务状态）
     -> 行号控件
     -> 列下拉
     -> A1 双向适配器
     -> 表头轻量预览
  -> 确认请求
  -> 最终预览
  -> 模板与列映射学习
  -> Excel 导入
```

必须移除或停止使用任何与 `finalRegionDrafts` 平行、能够独立参与确认或导入的旧映射状态。兼容字段只能从第一个最终区域投影，不得反向覆盖区域列表。

## 多区域行为

- 每个区域拥有稳定且唯一的 `regionId`。
- 新增区域时复制当前区域的字段列作为便捷初值，但建立新的行范围和独立对象。
- 复制区域必须深拷贝表头、字段映射和临时输入状态，不能共享可变引用。
- 删除区域只清除该区域的表头缓存和错误，不影响其他区域。
- 修改一个区域的表头、数据行或字段列，只使该区域的轻量表头缓存及最终预览有效性失效。
- 最终预览必须按当前区域集合重新生成，并带有 `(tableIndex, regionId, rowIndex)` 行定位。

## 重置与失败恢复

- “重置为识别结果”恢复当前 Sheet 的不可变 AI/规则快照。
- 用户存在修改时，重置前必须明确提示会覆盖当前 Sheet 的人工调整。
- AI 部分失败、超时或重试不得清空已有人工草稿。
- 表头预览失败、最终预览失败或 Sheet 切换不得丢失人工配置。
- 取消编辑恢复进入编辑前的当前区域草稿，不触发模板学习或导入。

## 兼容与迁移

- 现有 `SmartConfigRecognizedRegion` 已包含表头、数据行和四列映射，本设计不要求数据库迁移。
- 现有表级字段继续作为第一个区域的兼容投影。
- Word 保留现有真实行号和列选择流程，但可复用统一的区域校验与最终草稿边界。
- 旧模板没有区域列表时继续构造单个默认区域。
- 已保存的新区域结构仍使用现有确认契约，因此回滚前端不会破坏已保存模板。
- 实施前必须通过新的 OpenSpec 变更修正 `add-multi-region-smart-recognition` 中“A1 是唯一编辑入口”的旧要求，明确改为“行列控件与 A1 是同一结构的双向视图”。

## 验收场景

### AI 预填

- AI 识别出表头第 6 行、数据第 7–242 行、项目 D、规格 E、验收 G、备注 H。
- 页面直接显示上述行号和列选项。
- A1 同时显示 `D7:D242`、`E7:E242`、`G7:G242`、`H7:H242`。

### 行号同步

- 用户把数据起始行从 7 改为 8。
- 四个 A1 范围同时变为从第 8 行开始。
- 确认请求和最终预览使用第 8 行，不再读取识别结果中的第 7 行。

### 列同步

- 用户把规格列从 E 改为 F。
- 规格 A1 立即变为 `F7:F242`。
- 项目、验收、备注列保持不变。

### A1 反向同步

- 用户把项目范围从 `D7:D242` 改为 `B9:B200`。
- 项目列变为 B，区域数据起止行变为 9–200。
- 规格、验收、备注 A1 自动同步为各自列的第 9–200 行。

### 表头不进入数据

- 表头位于第 1 行、数据位于第 2–7 行、项目列为 B。
- 页面显示项目范围 `B2:B7`，不得显示 `B1:B7`。

### 校验失败

- 字段列重复、表头与数据重叠、A1 越界、区域重叠或必填列为空时，页面阻止确认。
- 错误定位到具体区域和字段，用户已经输入的其他有效配置保持不变。

### 真实导入一致性

- 用户最终看到的区域草稿与确认请求、预览行定位和 Excel 导入请求逐字段一致。
- 切换 Sheet、刷新表头或重新预览后，人工配置不得回退成 AI 初始值。

## 测试要求

- 单元测试覆盖行列结构与 A1 的正反向转换、绝对/相对索引转换及所有校验规则。
- 组件测试覆盖 AI 预填、行号修改、列修改、A1 修改、错误定位、重置和多区域隔离。
- 组合测试证明表头轻量预览不会覆盖最终数据预览或其他区域缓存。
- 数据流测试证明确认、预览、模板学习和导入均只读取最终区域草稿。
- 回归测试覆盖 Word、旧单区域 Excel、仅规格模式和旧模板兼容。
- 浏览器验收使用真实 Excel 完成：AI 预填、人工改行、人工改列、直接改 A1、多区域、切换 Sheet、预览和最终导入。

## 风险与控制

- **风险**：双向同步形成循环更新。
    - **控制**：所有编辑先转换为一次 `RegionPatch`，由单一归一化函数原子提交；派生 A1 只由提交后的草稿计算。

- **风险**：直接修改一个 A1 意外改变其他字段行范围。
    - **控制**：明确显示区域共享数据行，并在发生变化时给出同步提示；无效输入不提交。

- **风险**：异步表头响应覆盖新配置。
    - **控制**：按 `regionId` 使用请求版本号和独立缓存，旧响应直接丢弃。

- **风险**：旧规范仍要求 A1 唯一入口。
    - **控制**：实施前创建并严格校验 OpenSpec 变更，完整替换冲突要求，不能只补充局部场景。

## 完成标准

满足以下条件才可称为完成：

- 当前确认页能够直接配置表头、数据起止行和四个业务列；
- 行列控件与 A1 坐标双向同步且只有一份最终区域状态；
- AI 预填和人工修改不会互相覆盖；
- 用户最终看到的配置与预览、确认、学习和导入完全一致；
- 所有定向测试、类型检查、代码规范、OpenSpec 严格校验和真实浏览器验收通过；
- 未验证的真实文件、浏览器或运行环境边界被明确报告。
