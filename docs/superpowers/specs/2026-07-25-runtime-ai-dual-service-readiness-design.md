# 数据导入与智能填充双 AI 服务就绪展示设计

## 背景

数据导入和智能填充的上传/目标步骤共用
`SmartStructureAiAssistControl.vue`。当前组件只检测并展示 LLM 服务，
因此用户只能看到结构疑难识别使用的 LLM 模型，无法确认后续语义召回所需的
Embedding 服务是否已连通。

## 目标

- 在数据导入和智能填充的共用 AI 辅助区域同时展示 LLM 与 Embedding 服务及模型。
- 只有 LLM 与 Embedding 都处于 `available` 状态时，AI 辅助开关才允许开启。
- 任一服务检测中、不可用或加载失败时，关闭 AI 辅助并明确显示对应状态。
- 两个业务页面保持完全一致的展示和启用规则。

## 非目标

- 不改变结构识别接口的请求参数；结构疑难裁决仍使用选中的 LLM 服务 ID。
- 不改变智能填充匹配、数据导入重复识别的后端算法或服务选择规则。
- 不新增 AI 服务配置、探测或组合状态后端接口。

## 方案

### 双服务加载

共用组件分别请求运行时 `llm` 与 `embedding` 选择结果，并在同一轮加载中等待
两项结果落定。组件分别保留两项选择状态及错误信息，已有取消请求、激活刷新和
重试机制同时覆盖两类服务。

### 启用状态

`hasServices` 改为双服务就绪判断：

- 两项均为 `available` 且都有服务 ID：允许开启。
- 任一为 `checking`：禁止开启并显示正在检测的服务。
- 任一为 `unavailable` 或请求失败：禁止开启并显示不可用原因。
- 已开启后任一服务失去可用状态：自动关闭并清除结构识别使用的 LLM 服务 ID。

组件继续只向父页面同步 LLM 服务 ID，因为现有结构识别接口只消费该 ID；
Embedding 选择用于就绪门禁和用户可见信息，后续业务链路仍按各自已有的运行时
Embedding 选择机制执行。

### 展示

开关下方使用两项紧凑信息展示：

- `LLM`：服务名称，以及与服务名称不重复的模型名称。
- `Embedding`：服务名称，以及与服务名称不重复的模型名称。

若服务正在检测或不可用，则在现有提示区域按服务名称给出状态，不用内部服务
ID，不改变数据导入和智能填充的业务中文标签。

## 错误处理

- 单项请求失败不覆盖另一项的真实状态。
- 重试时重新检测两项服务，避免只恢复其中一项后错误开启。
- 组件卸载、停用或发起新一轮加载时取消两项旧请求，过期响应不得覆盖新状态。
- 无配置权限的用户只看到状态说明；有权限的用户保留“去配置 AI 服务”和
  “重新检测”入口。

## 测试

- 先补充失败测试，证明只有 LLM 可用时仍不可开启。
- 覆盖两项均可用、LLM 不可用、Embedding 不可用和任一检测中的状态计算。
- 覆盖已开启后服务失效时自动关闭并清除 LLM 服务 ID。
- 覆盖 LLM 与 Embedding 的服务名称和模型名称均出现在共享组件中。
- 运行相关 Vitest/Node 定向测试、前端类型检查、格式检查和 `git diff --check`。

## 影响范围

主要修改共享组件及其状态辅助函数/测试。数据导入与智能填充只需继续复用该
组件，不分别实现重复逻辑，也不涉及数据库迁移和后端接口变更。
