# 批量回复步骤化文件工作区设计

## 背景
当前批量回复已经从旧的线性四段卡片改成了三段式页面，但内部仍主要依赖卡片展开表格配置，并单独保留了“当前表回写预览”区域。用户明确要求继续收敛为更强的上下文工作区：每一步一个 Tab，每个文件一个 Tab，文件下面再按 Sheet/表格拆分，且移除独立预检查区。

## 目标
- 页面主流程固定为“来源文件 / 目标文件 / 执行结果”三步。
- 来源文件步骤使用“文件 Tab -> Sheet/表格 Tab”结构承载行设置和列映射。
- 目标文件步骤使用“目标文件 Tab -> Sheet/表格 Tab”结构承载来源表选择、行设置和列映射。
- 取消独立预检查区，预览结果只出现在当前 Sheet/表格上下文内。
- 保持现有 API 契约尽量不变，避免为了重排交互打散后端逻辑。

## 推荐方案
1. 顶层步骤保持 `el-tabs`，但文案改为“来源文件 / 目标文件 / 执行结果”。
2. 来源文件即使只有一份，也显式保留文件级 Tab，避免用户对来源与目标的层级认知不一致。
3. `BatchTableConfig.vue` 从“卡片列表”切换为“Sheet/表格 Tab 工作区”，让每个 Sheet/表格内部直接展示：
   - 行设置
   - 项目列
   - 规格列
   - 验收列
   - 备注列
   - 来源表选择（仅目标表场景）
   - 预览入口与预览反馈
4. 独立“当前表回写预览”卡片删除，避免用户在配置和预览之间来回切换。

## 取舍
- 不新增后端接口：继续复用当前逐表预览与执行接口，避免扩大回归范围。
- 不再保留独立预检查区域：因为它会打断“当前文件 / 当前表”的上下文，和本轮交互目标冲突。
- 不在本轮抽统一工作区组件：先把批量回复调整到正确交互，再考虑是否复用于其他页面。

## 风险
- `BatchTableConfig.vue` 当前同时被智能填充和批量回复复用，重构时需要确保智能填充不被误伤。
- 目标文件页的状态层级会变成“文件 -> 表 -> 预览结果”，需要避免切换 Tab 时串状态。
- 移除独立预检查区后，必须在当前 Sheet/表格上下文给出足够明确的预览反馈，避免用户误以为预览被删掉了。

## 验收标准
- 页面顶层不再出现“来源配置 / 目标配置”旧文案，而是“来源文件 / 目标文件 / 执行结果”。
- 目标文件步骤中，每个目标文件都是一个 Tab，每个目标文件内部继续按 Sheet/表格分 Tab。
- 配置项直接落在当前 Sheet/表格上下文内，可见行设置和项目/规格/验收/备注列。
- 页面中不再存在单独的“预检查”“当前表回写预览”区块。
