# 单角色强制设计

## 目标
把当前“用户可挂多个角色”的实现收敛为“一个用户只能有一个角色”的系统规则，并同步收口数据库、API、认证上下文与前端表单/缓存口径。

## 设计结论
- 保留 `AuthUserRoles` 关系表，但通过数据库唯一约束强制 `UserId` 只能对应一条有效角色关系。
- 历史多角色数据迁移时，若包含 `admin` 则优先保留 `admin`；否则按最早创建记录保留第一条角色关系。
- 历史无角色用户在迁移时补到 `common` 角色，避免出现无法登录或无授权上下文的账号。
- 系统用户创建、编辑、查询接口统一改为 `roleCode` 单值字段，不再暴露 `roles` 数组。
- 登录、刷新令牌和前端本地缓存统一改为单角色字段；权限仍保持数组，不改变现有权限校验模型。

## 影响范围
- 后端：系统用户 DTO、用户管理控制器、认证控制器、认证访问服务、JWT 令牌服务、用户仓储
- 前端：系统用户 API、登录用户 API、用户状态缓存、系统用户管理页面
- 数据库：`AuthUserRoles` 历史数据清洗与唯一索引迁移
- 测试：迁移、用户管理、登录/刷新令牌、前端类型检查

## 风险控制
- 迁移规则固定为“`admin` 优先，其次最早创建”，避免不同环境出现不一致结果。
- 数据库唯一约束放在数据清洗之后执行，避免迁移中途因脏数据失败。
- 本次不重做权限聚合模型，只把角色入口收敛为单角色，避免把无关重构混入同一变更。
